# Design Review: プレーヤーレーダー

対象: MOM-30の要求仕様とローカル試作。2026-09-28。正本は [要求仕様](series-player-radar.md)。本書はレビュー記録であり、実装契約を重複定義しない。実データ・実測値・画面写真は公開文書へ含めない。

**Verdict:** NOT DONE — 製品化の判定は7/10。今回の修正後も、採用軸・採点式・必要件数と利用者本人の読解が未確定である。ローカル試作の改善は完了しても、MOM-30を完了にはしない。

**The One Thing:** 同じ記録条件・固定した採点基準で、4人の各観点の成績と、高い得点がどこまで揃っているかを読み取れること。

**Keeps its promise?** 部分的に満たす。合算しない4人比較は成立する一方、金融的な成績の複数の統計量を、別々の能力と受け取る余地がある。点数の根拠と条件を読めるようにしたが、それが本人の直感と一致するかは未確認。

**Cut list:** 主画面から検証用の選択肢・診断・模擬管理操作を外して開閉領域へ移した。総合点・順位・新しい万能性指数は追加しない。軸数削減そのもの、参考点のゼロ補完、目的地の再採用、レーティングの実装も今回の修正に含めない。

**Fix list:** 以下のS3・S2所見を修正した。重大度は0〜4の定性的な判定であり、プレーヤーの採点でも実測した品質指標でもない。

| 重大度 | 攻めた観点・反例 | 問題と対応 |
| --- | --- | --- |
| S3 | 意味・構成概念: 6軸が高い人は6種類の能力に優れるのか | 順位1・収益2・資産3であり、独立した能力数ではないと明記。現在の観点に限定した万能性として扱う。平均とP90を両方残す判断は未確定 |
| S3 | 信頼: 参考値は図のどの軸か | 全体の注記だけでは特定できなかった。各軸の「参考」、白抜きの点、破線、図のテキスト表現へ品質を反映 |
| S3 | 分母: 条件付き成績が特定の開催に集中したら | 条件外の開催も件数判定に使っていた。指標ごとに条件対象の試合数・開催数を計算し、全体の開催数で不足を隠さない。銀次の追加基準は件数にかかわらず検討中の参考値 |
| S3 | 管理状態: 直前基準へ戻す比較を取り消したら | 点数が新基準のまま「冬の基準を適用中」と案内する経路を再現。取消後は現在の適用状態を維持。基準不足の候補を適用する操作も無効化。模擬適用の結果は同じ評価記録の管理表に表示し、異なる試合数の主図と混同させない |

| S2 | 初見・情報構成: 比較と実験はどちらが主目的か | 別案・診断・管理が一続きだった。通常比較を先に置き、軸の意味へ直接進める。実験は用途を名付けた開閉領域にまとめる |
| S2 | 指標名: 「下位資産」は3・4位の試合か | 図はP10・P90と明示し、数値表の指標名から定義へ移動できる。低い側・高い側の境界であり、順位別の抽出や裾の平均ではないと説明 |
| S2 | 数値の誠実さ: 1点差は同じ能力差か | 段階点の差を等しい改善量に見せない。同点や上下限の中にある元の値の差を数値表で確認できるようにし、丸め前の値で判定することを明記 |
| S2 | 期間比較: 全マップの点数差は上達か | 表示対象のマップ別件数へ到達可能にし、構成差と成績変化を混同しない。異なる作品の同点も同じ強さと扱わない。自動的な比率補正は追加しない |
| S2 | ナビゲーション: 切替後にブラウザーで戻ると | 履歴を上書きしていた。条件変更を履歴へ保存し、戻る・進むで選択と結果を復元。無効なURL指定は正規化の理由を表示 |
| S2 | 小画面・支援技術: 表を押し込むと読めるか | 文字の過度な縮小をやめ、表内スクロールと行見出しを保つ。図のテキスト表現に各軸点・品質を含め、条件変更の結果をstatusとして通知。説明へのfocus移動を確認 |

**Back of the fence:** 対象0件、基準不足、候補の取消、保存不能、戻る・進むを修正・検証対象にした。本番の認可、同時更新、分析Worker、永続化・公開の一貫性は本試作の証拠には含めない。試作はローカル保存不能時にも利用でき、その場合の模擬状態の非永続性を表示する。

## 判定の内訳

スキルに沿った専門家の暫定評価であり、利用者テストの結果や客観的な測定値ではない。未確認を合格として数えない。

| フレーム | 修正後の評価 | 残る不合格・10/10に必要な確認 |
| --- | --- | --- |
| UX heuristics | 8/10 | 主要な不合格は「意味を考え込まず読めるか」。P10/P90、参考値、観点の重複の理解はS3の残るリスク。ほかの適用可能な診断はローカル操作で確認した。検索は固定4人の比較に不要として対象外 |
| Simplicity / end-to-end review | 7/10（7診断中5） | 目的の一文化、価値への短い経路、説明なしの実物確認、削除、端の状態は確認。実機スマートフォンでの利用と、日常的に使える採点設計の合意は未確認 |

## 採点設計に残る論点

1. **各軸が違う判断に役立つか。** 平均収益と収益P90、資産の3統計量を別々に見る理由を、利用者が元の値を参照して説明できるか。相関だけで機械的に削除せず、形を派手にするためにも残さない。
2. **基準作成窓と評価期間のずれ。** 固定試合数の集計値から作った基準を、短い期間・長い通算へ適用している。十分な件数という暫定条件だけでは安定性を保証しない。窓幅と開催除外の診断を根拠に、必要件数・参考表示を採用案として決める。
3. **同じ4人・同じ期間から繰り返し案を選ぶ限界。** 試作で何度も参照した後の期間を、完全に未見の検証データと呼ばない。現時点の比較は設計上の適合確認であり、将来の安定性の保証ではない。初回運用時の見直し対象期間と再表示条件まで決める。
4. **銀次の選択効果。** 遭遇試合の最終順位が良くても、実際の回復過程を観測してはいない。人ごとに対象試合も異なる。主図へ入れたときの誤読と欠測が許容できるか、補助表で足りるかを判断する。

これらを解決するために、合成指標、自由な重み、追加の本番計算方式を増やさない。軸数・係数・必要件数はレビュー担当者の好みで確定しない。レーティングはMOM-31の独立した検討に保つ。

## 採用判断に使う短い読解課題

- 4人の同じ軸を比較し、特徴が異なる2人について、どの軸と元の値からそう判断したかを説明する。
- 資産P10とP90が何を示し、何を示さないかを説明する。
- 参考・未採点の軸を見つけ、その理由を確認する。対象0件を0点と扱わない。
- 候補の比較を開いても採点基準は変わらないこと、戻す操作の取消でも現在の基準が維持されることを確認する。

説明者が先に正解を教えてから成功と扱わない。回答のずれは名称・配置・軸の採否に反映する。MOM-30の終了には、この読解と採点設計の採用判断が必要である。

## 検証の境界と根拠

計算テスト11件を通過し、手計算可能な反例で対象開催の分母・空条件を検証した。UIはPlaywright MCPで通常比較、参考・未採点、空条件、URL復元、管理の取消・再読込・基準不足・保存不能、キーボードでの説明への移動と表内スクロール、PC・スマートフォン相当の表示を確認した。旧結果形式の拒否と既存出力の保持、合成値を出力しないことも確認した。実データの再試算と合成例は区別している。対象者の読解、実機スクリーンリーダー、実機スマートフォン、本番処理は未検証。

判断に使った一次資料は以下。個別の軸・係数・件数にこれらの資料からお墨付きを与えない。

- 主目的と専門的な操作を分け、必要な詳細への入口を明確にする。[NN/g: Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/)
- 状態の可視化、取消、記憶に頼らない比較、エラーからの復帰を点検する。[NN/g: 10 Usability Heuristics](https://www.nngroup.com/articles/ten-usability-heuristics/)
- 図には値・意味へ到達できるテキスト表現を用意する。[W3C WAI: Complex Images](https://www.w3.org/WAI/tutorials/images/complex/)
- 二次元の表は表内でスクロールさせ、周囲の説明を画面幅へ収める。[W3C: Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)
- 表示する結果通知を支援技術でも識別できるようにし、過剰な読み上げは避ける。[W3C: Status Messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)

試作の全候補・全診断を本番成果物へそのまま持ち込まない。本番は採用した軸・必要な根拠と品質だけを既存の分析成果物へ接続し、通常表示時の再計算を避ける。実装gateはMOM-29で変更する実行経路に合わせて選ぶ。
