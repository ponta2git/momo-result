# 開催一覧・開催詳細 要求仕様

## 1. 目的

開催履歴を作成単位として扱うだけでなく、その開催に紐づく未確定作業と確定試合を、開催回内の順序で閲覧できるようにする。

開催詳細は、単一開催内の事実と試合メモを短時間で確認し、試合結果、戦績比較、次試合の記録へ移動するためのハブとする。長期間の傾向、勝因候補、次戦への行動仮説は `docs/requirements/series-comparison.md` と `docs/requirements/series-review-playbook.md` を正本とし、この画面で重複して推論しない。

## 2. 情報設計

- `/held-events` は開催回を条件で探し、開催ごとの成績を見比べ、作成する入口とする。
- `/held-events/:heldEventId` は1開催内の未確定作業、開催内サマリー、確定試合を表示する。
- `/matches` は開催をまたぐ検索と作業一覧を担当し、確定済み試合のメモ有無を本文なしで判別できるようにする。表示の詳細は `docs/requirements/match-note.md` を正本とする。
- `/matches/:matchId` は単一試合の保存結果を担当する。
- `/analytics/series` は作品、シーズン、マップを条件とした戦績比較を担当する。

開催内の試合は開催結果で閲覧し、開催一覧・詳細には開催で絞り込んだ試合検索へのリンクを重複して設けない。

## 3. 開催一覧

- 既定は開催日時の降順で表示する。同日時は開催IDのUTF-8 byte順の降順で安定化し、詳細の前後移動と同じ順序を使う。並び順で「開催が古い順」を選んだ場合は、同じ基準の昇順とする。
- 一覧APIは各開催の確定試合数、未確定下書き数、次試合番号候補、作品（シリーズ）・シーズンの組み合わせ、プレーヤー別の開催平均順位と各順位の回数を返す。メモの語句で絞り込んだ場合は、一致した試合メモの抜粋も返す。
- 一覧行は開催日時の下に作品・シーズン名を表示する。確定試合と有効な下書きの組み合わせを重複なく表示し、複数ある場合も省略しない。両方未設定の下書きや空開催には名称を補わず、一方だけ設定済みの場合は他方を未設定として示す。
- 開催日時を開催詳細へのリンクとする。
- 一覧行には確定試合数と未確定下書き数に加え、確定試合から算出したプレーヤー別の開催平均順位を表示する。次試合番号候補は開催詳細と記録開始時に使う。
- 次試合番号候補は、確定試合と有効な未確定下書きに設定された開催回内番号の最大値に1を加える。
- 候補は番号を予約しない。確定時の一意性検証を正本とする。
- 開催作成後は、作成した開催の詳細へ移動する。
- 全開催のうち最新の開催行には、絞り込み・並び順・ページによらず「最新」を示し、その開催を記録先としてOCR取り込みを始めるショートカットを表示する。次試合番号、手入力、下書き再開は開催詳細に残す。
- モバイルではページ全体を横スクロールさせず、開催と操作を縦方向に読めるようにする。

### 開催一覧の検索

試合一覧と同じ検索の型（主条件、詳細条件の開閉、適用中の条件、モバイルの検索条件シート）を使う。条件と並び順はURLに保持し、条件を変えると1ページ目に戻る。

- 主条件は作品、シーズン、マップ、並び順とする。作品・シーズン・マップは、その条件に合う確定試合を含む開催を探す。作品を変えると、シーズンとマップの選択を解除する。
- 詳細条件は次のとおりとする。
  - 期間: 開催日時の日本時間の日付で、開始日・終了日を含む範囲とする。
  - 確定試合数: 指定した試合数以上の開催を探す。
  - メモに含む語句: 開催内のどれかの確定試合のメモに語句を含む開催を探す。語句の扱いは `docs/requirements/match-note.md` の試合一覧の検索と同じとする。
  - プレーヤーの開催成績: プレーヤー、指標、値、以上・以下で探す。指標は開催平均順位と、1位から4位それぞれの回数とする。プレーヤーを選ばない場合は、4人のうち誰か1人でも当てはまる開催を探す。指標は開催内の確定試合だけで算出し、確定試合がない開催は当てはまらない。開催平均順位は表示と同じ小数第2位までに丸めて比べる。
- 開催平均順位は確定試合の順位の平均とし、一覧では小数第2位まで桁をそろえて表示する。一覧行では開催平均順位の昇順（開催内の順位順）に並べ、同率は同じ順位とし、その中は固定メンバー順とする。プレーヤーの開催平均順位で絞り込んでいる場合は、そのプレーヤーの値を強調する。
- メモの語句で絞り込んでいる場合だけ、各開催で一致した試合のうち開催回内番号が最も小さい試合の番号とメモの抜粋を語句を強調して示し、ほかに一致した試合の数を添える。語句の条件がない場合はメモを一覧に出さない。
- 条件に合う開催がない場合は、条件を解除する操作を示す。

## 4. 開催詳細

開催詳細は次の順で表示する。

1. 開催日時、確定試合数、未確定下書き数と、開催単位の出力・関連操作。
2. OCRまたは手入力で次試合を追加する操作。
3. 未確定下書きと、状態に応じた再開操作。
4. プレーヤー別の開催内1位回数、平均順位、試合番号順の順位列。
5. 開催回内番号順の確定試合タイムライン。

- 開催一覧はcard dashboardではなく日時順のledgerとし、開催詳細はidentity、次の操作、未確定下書き、決定論的サマリー、試合番号timeline、出力・管理をつなぐhubとする。
- 開催作成は一覧の走査を不安定にしないfocused dialogで行い、成功後は作成した開催詳細へ移動する。確定試合と有効な下書きがある開催は削除できず、削除確認では対象と結果を明示する。
- 開催単位の出力、再読み込みは、開催の識別情報と対応づけてページ上部の補助操作として表示する。
- 次試合番号候補は独立したサマリー項目にせず、次試合を追加する操作の文脈で表示する。

開催内サマリーは保存済み順位から決定論的に算出する。全員で共通する試合数は開催の識別情報に一度だけ併記し、各プレーヤーの戦績では復唱しない。勝因、信頼度、推薦文を生成しない。

各確定試合には、順位順に並べた4人の順位と総資産、オーナー、試合結果へのリンク、その試合を選択した戦績比較へのリンクを表示する。開催日時は開催の識別情報として上部に一度だけ表示し、各試合には重複表示しない。同一開催内で作品、シーズン、マップが異なる場合があるため、戦績比較条件は試合ごとに生成する。

試合メモがある場合は、対応する確定試合の中にcompactなpreviewを表示し、長い本文は同じ試合項目内の明示的な開閉操作で改行を保った全文を読めるようにする。初期状態で全試合の長文メモを展開してtimelineの走査を妨げない。開催詳細では閲覧専用とし、メモがない試合へ空欄や「メモなし」を反復しない。入力、編集、表示の詳細は `docs/requirements/match-note.md` を正本とする。

### 前後の開催へ移動する

- ページ下部の開催内容の後に「前の開催」「次の開催」を設け、一覧の絞り込みやページによらず全開催を移動する。開催日時、同日時では開催IDのUTF-8 byte順の昇順で、前は直前、次は直後とする。空開催と未確定下書きだけの開催も含む。
- 操作前に行き先の開催日時を判別できるようにし、同日時は相対順を補う。端には存在しない方向へのlinkを作らず、対象がないことを示す。
- 試合詳細と同じ共通の前後移動を使い、狭幅でも等幅2列で、前の開催を左揃え、次の開催を右揃えにする。行き先の説明は折り返して全文を読めるようにし、最初・最後の非link表示にも同じ文字色・余白・整列を適用する。
- 連続移動は通常の履歴に積み、ブラウザの戻る・進むで訪問した詳細や一覧のページ・絞り込み・hashをたどれるようにする。遷移元URLは次の画面へ渡さない。画面内には開催履歴へのlinkを置く。
- 移動後の試合一覧、出力、記録開始は表示中の開催に対応する。前後移動による表示完了時は移動先の識別見出しへfocusを移すが、待機中に利用者が別操作へ移った場合は奪わない。

## 5. 記録フローとの接続

- `/ocr/new?heldEventId=:heldEventId` は指定開催を記録先の初期値にする。
- `/matches/new?heldEventId=:heldEventId` は指定開催と次試合番号候補を初期値にする。
- 初期値の優先順位は、既存下書きまたは編集対象、URL指定開催、最新開催の順とする。
- OCR下書き作成時は、設定済みの開催IDと開催回内番号を保存する。
- 試合詳細から所属する開催詳細を開けるようにする。

## 6. 表示状態とアクセシビリティ

- 読み込み中は最終レイアウトに近いスケルトンを表示する。
- 空開催、未確定のみ、確定のみ、混在、取得失敗、削除済み開催を区別する。
- 同じ開催の再取得中と一時失敗では既存内容を保ち、前後操作だけを一時停止して更新状態・再試行を示す。存在しないことが確定した開催を、その後の通信失敗で復活させない。
- 本文を取得できても前後情報を利用できない場合は、端とは区別し、本文と開催履歴へのlink、再取得を残す。移動先が削除済みでも開催履歴を開けるようにする。
- マスタ名称を取得できない場合は、内部IDを名称として表示しない。
- 状態は色だけで伝えず、テキストを併記する。
- タイムラインは順序付きリストとしてマークアップし、最初から最後まで連続する1本の軸で試合順を表す。
- 主要操作の操作領域は44px以上とし、キーボードフォーカスを可視化する。
- 非必須モーションは `prefers-reduced-motion` に従う。

## 7. API要求

- `GET /api/held-events` は各開催の確定試合数、未確定下書き数、次試合番号候補、プレーヤー別の開催平均順位と各順位の回数、全開催のうち最新の開催IDを返す。メモの語句で絞り込んだ場合は、一致した試合メモの抜粋と、ほかに一致した試合の数を返す。
- 一覧の検索条件、件数、ページ、最新の開催IDは同じread snapshotから求める。プレーヤー別の成績とメモの抜粋は表示するページの開催に限って取得し、開催ごとに問い合わせない。
- `GET /api/held-events/:heldEventId` は開催、確定試合とその試合メモ、算出済み状態の未確定下書き、全開催内の直前・直後の開催identityを同じread snapshotから返す。隣接判定の失敗を対象なしに置き換えない。
- 確定試合は開催回内番号の昇順で返す。
- 一覧・詳細と試合メモの表示のために試合詳細APIをN+1で呼ばない。
- 存在しない開催は404を返す。
