# 見込み順位との差 要求仕様

状態: 実装済み（2026-11-16、algorithm `series-analysis-v15`・artifact schema 11）。利用者が [11節の判断](#11-確定した判断) を採用した。既存正本（戦績比較、行動プレイブック、試合メモ）の該当箇所は [9節の一覧](#既存正本への反映) に従い同じ変更で改訂した。

目的: 桃鉄のルール上、物件収益が多い人と目的地に多く着いた人は総資産が増えやすく、順位が上がるのは当然である。この当然の部分を「見込み順位」として先に差し引き、残った差が誰に・どの記録と一緒に現れているかを示す。ルールからは読み取れない差を、次戦で試す行動を考える手掛かりにする。

| 関心事 | 正本 |
| --- | --- |

| HTTP・成果物の構造 | Tapir endpoint、JSON Schema |

## 1. 成功条件

- 各プレーヤーについて「物件収益の順位と目的地の回数が同じだった場合の平均と比べ、実際の順位が上か下か」を、説明者の補助なしに答えられる。
- 場全体について「見込みとの差が、どの記録の多い・少ないと一緒に現れているか」を、値と件数を添えて答えられる。物件収益と目的地の多寡そのものを答えにしない。
- あるプレーヤーの差が、特定の記録の区分に偏っているのか、どの区分でも同じ向きなのかを見分けられる。
- 傾向のある記録について、その回数だった試合でほかの記録・物件収益・総資産がどう違うかを読み、差がどこでついているかの手掛かりを得られる。止まった理由そのものは記録になく、分からないことを分からないと読める。
- 見込みより大きく上位・下位だった試合を一覧で確かめ、その試合の試合メモを同じ場所で読んで、数値に残らない経緯を確かめられる。試合詳細へ移動して4人の結果も読める。
- 見込み順位と実際の平均順位を並べて読み、「見込みとの差」が何位と何位の差なのかを答えられる。
- プレーヤーを一人選び、その人の記録別の差と、傾向があるかどうかを読める。場全体の値と同じ軸で見比べられる。
- 差が「傾向あり」「兆し」に当たるか、偶然の範囲に収まるかを、統計の説明なしに読み分けられる。記録ごとの結論を、その記録の見出しで読める。
- 偶然の範囲に収まる差を傾向として読ませない。対象なし・少数例・観測された0を区別できる。
- 共起を因果として表現しない。見込みは保存済みの結果から作る比較の基準であり、勝敗の予測、能力の評価、試合中の行動の観測として扱わない。

## 2. 当然の部分と、残りの部分

| 分類 | 記録 | 本書での扱い |
| --- | --- | --- |
| 見込みに使う | 物件収益の試合内順位、目的地の回数 | 順位と結び付くことがルールから分かる。見込み順位の層に使い、差の説明には使わない |
| 差の説明に使う | カード売り場、プラス駅、カード駅、マイナス駅、スリの銀次 | 見込みとの差を回数の区分別に示す |
| 使わない | 総資産 | 最終順位を直接決めるため、見込みにも説明にも使わない |
| 使わない | 番手、オーナー、マップ、シーズン | 既存の条件別比較とscope切替で読む |

総資産には物件の価値と目的地の賞金が含まれる。そのため「収益が多いと上位」「目的地が多いと上位」は、戦い方の手掛かりというより採点方法の言い換えに近い。本機能はこの部分を主表示にしない。

### 既存指標との関係

- 「順位を読む手掛かり」は本機能へ置き換える。手掛かりは物件収益と事件簿6項目を同じ候補として扱うため、当然の項目が先頭に並び、4人でほぼ同じ内容になっていた。本機能の「記録別の差」は、同じ問い（何が順位と結び付くか）に当然の部分を除いて答える。
- 「予測より上位だった勝利」は本機能の [根拠試合](#5-根拠試合) へ統合する。意外な結果の試合を示す基準を、物件収益の順位と目的地だけから作る見込みへ一本化する。
- 「王座の確からしさ」は変更しない。モデル、fold、品質境界（安定した順位signalの有無を含む）、再標本化は [戦績比較](series-comparison.md#6-advanced-rank-analysis) の定義を維持し、手掛かりと予測より上位だった勝利の出力・drilldown・表示だけを取り除く。
- 既存の物件収益順位との差、目的地変換効率、収益トップ未勝利率は、平均どうしの差または条件付きの率である。本機能は1試合ごとに同じ層の平均と比べる点が異なり、既存の値の定義は変えない。

## 3. 見込み順位

- 権限、scope、確定済み試合、対戦順、保存順位の扱いは [戦績比較の不変条件](series-comparison.md#2-data--scope-invariants) に従う。
- 単位は、選択scope内の1試合における1プレーヤーの結果（以下「明細」）とする。各明細を次の2軸の組合せによる層へ分ける。層に使う軸はこの2つだけとし、収益の差の大きさなどを加えない。

| 軸 | 区分 |
| --- | --- |
| 収益順位 | その試合で本人より物件収益が大きい人数に1を足した値（1〜4）。同値は同じ順位とし、最大値と同値の全員が1位になる |
| 目的地 | 0回、1回、2回以上 |

- 見込み順位は、選択scope内で同じ層に入る全明細（4人分を合算）の保存順位の平均とする。本人の明細も含める。
- 明細が3件未満の層は、同じ収益順位の中で目的地の区分が隣り合う層と併合し、併合後の層で平均を求める。併合の順序は決定論的に固定する。併合しても3件に満たない収益順位は、その収益順位の全明細を一つの層とする。
- 見込みは選択scopeごとに作る。別のscope、別の作品、過去の成果物の平均で補わない。マップやシーズンを絞ると、その範囲での見込みに変わる。
- 見込みとの差は `見込み順位 − 保存順位` とし、正の値は見込みより上位だったことを表す。
- 層ごとの差の合計は0になる。したがって選択scopeの全明細の差の合計も0になる。

## 4. 指標

### 個人の差

| 指標 | 定義 |
| --- | --- |
| 見込み順位 | 本人の全明細の見込み順位の平均 |
| 実際の平均順位 | 本人の保存順位の平均。既存の平均順位と同じ値 |
| 平均差 | 見込み順位 − 実際の平均順位。本人の全明細の見込みとの差の平均に等しい。正ほど、同じ収益順位・目的地回数の平均より上位 |
| 対象件数 | 本人の選択scope内参加試合数 |
| 判定 | 6節の「傾向あり」「兆し」。見込みより上位か下位かの向きを添える。偶然の範囲は言葉を付けず、図の帯で示す |

### 記録別の差

カード売り場、プラス駅、カード駅、マイナス駅、スリの銀次のそれぞれについて、回数を区分し、区分ごとに次を算出する。場全体（4人の明細を合算）と各プレーヤーの両方で同じ定義を使う。

| 指標 | 定義 |
| --- | --- |
| 件数・割合 | その区分に入る明細数と、分母に対する割合。分母はプレーヤーでは本人の参加試合数、場全体では全明細数 |
| 見込み順位 | その区分に入る明細の見込み順位の平均 |
| 実際の平均順位 | その区分に入る明細の保存順位の平均 |
| 平均差 | 見込み順位 − 実際の平均順位。その区分に入る明細の見込みとの差の平均に等しい |

- 回数の区分は項目ごとに固定する。0回の明細が大半を占める項目（マイナス駅、スリの銀次）は「0回／1回以上」、それ以外は少ない側・中間・多い側の3区分とする。3区分の境界は作品の全確定試合から一度だけ決め、選択scopeや表示のたびに作り直さない。決め方はalgorithm versionで追跡し、試合が増えて境界が動いた場合も、その成果物の全scopeで同じ境界を使う。
- 場全体の値を主とし、「この記録が多い（少ない）明細は、見込みより上位（下位）だった」を読む。プレーヤー別の値は、本人の平均差がどの区分に現れているか、その区分に入る頻度が場全体とどう違うかを読むために使い、場全体と同じ定義で判定する。
- 場全体をまとめた実際の平均順位は、順位に同値がなければ常に2.5位であり、見込み順位の平均も2.5位になる。基準は区分やプレーヤーごとに異なるため、見込み順位と実際の平均順位を各行に併記し、差だけを示さない。
- 示すのは区分別の平均差までとする。「1回あたり何位ぶん」への換算、係数、寄与率、項目間の重要度の順位は算出・表示しない。区分を並べることで、回数が増えるほど差が大きくなるか、頭打ちになるかを読めるようにする。
- 項目どうしは互いに調整しない。ある項目の区分別の差には、同時に起きやすい別の項目の影響が含まれうる。同時に起きている違いは次の「背景」で示す。

### 背景: 一緒に動く記録

記録別の差で「傾向あり」または「兆し」の区分を持つ項目について、区分ごとに次の値を示す。その回数だった試合で、ほかに何が違っていたかを読むためのものである。

| 値 | 定義 |
| --- | --- |
| 物件収益のシェア | 本人の物件収益 / その試合の4人の物件収益の合計。合計が0の試合は等分とみなす。層の平均との差の平均 |
| 総資産 | 層の中央値との差の中央値 |
| ほかの記録の回数 | その項目自身を除く、カード売り場、プラス駅、カード駅、マイナス駅、スリの銀次。層の平均との差の平均 |

- どの値も、3節の層（同じ収益順位・目的地回数）の中での差として求め、当然の部分を除く。場全体の値だけを示し、プレーヤー別には分けない。
- 物件収益は金額ではなくシェアで比べる。金額は試合ごとの規模の違いが大きく、層の中央値との差がほとんど0になって読めないためである。
- ほかの記録と物件収益のシェアには、6節の入れ替えで偶然では出にくい差にだけ「差あり」を付ける。総資産は最終順位そのものに近いため、値だけを示して判定を付けない。
- 背景は「一緒に起きていること」であり、原因ではない。なぜその駅に止まったか、狙ったのか出目によるのかは記録になく、背景からは分からないことを読み方に明記する。
- 背景の見出しには観測した事実だけを書く。物件収益のシェアに差があるか、一緒に動くほかの記録の順に短く示し、総資産の差は表で示す。「差は物件収益以外の部分でついている」のように差の出どころを推論する文は置かない。物件の評価額や持ち金は記録になく、[UI規約](../ui-rule.md#ui-ライティングと分析の断定) が観測していない原因へ広げることを禁じているためである。

## 5. 根拠試合

- 各プレーヤーについて、見込みより上位だった明細と下位だった明細を、それぞれ差の絶対値が大きい順に最大5件示す。差が同値の場合は対戦順の新しい試合を先にする。差が0の明細は含めない。
- 上位側・下位側のどちらかに該当する明細がない場合は、その側を「該当なし」とする。件数を埋めるために差の小さい明細を別の規則で補わない。
- 各行は、試合を識別する情報、本人の収益順位、目的地の回数、見込み順位、保存順位、見込みとの差を示す。その試合での本人の物件収益、目的地、プラス駅、マイナス駅、カード駅、カード売り場、スリの銀次の保存値を欠落なく示す。
- 行から、ページ共通の選択試合と試合詳細へ移動できる。browser back後は元のscope、view、開示状態へ戻れる。
- 各行に、その試合の試合メモがあれば本文を表示する。メモは一覧を読む時点の保存済み本文をAPIが添え、成果物には保存しない。メモだけの保存で分析の再計算を起こさない [試合メモの契約](match-note.md) は変えない。
- 試合メモは途中から加わった機能であり、古い試合にはメモがない。メモの有無で根拠試合の選定・順序・件数を変えず、見込み・差・判定の重みにも使わない。メモがない行は、メモ欄を空として示すだけにする。
- メモの中の情報を戦績の読解に活用することは妨げない。本文から語を数える・分類するなどの派生値を加える場合も、メモがある試合だけを対象にした値であることを件数とともに示し、メモのない試合を「該当なし」として集計に混ぜない。初版の範囲は本文の表示までとする。
- 一覧は初期payloadへ含めず、blockから同一成果物のdrilldownとして取得する。

## 6. 件数・品質・偶然の差

| 対象 | 件数 | 表示 |
| --- | --- | --- |
| 選択scopeの試合数 | 0 | 共通の空状態 |
| 選択scopeの試合数 | 1〜2 | 見込みを作らず「対象なし」 |
| 選択scopeの試合数 | 3〜19 | 数値・件数と既存の「参考値」。判定の言葉と結論文は付けない |
| 区分の明細数 | 0 | 割合は観測された0%、平均差は「—」 |
| 区分の明細数 | 1〜2 | 数値・件数と「参考値」 |

### 判定の言葉

個人の平均差（4人）と、場全体の区分別の平均差を、次の3段階で判定する。画面に言葉として出すのは「傾向あり」と「兆し」だけとする。

| 段階 | 意味 | 条件 | 表示 |
| --- | --- | --- | --- |
| 傾向あり | 偶然ではまず説明できず、時期を分けても同じ向きの差 | 偶然で出る頻度が20回に1回未満で、かつ対戦順の前半と後半で平均差が同じ向き | 対象の行に標章 |
| 兆し | 偶然にしては大きいが、まだ言い切れない差 | 偶然で出る頻度が10回に1回未満で、傾向ありに当たらない | 対象の行に標章 |
| 偶然の範囲 | 差があるようには見えない | 上記以外 | 言葉を付けない。図の帯の内側として示す |

- 偶然で出る頻度は、成果物の計算時に、選択scopeの各試合の中で4人の見込みとの差を無作為に入れ替えた戦績から求める。
- 頻度は比較の数を補正して数える。個人の平均差は「4人のうち最も大きい差」が、区分別の平均差は「全項目・全区分のうち最も出にくい差」が、入れ替えた戦績でその大きさ以上になる頻度とする。4人や多数の区分のどれかに偶然で言葉が付く頻度を、表示上の基準と同じ水準に抑えるためである。
- 前半・後半は、選択scopeの試合を [対戦順](series-comparison.md#2-data--scope-invariants) で二分したものとする。どちらかの半分に対象の明細がない場合は、同じ向きとみなさない。
- 入れ替えは固定seedで決定論的に行う。seedは作品と選択scopeの対象試合（対戦順）から決定論的に作り、同じ試合だけを含む別のscopeには同じ判定を返す。入れ替えの回数はalgorithm versionで固定する。同じ入力からは同じ判定が得られ、計算量は [分析バッチ](series-analysis-batch.md) の資源上限に収める。頻度の水準と入れ替えの回数は実装とalgorithm versionを正本とし、変更時は本書の表を合わせる。
- プレーヤー別の区分の値も、同じ3段階で判定する。4人×全項目・全区分をまとめて補正し、4人のどこかに偶然で言葉が付く頻度を場全体の判定と同じ水準に抑える。帯もプレーヤー・区分ごとに求める。補正が厳しいため、付く言葉は少なくなる。
- 背景の「差あり」は、背景に示す全ての値・区分の組合せをまとめて補正し、偶然で出る頻度が20回に1回未満のものに付ける。前半・後半の一致は求めない。背景は補助であり、「傾向あり」と同じ言葉を使わない。
- 言葉は確かさを表し、差の大きさは数値で読む。頻度の数値は画面の主表示に出さず、読み方の説明に置く。確率、検定の結論、能力の評価として表現しない。
- 偶然の範囲の行にも数値と件数は表示し、言葉は付けない。同じ言葉を多くの行に反復せず、[UI規約](../ui-rule.md#ui-ライティングと分析の断定) が通常の状態への安心文言を禁じているためである。参考値のscopeと3件未満の区分は判定しない。
- 図に示す帯は、行ごとに「兆し」の基準に相当する大きさとし、0を中心に対称に置く。帯の大きさはWorkerが判定と同じ入れ替えから求めて成果物に保存する。

### 結論文

- 4人の差には結論文を置かない。4人を同じ強さの行として並べ、傾向あり・兆しの行にだけ向きと標章を付ける。一人の下位傾向を文章で名指しして強調しないためである（[UI規約の視覚階層と強調](../ui-rule.md#視覚階層と強調)）。
- 記録別の差は、記録ごとに短い結論を行群の見出しとして示す。傾向ありは「〜の傾向」、兆しは「〜の兆し」と言い切る。どちらもない記録は「順位との結び付きは見られない」と弱く示す。
- 結論の語彙は「傾向」「兆し」までとする。行動の提案は書かない。プレーヤーを選んだ表示では、記録ごとの結論を本人について文にせず、行の標章だけで示す。場全体の結論は参照として弱く添えてよい。
- 結論はWorkerが判定から決定論的に生成し、文面はalgorithm versionで追跡できるtemplateとする。APIとWebは文を組み立て直さない。弱い差を拾って結論を作らない。
- 言い切るのは記録と結果の対応までとする。「売り場へ行けば順位が上がる」のような因果、能力、次戦の結果は書かない。

- 併合した層があるscopeでは、見込みが粗くなっていることを品質の注意として確認できるようにする。

検討時点の確定済み戦績では、見込みに使う2項目だけで順位のばらつきの半分近くが説明され、残りの差はカード売り場の区分で傾向ありとなり、成熟したscopeのいずれでも同じ向きだった。比較の数を補正しない判定では、4人の誰かに偶然で言葉が付く頻度が高く、弱い判定は読み手を誤らせた。補正後に傾向ありとなった個人は一部のプレーヤーに限られた。実測値は本書へ記載しない。

## 7. 表示

- 「分析する」→「勝因候補」の、現在「順位を読む手掛かり」がある位置に置く。「推移」の「予測より上位だった勝利」は取り除き、根拠試合は本blockから開く。ページ上部の作品・シーズン・マップ、対戦数、最終更新、「表示を更新」を共有し、block内へ複製しない。
- 意味・階層・関係は、位置、読み順、整列、余白、列、罫線で伝える。説明文、淡色面、card、色に頼らない。blockの中に置く文は見込みの定義の一文だけとし、向きは軸の見出し、まとまりは行群、偶然の範囲は帯、基準と注意は節末の読み方の開示で示す。
- ページの content surface の中に、節見出しと罫線で置く。節や小節を card や淡色面で囲わない。文字・余白・ウェイトは [UI規約](../ui-rule.md#文字余白レイアウト) の scale と役割に従う。
- 読む順序は、見込みの定義、4人の差、記録別の差とする。背景は記録別の差の該当する行群の直下に開示として置く。見込み順位の層と判定の基準は、既存の各節と同じく節末の読み方の開示へ置く。
- 4人の差と記録別の差は、0（見込みどおり）を中心にした同じ軸・同じ目盛り・同じ列位置で示し、個人の差と記録の差の大きさを見比べられるようにする。各行に偶然の範囲の帯を置き、帯の意味は凡例で一度だけ示す。
- 軸には両端だけでなく途中の目盛りを置き、各行の図にも同じ位置の目盛り線を引いて、差の大きさを行ごとに読み取れるようにする。目盛りの間隔は表示範囲に対して5〜7本になる切りのよい値とし、[UI規約](../ui-rule.md#文字) の文字の下限を守る。
- 4人の差は、行をプレーヤー、列を対象件数・見込み順位・実際の平均順位・図・見込みとの差・判定・根拠の試合を開く操作とする。4人の値を同じ強さで示し、判定の有無で行の高さや操作の位置を変えない。
- 記録別の差は、記録ごとの行群とし、行群の見出しに記録名と結論、各行に回数の区分・件数と割合・見込み順位・実際の平均順位・図・見込みとの差・判定を置く。偶然の範囲の行は弱く示してよい。項目・区分の順序を差の大きさで並べ替えない。
- 記録別の差は、対象を「場全体」と固定4名から一つ選んで表示する。値だけを切り替える少数の選択なので segmented control を使い、既定は場全体とする。プレーヤーを選ぶと、同じ表・同じ軸・同じ行の並びのまま本人の件数・順位・差・帯・判定に替わり、各行の図に場全体の値を目印として重ねる。4人を横に並べて下位だけが目立つ表にはしない。
- 対象の切替は表示だけを変え、scope・分母の定義・成果物・選択試合を変えない。切替の前後で読んでいる位置とfocusを保つ。URLでの復元は既存の表示設定の規則に従う。背景は場全体を選んでいるときだけ示す。
- 背景は、開示の見出しに短い事実を示し、開いた中に行を区分、列を値とする表を置く。金額・シェア・回数の単位と、平均か中央値かを列見出しで区別する。傾向あり・兆しの記録だけに置く。
- 根拠試合は、4人の差の各行の操作から開くdialogに置き、比較の高さを変えない。上位側・下位側を区別して示し、各行の値と試合への移動を対応づける。試合メモはラベルと本文だけで示し、淡色面で囲わない。メモがない試合には欄を置かない。狭い幅ではdialogの本文に縦スクロールを一つだけ持たせる。
- 向きの色は、既存の分析用の正・負の意味色を使い、符号と「上位・下位」を文字で併記する。固定メンバーの色は名前の標識だけに使い、図の系列や傾向へ流用しない。
- 文言は「〜回だった試合では見込みより上位だった」のように記録と結果の対応として書く。「売り場へ行けば順位が上がる」「プラス駅に止まるのは損」のような因果・行動の断定を使わない。読み方の説明には、回数が試合終了時の値であり順序が分からないこと、余裕のある展開だから回数が増えた可能性を消せないことを含める。
- PC・mobileで項目、区分、名前の順序、数値、分母を変えない。狭い幅では1行を「名前または区分・件数・差」「図」「判定」の順に積み、軸の目盛りを表の上に一度だけ示す。必要な横スクロールは表内に閉じる。

## 8. 行動プレイブックとの関係

今回は、見込みとの差を「次戦に備える」の行動仮説へ接続しない。分析側で傾向を読めることまでを範囲とする。

- プレイブックの正本は「順位を読む手掛かり」を二次的な候補にできると定めているが、現在の実装は候補に使っていない。手掛かりを取り除くため、正本からこの記述を外す。代わりの候補は加えない。
- 「予測より上位だった勝利」「王座の確からしさ」は従来から候補に使っておらず、変更はない。
- 本機能を行動仮説へ接続する場合は、別の要求として、候補の条件・文面・行動へ接続できる記録の範囲を定める。検討時点の試作では、範囲を絞ると仮説の向きがぶれやすく、場全体で傾向のある区分だけを根拠にする必要があった。

## 9. 実装に渡す境界

- 既存の分析入力だけで計算する。入力、DB schema、記録項目、OCRを本機能のために変更しない。試合メモを分析入力・成果物・checksumへ含めない。根拠試合に添えるメモは、drilldownの保存payloadを検証した後のHTTP応答へAPIが付加し、付加後の上限を確認する。
- 各scopeの集計と同じ入力から事前計算する。aggregateへの追加payloadは、層の表（最大12層）、「場全体＋固定4名」×「5項目の区分」（件数・順位・差・判定・帯）、背景（最大5項目×各区分×6値）の固定サイズに収める。根拠試合はdrilldownへ置き、各人最大10行に収める。全明細の差は成果物へ保存しない。
- 見込み、差、区分、件数、品質、判定、帯、結論文、根拠試合の選定と順序はWorkerが確定する。APIとWebは保存済み成果物を検証して表示し、層の併合・平均・入れ替え・選定を再計算しない。対象の切替も保存済みの値の表示を替えるだけとする。
- 意味検証は、層の件数の合計と全明細数、層ごとの差の合計が0であること、各項目の区分の件数の合計と分母、プレーヤー別の区分の件数の合計と場全体の件数、背景が傾向あり・兆しの項目だけに付くこと、根拠試合の件数上限・順序・符号を照合する。不正な成果物は公開しない。
- 手掛かりと予測より上位だった勝利の出力を取り除くため、成果物は非互換変更となる。API・Web・Workerと既存作品の再計算を [切替契約](series-analysis-batch.md#8-compatibility--release--rollback) に従って揃え、旧形式の互換コードは維持しない。
- 王座の確からしさが使うモデルの計算と品質判定は維持する。品質判定は安定した順位signalの有無を参考値の条件に含むため、その判定に使う重要度の算出は内部に残す。取り除くのは、手掛かりと予測より上位だった勝利の出力（aggregateの項目、drilldown、表示）と、予測より上位だった勝利の抽出に限る。
- 更新中・失敗時の直前成功成果物の扱い、同一成果物への固定、取得失敗は [分析バッチ](series-analysis-batch.md#6-api--web--admin) の共通契約に従う。見込みを作れないscopeは定義済みの対象なしとして正常な成果物に含め、予期しない計算失敗では部分公開しない。

### 手計算できる具体例

以下は説明用の架空データであり、実際の戦績ではない。層「収益順位2位・目的地0回」に入る明細が次の4件だけだったとし、層の併合は考えない。

| 試合 | プレーヤー | 順位 | カード売り場 |
| --- | --- | --- | --- |
| 1 | B | 2位 | 1回 |
| 2 | C | 3位 | 0回 |
| 3 | A | 1位 | 2回 |
| 4 | B | 2位 | 0回 |

- この層の見込み順位は `(2 + 3 + 1 + 2) / 4 = 2.0` となる。
- 見込みとの差は、試合1のBが0、試合2のCが−1.0、試合3のAが＋1.0、試合4のBが0で、合計は0になる。
- この層だけで見ると、カード売り場の区分別の平均差は、0回が `(−1.0 + 0) / 2 = −0.5`、1回が0、2回以上が＋1.0となる。いずれも1〜2件のため参考値とする。
- プレーヤーBのこの層での平均差は0であり、「収益2位で目的地0回なら2位」という見込みどおりの結果を表す。Bの順位が2位と高くても、見込みより上位とは読まない。
- 根拠試合は、Aの上位側が試合3、Cの下位側が試合2となる。Bは差が0の明細だけなので、上位側・下位側とも該当なしとなる。
- 実際の集計では、全層の明細をまとめて区分別・プレーヤー別の平均差と根拠試合を求める。

## 11. 確定した判断

| 事項 | 決定 | 理由 |
| --- | --- | --- |
| 既存の「順位を読む手掛かり」 | 本機能へ置き換える | 同じ問いに二つのblockが別の単位で答えることを避ける。手掛かりは当然の項目が先頭に並び、4人でほぼ同じ内容だった |
| 既存の「予測より上位だった勝利」 | 本機能の根拠試合へ統合する | 意外な結果の試合を示す基準を一つにする。王座の確からしさは維持する |
| 置き場所 | 勝因候補の、手掛かりがあった位置 | 置き換えにより位置を引き継ぐ |
| 根拠試合 | 初版に含める。各人の上位側・下位側を各最大5件 | 試合メモには数値に残らない手筋が書かれており、うまくいった展開と崩れた展開の両方を読めるようにする |
| 記録別の差の単位 | 区分別の平均差のみ | 手計算で確かめられる。1回あたりへの換算は回帰が必要で、回数による頭打ちが見えなくなる |
| 偶然の差の境界 | 成果物の計算時に、固定seedの入れ替えで求める | 件数とデータの偏りに合う。試合数帯だけの固定の定数では、区分の件数や作品ごとの分布の違いに合わせにくい |
| 判定の言葉 | 3段階で判定し、言葉として出すのは「傾向あり」「兆し」だけとする。偶然の範囲は図の帯で示す。頻度は比較の数を補正し、傾向ありには前半・後半の一致を求める | 「偶然では出にくい差」や頻度の数字は意味が伝わりにくかった。補正しない判定では、弱い差や意味のない差に言葉が付いた |
| 結論の置き方 | 記録別の差は記録ごとの見出しで言い切る。4人の差には結論文を置かない。背景は観測した事実だけを書く | 一人の下位傾向を文章で強調しない。差の出どころの推論は、観測していない原因へ広げることになる |
| 表示の構成 | 説明文・淡色面・cardではなく、位置・整列・軸・行群・帯で伝える。根拠試合はdialogに置く | UI規約と既存画面の文法に合わせる。試作で規約との衝突点を洗い、回避・調整した |
| 規約に対して受け入れた点 | 向きに既存の正・負の意味色を使う。見込みの定義を一文だけ置く | 色は既存の番手比較と同じ用途で、符号と文字を併記する。定義は解釈を変える前提であり、一度だけ示す |
| 行動プレイブック | 今回は接続しない。手掛かりを二次候補にできるとする正本の記述は、指標の置き換えに伴って外す（実装は候補に使っていない） | 分析側で傾向を読めることを先に確かめる。試作では、範囲を絞ると仮説の向きがぶれやすかった |
| 基準の順位 | 見込み順位と実際の平均順位を各行に併記する | 差だけでは「何位と何位の差か」が分からない。場全体の平均は常に2.5位で、基準は行ごとに異なる |
| 軸の目盛り | 途中の目盛りと目盛り線を置く | 両端の値だけでは差の大きさを読み取りにくい |
| プレーヤー別の判定 | 対象を切り替えて1人ずつ表示し、4人×全区分を補正して判定する | 個人についても傾向の有無を知りたい。並べて表示すると下位だけが目立ち、補正しないと偶然の判定が増える |
| 背景 | 傾向あり・兆しの項目に、一緒に動く記録・物件収益のシェア・総資産を示す。メモの語の集計と、理由を記録する新しい入力は加えない | 「なぜ増えたか」を考える手掛かりが必要だが、止まった理由は記録にない。全試合から自動で出せる範囲にとどめ、入力の負担を増やさない |
| 試合メモ | 根拠試合に本文を表示する。中の情報の活用は可とし、有無による選定・重み付けはしない | メモは途中から加わった機能で、古い試合にはない。有無で重みを変えると時期の偏りが結果に混ざる |
| 見込みの層 | 収益順位と目的地の2軸だけ | 収益の差の大きさを加えても、見込みの当てはまりと個人の平均差がほとんど変わらなかった。層が増えると少数例の併合が増える |

実装時に決める事項: 回数の区分の境界、入れ替えの回数とseedの構成、層の併合順序の詳細、結論文のtemplate、軸の目盛りの間隔、成果物とdrilldownのschema。いずれもalgorithm versionまたはschemaで追跡し、本書へ値を複製しない。

範囲外: 見込みとの差の行動仮説への接続、物件収益・目的地の多寡そのものを勝ち筋として示す表示、番手・オーナー別の見込みとの差、試合メモの有無による試合の選定・重み付け、試合メモの本文から作る派生値（初版）、新しい記録項目、統計モデルによる項目の自動選択、勝者予測、AIによる解説。
