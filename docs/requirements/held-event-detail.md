# 開催一覧・開催詳細 要求仕様

## 1. 目的

開催履歴を作成単位として扱うだけでなく、その開催に紐づく未確定作業と確定試合を、開催回内の順序で閲覧できるようにする。

開催詳細は、単一開催内の事実を短時間で確認し、試合結果、戦績比較、次試合の記録へ移動するためのハブとする。長期間の傾向、勝因候補、次戦への行動仮説は `docs/requirements/series-comparison.md` と `docs/requirements/series-review-playbook.md` を正本とし、この画面で重複して推論しない。

## 2. 情報設計

- `/held-events` は開催回を探し、作成する入口とする。
- `/held-events/:heldEventId` は1開催内の未確定作業、開催内サマリー、確定試合を表示する。
- `/matches` は開催をまたぐ検索と作業一覧を担当する。
- `/matches/:matchId` は単一試合の保存結果を担当する。
- `/analytics/series` は作品、シーズン、マップを条件とした戦績比較を担当する。

開催詳細から試合検索へ移動する場合は `heldEventId` と `sort=match_no_asc` を指定し、開催回内番号順を明示する。

## 3. 開催一覧

- 開催日時の降順で表示する。
- 各開催に確定試合数、未確定下書き数、次試合番号候補を表示できるデータを返す。
- 次試合番号候補は、確定試合と有効な未確定下書きに設定された開催回内番号の最大値に1を加える。
- 候補は番号を予約しない。確定時の一意性検証を正本とする。
- 開催作成後は、作成した開催の詳細へ移動する。
- モバイルではページ全体を横スクロールさせず、開催と操作を縦方向に読めるようにする。

## 4. 開催詳細

開催詳細は次の順で表示する。

1. 開催日時、確定試合数、未確定下書き数。
2. OCRまたは手入力で次試合を追加する操作。
3. 未確定下書きと、状態に応じた再開操作。
4. プレーヤー別の開催内1位回数、平均順位、試合番号順の順位列。
5. 開催回内番号順の確定試合タイムライン。
6. 開催単位の出力と管理操作。

開催内サマリーは保存済み順位から決定論的に算出する。サンプル数を併記し、勝因、信頼度、推薦文を生成しない。

各確定試合には、4人の順位と総資産、試合結果へのリンク、その試合を選択した戦績比較へのリンクを表示する。同一開催内で作品、シーズン、マップが異なる場合があるため、戦績比較条件は試合ごとに生成する。

## 5. 記録フローとの接続

- `/ocr/new?heldEventId=:heldEventId` は指定開催を記録先の初期値にする。
- `/matches/new?heldEventId=:heldEventId` は指定開催と次試合番号候補を初期値にする。
- 初期値の優先順位は、既存下書きまたは編集対象、URL指定開催、最新開催の順とする。
- OCR下書き作成時は、設定済みの開催IDと開催回内番号を保存する。
- 試合詳細から所属する開催詳細へ戻れるようにする。

## 6. 表示状態とアクセシビリティ

- 読み込み中は最終レイアウトに近いスケルトンを表示する。
- 空開催、未確定のみ、確定のみ、混在、取得失敗、削除済み開催を区別する。
- マスタ名称を取得できない場合は、内部IDを名称として表示しない。
- 状態は色だけで伝えず、テキストを併記する。
- タイムラインは順序付きリストとしてマークアップする。
- 主要操作の操作領域は44px以上とし、キーボードフォーカスを可視化する。
- 非必須モーションは `prefers-reduced-motion` に従う。

## 7. API要求

- `GET /api/held-events` は各開催の確定試合数、未確定下書き数、次試合番号候補を返す。
- `GET /api/held-events/:heldEventId` は開催、確定試合、算出済み状態の未確定下書きを返す。
- 確定試合は開催回内番号の昇順で返す。
- 一覧・詳細の表示のために試合詳細APIをN+1で呼ばない。
- 存在しない開催は404を返す。
