## 1. 提供価値と利用場面

総合成績に蓄積した相手との差を、必要な成績改善と、それを続ける試合数へ置き換える。相手より良い平均が必要だと示すだけでなく、少し改善すれば届くのか、その改善を続けても長くかかるのかを判断できるようにする。

現在の平均順位の差が同じでも、累積戦数が多いほど追いつくために積み重ねる成績差は大きい。次戦で順位が動かない局面も主な利用場面とし、改善幅と継続戦数の組合せを比べられることを重視する。既存の総合成績の意味を保ちながら競争の見方を広げ、接戦時だけ次戦の緊張感を補う。

| 利用場面 | 答える問い |
| --- | --- |
| 相手を追う | 直近の勝ち方・負け方が続くと、何戦で同率・逆転になるか。届かないならどれくらい変える必要があるか |
| 期間を決めて考える | 50戦後・100戦後、または指定した試合数で上回るには、どの程度の平均が必要か |
| 先行を守る | 指定した時点でも相手より上でいるには、どの程度の成績を続ける必要があるか |
| 相手の変化も考える | 自分だけが改善する場合と、相手も改善・悪化する場合で、到達時期や必要な成績がどう変わるか |
| 次の対戦へつなぐ | 必要な改善は過去の実績からどれほど離れているか。どの戦績や行動仮説を見直すと手掛かりになるか |

対戦後に距離の変化を確かめたくなること、競争への関心とゲーム・アプリへの継続的な参加につながることを価値仮説とする。試作の機能受入を、再訪や行動変化の効果検証済みとは扱わない。この機能のために独自のスコアや計測基盤を必須化しない。

## 2. 対象とデータの意味

- 作品総合と、これから試合を重ねるシーズン総合を扱う。初版の対象は全マップの成績とする。終了したシーズンを過去時点からやり直す機能は含めない。
- 固定4名から「注目する人」と「比較する相手」の異なる2名を選ぶ。ログインアカウントを注目するプレーヤーと決めつけない。
- 保存済みの確定順位から求めた算術平均順位を比較する。小さいほど良い成績であり、資産からの順位再計算、新得点・レーティングへの置換をしない。
- 2名は同じ確定試合集合に参加している前提で比較する。将来の1戦にも固定4名が参加し、1〜4位を重複なく取る。残る2名の個別成績や、4名全体での将来順位はこの比較から決めない。
- 現在の累積成績は選択した作品・シーズンの全対象試合を使う。今後の成績の初期値は、作品全体の直近20戦の順位分布を使う。この2つの母集団を混同しない。
- シーズン総合でも初期値が前シーズンを含む場合がある。対象範囲、累積成績の戦数、初期値の参照期間・戦数を確認できるようにする。マップ条件のある既存画面から入る場合、元の共有scopeを保持した別条件の試算にするか、利用者が明示的にscopeを切り替える。view選択だけでマップ条件を変更せず、総合の試算を元と同じ範囲の値に見せない。
- 直近20戦や連続した過去の実績は、戦績比較の対戦順に従う。作品の日時・件数・メンバー名を試作の値へ固定しない。
- 対象なし・件数不足・集計失敗・古い成果物は、既存の戦績比較の品質・状態契約に従う。20戦未満では実件数を示し、20戦の実績があるように補わない。換算や表示の丸めで実績平均を変更せず、算出できない項目は理由とともに区別する。
- 将来分は、選択した総合成績へ同じ試合数を追加する条件計算である。暦日、次回開催日、シーズン終了までの残り戦数は推定しない。

## 3. 見通しと必要条件

### 順算と逆算

- 2つの問いに1画面で常に答える。「この平均が続くと」では2名の今後の平均を同時に示し、その成績が続いたときに誰が先行し、何戦で順番が入れ替わるかを読む。「目標の戦数で上回るには」では指定した時点で注目する人が上回るための平均、直近からの改善幅、同期間の過去実績を読む。先行中は指定時点でも上でいるための条件を示す。初期値は直近の成績とし、操作前から両方の答えを表示する。
- 2つの問いは、同じ2名・同じ集計時点・同じ有効な成績を使う。問いを切り替える操作や、問いごとの成績・戦数の入力は設けない。
- 必要条件を考える目標戦数は初期値100戦とし、整数の1〜1000戦を指定できる。順算の推移は図の上で戦数を選んで読み、観察戦数の入力は設けない。今・10・20・50・100戦後と目標の戦数の詳しい数値は詳細で確認する。
- 目標戦数の変更や図の読み取りでは、本人・相手の平均や順位別回数を自動変更しない。目標の必要条件を示すことと、その成績を試す操作を分ける。
- 相手の仮定を変えると必要条件も変わる。本人だけを編集する間は相手の指定を保ち、相手も変える場合は別の仮定として明示的に編集する。本人の改善に対する相手の反応を自動予測しない。同じ人物の過去の累積平均と、これからの平均を取り違えないようにする。

### 計算の契約

同じ対象試合数を `N`、保存済み順位合計を `S_A`・`S_B`、これからの平均順位を `mu_A`・`mu_B`、追加戦数を `h` とする。総合の平均は次の条件計算で求める。

```text
A(h) = (S_A + h * mu_A) / (N + h)
B(h) = (S_B + h * mu_B) / (N + h)
D = S_A - S_B
G(h) = B(h) - A(h) = (-D + h * (mu_B - mu_A)) / (N + h)
```

- `G(h) > 0` はAが上、`G(h) = 0` は同率、`G(h) < 0` はBが上。「上回る」は厳密な大小関係とする。
- 指定時点でAが上となる条件は `mu_A < mu_B - D / h`。平均を0.01刻みで指定する場合は、この境界を厳密に下回る設定可能値を示す。同率になる値を「上回るための値」に含めない。
- 初めて同率以上になる整数戦数と、初めて厳密に上回る戦数を区別する。すでに先行、現在同率、相手が追いつく場合も扱う。
- 表示用の丸めを大小・同率・到達戦数の判定に使わない。実績の有理数と平均操作から作った内訳の精度を保ち、丸め後の表示が同じでも判定が違う場合は説明する。
- 成立可能な順位分布の制約も含めて判定する。「この成績では追いつかない」「100戦以内には届かない」「指定時点にはどの成立する成績でも届かない」を区別する。
- 数学的には届くが平均0.01刻みでは指定できない条件を区別し、別の入力方法を代替として案内しない。未操作の実績値が条件を満たす場合は、その正確な値で判定する。

人工例: 2名とも200戦、Aの順位合計510、Bは500、Bの今後の平均2.55とする。Aが平均2.35なら50戦後に同率、51戦後に上回る。2.45なら100戦後に同率、101戦後に上回るため、改善幅と続ける長さの違いを比較できる。50戦後に上回るための0.01刻みの条件は2.34以下となる。この例は保存データや到達予測ではない。

### 推移と次戦

- 「この平均が続くと」では、平均どおりの推移と3つの展開例を一つの差の図へ重ねて比較する。縦軸は注目する人から見た総合平均の差とし、0を同率とする。図の範囲は目標戦数から決め、50戦以下なら50戦、100戦以下なら100戦、それより長ければ200戦とする。範囲を選ぶ操作は設けない。成績の変更で横軸を変えず、縦軸は範囲内の実際の線へ合わせる。200戦を超える目標の値は詳細の表で確認する。
- 到達結果は誰が誰を何戦後に上回るかを示し、整数戦数での同率を区別する。図の範囲より後の到達も数値で示し、未到達と混同しない。結果をhoverだけに隠さない。
- 試している成績が直近の成績と異なるときは、主結果の補足で直近の成績のままの到達結果を示し、変更による違いを同じ位置で読めるようにする。別の成績を基準として保持する操作は設けない。試算を実績の更新として表示しない。
- 実際の次戦1回で同率・逆転が可能な接戦は、成立する順位の組合せを補助的に強調する。次戦で動かないときにも中長期の見通しが利用価値を持つ構成にする。

## 4. 成績を調整する操作

成績は今後の平均順位で調整し、「どれほど改善し、何戦続けるか」を比較する入口とする。スライダーでは変更量と到達時期の変化を連続して確かめ、直接入力では試したい値を正確に指定する。順位別の回数は平均から作る内訳として扱い、回数を直接操作する入口は設けない。操作の価値は、その結果から改善の負担と継続の長さを判断できることに置く。

- 本人・相手の今後の平均を主画面で同時に調整できる。
- 平均順位は0.01刻みで、連続操作と数値の直接入力に対応する。小さいほど良いこと、変更対象の人、直近との差、結果への反映が分かるようにする。
- 回数は長期の順位分布を20戦あたりに換算した目安である。直近実績の20戦換算と、平均から作った内訳には端数があり得る。表示のために丸めず、端数を実際の1試合や確定した20戦の結果として扱わない。
- 平均を実際に変更した場合は、合計・指定平均・2名の両立条件を守り、各順位へできるだけ均した回数の一例を作る。同じ平均を再入力しただけでは、手で作った内訳を置き換えない。
- 自動生成した内訳は、観測実績・本人の意図・改善の推奨手段とは区別する。同じ平均でも内訳によってブレは変わり得る。
- 各順位で2名の割合の合計が1を超える指定を受け付けない。相手を同じ試合で同順位にせず、相手の設定を黙って変更して整合させない。
- 範囲外・未完成・不成立の入力では、理由と直し方を示して直前の有効な試算を維持する。
- 対象者だけを直近の成績へ戻す操作を用意する。成績を1操作ずつ戻すアンドゥは設けない。スライダーの連続操作中は、Escapeとpointer cancelで操作開始時の成績へ戻せる。
- 一方を直近に戻すと他方の指定と両立しない場合は、その理由を示す。他方を無断で変更しない。

## 5. 試合ごとのブレ

- ブレは「この平均が続くと」の差の図で、平均どおりの線と3つの展開例を同じ軸に重ねて確認する。4パターンを同時に比べ、例を一つずつ切り替える操作を挟まない。
- 保存済みの試合ごとの順位・2名の同時順位の組合せを参照し、表示中の順位分布に対応するブレを扱う。本人と相手の両方を含め、同一試合の順位の整合を守る。
- 1000戦までの合法な展開を201候補作り、図の範囲の終点における2名の順位差を並べた20・50・80%位置から3例を選ぶ。注目する人にとって有利な順に並べ、「有利な例」「中間の例」「不利な例」とする。選んだ終点差に同値がある場合は「展開例1・2・3」の中立な名前にする。いずれも図の範囲の終点での相対的な並びであり、上限・下限、信頼区間、逆転確率として表示しない。
- 候補の作り方と3例の選び方が分かり、同じ条件なら再現できる。目標戦数・図の範囲を乱数seedへ含めず、目標戦数の変更で範囲が変わっても同じ1000戦の候補から終点に応じた3例を選び直す。範囲が変わらない目標戦数の変更や図の読み取りでは、候補・選択する3例を変えない。
- 平均と3例は図の範囲と読み取る戦数を共有する。ブレ専用の戦数の入力や観察位置を設けない。
- ブレは見通しを表示しているときだけ算出する。sliderのドラッグやキーの押し続け中は操作開始時の配分による例を保ち、確定後の成績に合わせて更新する。取消では開始時の成績と例を保つ。
- 一度追い越して再び下回る展開もあり得る。平均線の到達点や指定時点で上となる条件を、途中も含めて必ず上にいる保証として扱わない。
- 2人の差がどの例でも同じ推移になる条件ではその状態を説明し、差の違いを捏造しない。各人の平均線には違いがあり得る。ブレの例だけを作れない場合は、説明とともに利用可能な平均の試算を残す。
- 連勝・連敗の持続、将来の実力変化、因果的な戦略効果を再現したとは扱わない。初版は双方の実績と試している内訳に対応した3例でブレを読めることに絞る。独立したブレ幅の調整UIは必須にせず、平均・順位内訳・同時順位との整合を優先する。

## 6. 実績との照合と検討の続き

- 「目標の戦数で上回るには」で必要な平均を、本人の過去の同じ長さの実績と照らせる。目標が50戦なら連続50戦、100戦なら連続100戦を使い、作品内の自己ベストと対象期間・件数を確認できる。
- 同じ長さの記録がない場合は不足を示す。短期間の好成績を、長期間続けられる根拠へ読み替えない。過去の実績は当時の相手・展開を含み、表示中の相手の仮定と同条件だったとは扱わない。
- 本人の目標用には、必要平均の厳密な境界を下回る順位内訳を、実際にあった連続20戦の成績から「目標に届く実績」として示す。直近の内訳に近く、相手の指定と両立する例を優先し、目的に届くだけの極端な配分を実績に代えて勧めない。
- 本人・相手の今後の平均を条件にした実績例は示さない。過去の20戦例は本人の目標用に限り、丸め前の有理数で判定する。
- 実績例に0回の順位があっても、それだけで除外・補正しない。対象者の実績と直近からの違いを判断材料にし、全順位を含めるための固定下限は設けない。実績例の選定と、平均入力を回数へ変換するために均す規則は目的を分ける。
- 20戦未満、指定した平均を満たす実績なし、平均は満たすがもう一方の内訳と両立しない、取得失敗を区別する。本人の目標では指定時点に成立する条件自体がない場合も分ける。例がなくても成立可能な手入力は妨げない。
- 過去の例は、利用者が明示的に選んだときだけ注目する人へ反映し、「直近に戻す」で戻せる。20戦の実績を指定した全戦数まで続ける仮定であることを示す。
- 「目標の戦数で上回るには」には、必要な改善や試している内訳から「勝ち切れない試合」「下位だった試合」「好調期との違い」など、何を見直したいかという観点を示して、既存の行動仮説・戦績へつなぐ。リンクを置くだけで完結させない。
- この導線は「注目する人」を対象とする。相手の成績を編集しただけで、相手の改善策を考える導線へ切り替えない。
- 平均から自動生成した回数を、本人が選んだ戦略や実績由来の行動仮説として扱わない。既存プレイブックの候補・採否・文章・品質は再生成しない。
- 移動先が保持できる作品・シーズン等を引き継ぎ、対応していない人物・期間・順位の絞り込みまで適用したと表示しない。

## 7. 本実装へ引き継ぐ境界

### IA・UX・UI

試作で確定したのは、上記の問いに答える機能と意味である。実アプリでの配置、表・グラフ、操作、状態の仕様は9節以降に定める。細部の寸法・折り返しは既存UI規約に合わせ、本番画面の確認で調整する。

その際も、操作前に見通しを読めること、順算・逆算の条件が揃うこと、誰の何を変えると結果がどう変わったか分かることを維持する。調整と結果は近接させ、PC・mobileで同じ意味と機能を提供する。色・hover・ドラッグだけに依存させず、数値とkeyboardで操作・結果を確認できるようにする。

試作では固定した実戦績を使い、機能と操作を検討した。最新実績との一致、実際の画面構成・操作・性能、再訪や行動変化は、それぞれの利用条件に即して判断する。

### 実績集計と仮定の試算

- 保存済みの実績指標、累積値、過去窓の実績、順位の組合せ等の参照データは、既存の分析成果物の責務・一貫性に従って提供する。
- 利用者が変更する仮定からの見通し・必要条件・展開例は、実績とは別の一時的な試算である。確定戦績を書き換えず、実績の集計失敗を同期再計算で補わない。
- 試算の実行場所、配分変換、ブレの生成、成果物の分割、計算上限は9節以降に定める。wireの厳密な型・path・versionは実装時のTapir・JSON Schemaを正本とする。試作の全履歴埋め込み・ブラウザでの実績再集計を本番へ持ち込まない。
- 実績を読む範囲は用途ごとの有限なデータとし、初期表示のために全試合の詳細を取得しない。比較の基になるデータを同じ成果物・集計時点へ揃え、試合追加・訂正・削除後に新旧の値を混ぜない。
- データ更新時も、適用中の入力と参照実績の関係を明示する。更新が利用者の編集を黙って上書きしたり、過去の試算を最新実績に基づく結果として残したりしない。

### 範囲外

行動方針・目標・コミットメントの記録、試算の永続保存・公開共有、通知、新しいランキングやレーティング、4名全体の将来順位・勝者予測、目標からの配分の自動変更、新しい行動仮説生成・AI解説、未保存の行動情報の推定は追加しない。

## 9. momo-resultへの組み込み

### 入口と対象

戦績比較 `/analytics/series` の上位目的に「見通しを試す」（`view=outlook`）を追加する。「次戦に備える」「分析する」と同格とし、既存の初期viewは変えない。分析の4切り口は実績を読む場所として維持する。仮定を編集する本機能は、現在の順位や行動仮説とは異なる操作のまとまりとして置く。

- 共通の比較条件、作品・シーズン選択、状態更新、認証、`PageFrame` / `PageContentSurface` を使う。独立route、専用の画面全体テーマ、重複したpage titleを追加しない。
- 「今の差」の順位比較の近くに「総合成績の見通しを試す」を置く。`view`だけを切り替え、作品・シーズン・マップを保持する。
- マップ指定中は試算を開始せず、「見通しは全マップの総合成績で試します」と「全マップで試す」を表示する。実行時にマップだけを解除し、作品・シーズンを保持する。このためだけに個別マップのaggregateを取得しない。
- シーズン未指定は作品総合、指定ありはそのシーズン総合。シーズンには現在、開始・終了・開催中を表す正式な状態がないため、名称、表示順、最新試合から終了を判定しない。「選んだシーズンに、この先の試合を加えた場合」と説明する。過去の途中時点へ巻き戻す指定は設けない。
- 選択試合は共有URLに保持しても、見通しの計算・マーカーに使わない。このviewではmatch-contextを取得せず、「分析する」に戻ったときに既存の整合確認を通す。明示的なscope変更では既存どおり選択試合を解除する。

### 人物とURL

| 状態 | 所有と初期値 |
| --- | --- |
| 作品・シーズン・マップ・view | 既存の共通URL状態 |
| 注目する人・比較する相手 | outlook用のURL状態 `focusMemberId` / `rivalMemberId`。固定メンバーIDのみ許可する |
| 今後の平均・内訳と出所、未反映の平均入力、目標戦数 | 同じ比較を検討している間の一時状態。URL・DB・永続storageへ保存しない |

人物を未指定の場合はcanonical順の先頭2名とする。成績順やログインアカウントから本人を推定しない。人物の選択欄は「注目する人」「比較する相手」の役割順に固定し、人物変更で位置を入れ替えない。隣の「入れ替える」では2名の役割を一度に交換する。候補と同格の結果比較は既存のcanonical順を使い、候補では現在の他方を選択不可にする。一方だけが有効なら保持し、他方はcanonical順で異なる先頭の人へ補う。同一人物のURLは注目する人を保って相手を補い、不正な指定の変更理由を示す。

人物の入替・変更は別の比較を始める操作とし、2名とも直近実績へ戻す。変更先では直近の成績から検討を始める。主画面では2名を同時に編集できるようにし、編集対象を選ぶTabsを置かない。

比較ページで同じ比較の検討を続ける間は、主画面の直近1件の試算を同じ認証・ブラウザタブ内のメモリに保持する。比較内の分析タブの切替と、比較内の戦績・行動仮説を確認してブラウザの戻る操作で帰る場合を同じ扱いにする。目標戦数も保持対象とする。状態の所有者は比較ページ内の全view・lazy境界より上へ置き、見通しの非表示中は計算や取得を継続しない。

作品・シーズン・マップ・比較する人物の変更、比較ページ外への移動、認証の終了・切替、ページ再読込で主画面の一時状態を破棄する。試合一覧・詳細などから戻った場合も、新しい試算として直近実績から始める。別の比較を始めても以前の試算を複数保存しない。比較内のviewへ戻った時点でartifactが変わっている場合の復元は14節に従う。試算を永続保存・共有する機能や離脱確認dialogは追加しない。

## 10. 画面の読み順と操作の対応

2名の選択と今の総合平均に続けて、2名の「これからの平均順位」と2つの問いを1画面に置く。下位Tabsで問いを切り替えず、両方の答えを常に表示する。平均の入力方法や編集する人物のTabsも重ねない。

| 領域 | 読む内容 | 主な操作 |
| --- | --- | --- |
| 比較の条件 | 注目する人・比較する相手、今の総合平均と先行の差 | 人物の変更、入れ替え |
| これからの平均順位 | 各人の今後の平均と直近との差 | 入力・反映・取消、slider、直近に戻す |
| この平均が続くと | 到達結果、直近のままとの違い、次戦で動く組合せ、差の図 | 図で任意の戦数の値を読む |
| 目標の戦数で上回るには | 必要平均、相手の前提、改善幅、同期間の自己ベスト、必要ラインの図 | 目標戦数の入力、必要な平均を試す、目標に届く実績、本人の行動仮説・戦績へ |
| 詳しい数値と計算の前提 | 2図の代替表、累積と初期値の母集団・期間、丸めの扱い | 開閉 |

PCでは左の列に「これからの平均順位」、右に2つの問いを置く。2つの問いは「問い → 答え → 補足 → 図 → 図の注記」の同じ型とし、十分な幅では横に並べて各段の位置を揃える。左の列が画面に収まる間は、答えと図を読むときも左の列を表示し続ける。狭幅では比較の条件、これからの平均順位、「この平均が続くと」、「目標の戦数で上回るには」、詳細の順に読み、2つの答えを画面上部に固定して、入力を操作しながら結果を確かめられるようにする。PCでも2つの問いを横に並べられない幅では、答えの列の上部に2つの答えを固定する。見た目とkeyboardの移動順を揃える。

同じ強さの数値cardや同じ結論を並べず、操作の結果を読む場所を一つにする。対象scope・参照実績・試算の前提を各領域で繰り返さない。今後の平均は累積の総合平均と区別し、初期値の出所を設定の近く、詳しい期間・計算を詳細に置く。少数実績、丸め、入力不成立など、判断を変える説明は生じた箇所で示す。配置、図中のラベル、操作の名前で伝わることを説明文で繰り返さない。

入力・sliderを一つの操作群とし、補足・エラーはその後へ置く。各人の名前を見出しにし、直近からの差と「直近に戻す」、平均の入力・反映・取消、sliderを近接させる。2人の間は群内より広い余白で分け、水平線を使わずに誰の成績を変える操作かを示す。操作位置を安定させ、初回編集や補足の増減で操作対象を動かさない。結論の変化は結果側で受け、編集中の欄を押し下げない。同じ人物・scopeで成績を連続編集する間は、主結果、補足、図の領域を保ち、文量の変化で後続の操作・図を移動させない。比較の開始、詳細・実績例の開閉は意図した展開として扱う。

### これからの平均順位

各人の名前、今後の平均、直接入力とsliderを同時に表示する。名前の見出しと「これからの平均順位」を対応させ、直近からの差を見出しの行に示す。sliderには直近の位置、設定できる両端の値、良い・悪いの向きを示す。成績を変えた人にだけ「直近に戻す」を示し、その有無で入力とsliderの位置を動かさない。直近の成績以外を使う間は、出所（「平均に合わせた内訳」、実績例の期間、「更新前の直近n戦」「更新前の実績例を使っています」）を各人の操作群の末尾に1行で示し、行の高さは常に確保する。実績の平均が設定できる範囲の外にある場合は、同じ行で範囲との違いを示す。もう一方の成績を確認するための人物切替を要求しない。

### この平均が続くと

結果は「○○が△△を51戦後に上回る」のように人物名と初めて厳密に上回る戦数を主文にする。50戦後に同率になる場合は補足で分ける。現在先行する人がそのまま上にいる場合、相手に上回られる場合、現在同率の場合、同率が続く場合も名前と状態を明示し、常に注目する人が追いかけているとは決めつけない。図の範囲より後の到達も主結果に数値を残し、図の注記で範囲より先だと示す。主結果は平均どおりに進んだときの計算であり、ブレの例の到達結果と混同させない。試している成績が直近と異なる場合は、補足に「直近20戦のままなら：」として直近の成績での主文を示す（20戦未満は実件数）。実際の次戦で同率・逆転が可能な場合は、その順位の組合せを補足に示す。

差の図は次のとおりとする。

- 横軸は「この先の試合数」、0は現在。範囲は目標戦数から50・100・200戦に決め、成績の変更では変えない。
- 縦軸は注目する人から見た差「相手の総合平均 − 注目する人の総合平均」とし、0の目盛を「同率」とする。0の上下の領域に「○○が上」と人物名を付け、符号だけで向きを読ませない。範囲は図の範囲内の平均どおりと3例の実際の値と0を含め、値幅に対する余白と読みやすい目盛で決める。連続操作中は操作開始時の平均線も算定に残し、確定後は現在の線に合わせる。
- 平均どおりを太い線、3例を細い線で描き、各線の名前と終点の差を図の右側へ直接示す。名前が重なる場合は位置だけをずらし、線との対応を保つ。各人の総合平均の線は重ねない。
- 平均どおりの到達点が範囲内なら図中に示し、同率と厳密に上回る戦数が異なる場合は主結果と一致させる。範囲外の点を端へ置き換えない。
- 図の上のpointer移動・タップ・横ドラッグで戦数を選び、平均どおりと3例の差、平均どおりの2名の総合平均を読める。図はkeyboardでfocusできるsliderとし、矢印キーは1戦、Page Up / Downは10戦、Home / Endは範囲の始点・終点へ移動し、Escapeで読み取りを閉じる。読み取りは成績・目標戦数を変えない。読み取る戦数は必要ラインの図と共有し、どちらの図で選んでも両方に同じ戦数の縦線と値を示す。必要ラインの図では、その戦数で厳密に上回るための0.01刻みの平均を読める。読み取りで同期間の実績を取得しない。
- 縦方向のtouch操作はページのスクロールに使う。図全体を横スクロールさせず、範囲を利用可能幅へ収める。文字・touch対象を縮めて解決しない。

### 目標の戦数で上回るには

目標戦数は初期100戦、整数の1〜1000戦とし、問いの文の中で入力する（「100戦後に、○○が上回るには」。先行中は「先行を保つには」）。答えは注目する人がその時点で厳密に上回るための必要平均とし、相手の今後の平均という前提、直近からの改善幅、同期間の自己ベストを補足にまとめる。必要条件の表に50・100戦の別目標を常設して主結果を分散させない。

相手の成績は「これからの平均順位」と同じ有効値を使う。目標戦数の変更だけでは2名の成績を変えない。範囲外・未完成の目標入力では最後の有効な必要条件を保ち、表示中の戦数と理由を示す。

答えの隣の「○○をX位で試す」で、相手を固定したまま必要条件を満たす0.01刻みの平均を注目する人へ適用する。出所は「平均に合わせた内訳」とし、「直近に戻す」で戻せる。本人の未確定入力は置き換える。相手に未反映・不正な入力がある間は適用を止め、反映または取消で再開できるようにする。相手の入力を自動確定・破棄しない。適用しても画面の位置は変えず、2つの答えと図を新しい平均で更新する。

現在の本人の成績が既に厳密な条件を満たす場合は、その成績で上回れることを主結果とし、必要平均の境界は補足にする。成績を弱める操作は示さない。条件不成立・入力精度の制約は理由を示す。同期間の実績や20戦の過去例がなくても、成立する成績の検討は続けられる。

必要ラインの図は次のとおりとする。

- 横軸は差の図と同じ範囲とする。縦軸は今後の平均順位とし、小さいほど上へ描く。
- 相手が今後の平均を続けるとき、注目する人が各戦数で厳密に上回るのに必要な平均の境界（3節の `mu_B - D / h`）を1本の線で描き、図中で「必要な平均」と名付ける。線より良い側と悪い側の領域に「○○が上」と人物名を付ける。
- 2名の今後の平均を水平線で示し、名前と値を図の右側へ直接示す。注目する人の平均線が必要な平均の線と交わる点を、主結果と同じ到達戦数で示す。
- 目標の戦数に縦線と必要平均の点を置き、「目標」と示す。目標が図の範囲より先にある場合は図の注記で示す。

図の後に「目標に届く実績」の開閉と、注目する人の行動仮説・戦績への導線を置く。「目標に届く実績」は6節の本人の目標用の20戦例を最大3例、平均・1〜4位の回数・期間・「試す」の同じ形で示す。開閉や例の読取だけでは成績を変更しない。「試す」は注目する人だけへ実績例の分布と出所を適用し、「直近に戻す」で戻せる。どちらかの平均に未反映の文字・エラーがある間、または連続操作中は適用できない理由を示す。未確定入力を自動反映・破棄せず、適用直前に現在の条件で平均と両立を再確認する。平均を満たす実績なし、平均は満たすが相手の現在の内訳と両立する例なし、作品の実績が20戦未満、取得失敗を区別する。

### 詳細と共通の表現

詳細には、今・10・20・50・100戦後と目標の戦数について、2名の総合平均、平均どおりと3例の差、上回るのに必要な平均を一つの表にまとめ、2図の代替表とする。3例の名前と順序は図と揃え、図の範囲より後の行でも同じ3例の値を示す。累積と初期値の母集団・期間、丸めの扱いも詳細に置く。

3例の有利・不利は、注目する人にとって図の範囲の終点での順位差を比べた名前とする。途中や範囲外の戦数でも同じ順になるとは限らない。選んだ3例の終点差に同値があれば、表・図ともに「展開例1・2・3」とし、良悪の差を捏造しない。差の図の注記で、確率・上下限を示すものではないと分かるようにする。計算中・失敗・展開の重複も同じ注記に示し、成績入力と平均どおりの線は使える状態を保つ。連続操作中は操作開始時の配分による3例を保ち、確定後に更新する。平均どおりの到達結果と線は操作中も有効な成績へ追従し、操作前の例を更新後の条件の例として説明しない。算出の扱いは14節に従う。

既存の白い面、neutralの階層、member sequenceの青・赤・黄・緑、順位専用の意味表現を役割どおり使う。`MemberSequenceLabel`、共通の文字recipe・数値整列・入力・Disclosure・Button・DataTableを使い、試作の見出し装飾・配色・カード構成を移植しない。線種、図中の名前、keyboard操作、44px以上のtouch対象を持たせ、色やドラッグのみで操作させない。

### 戦績の振り返りへの接続

「目標の戦数で上回るには」に、注目する人の戦績・行動仮説への導線を置く。必要な平均だけでは何を振り返るか決まらないため、改善幅と実際に指定した内容から、記録を見直す観点を短く言葉にしてから移動先を置く。成績を試し、戦績や行動仮説を確認して戻るまでを一つの作業として扱う。初版は次の決定規則で十分とし、試算から戦略の因果を生成しない。

| 状態 | 見直す観点と導線 |
| --- | --- |
| 必要な平均が直近より良い | 改善幅と続ける戦数を参照し、本人の行動仮説を確認する。必要条件の結論文を繰り返さない |
| 本人が過去例を適用し、1位を増やしている | 「勝ち切れなかった試合で、見直せる点を探す」 |
| 同じく3・4位の合計を減らしている | 「下位だった試合で、共通する展開を確かめる」 |
| 平均だけを変更し、回数が自動生成されている | 平均の改善幅から振り返る。自動生成した回数を本人の方針として説明しない |
| 先行条件を直近成績が満たし、相手の指定とも両立する | 成績を維持できた試合の振り返りへつなぐ。平均だけが条件を満たす場合は、内訳の見直しが必要だと区別する |

複数が当てはまる場合は下位の減少、1位の増加の順に最大2観点を示す。変更対象が相手でも、本人の観点を置き換えない。行動仮説への移動は同じ作品・シーズンの `review` と本人のsection anchorへ接続し、戻ると試算を保持する。既存の本人別sectionへ安定したIDとfocus可能な見出しを加える。仮説がない場合はその状態を残し、推奨文を捏造しない。

戦績一覧には作品・シーズン・確定状態を渡し、元の比較にはブラウザの戻る操作で帰る。現行一覧が扱わない人物・順位・任意期間の絞り込みを適用したとは表示しない。作品総合なら「この作品の確定戦績を見る」、シーズン総合なら「このシーズンの確定戦績を見る」とする。一覧への移動では9節に従って一時状態を破棄し、戻った場合は直近実績から試算を始める。

## 11. 入力と一時状態

### 値の保持と表示

- 未編集の直近実績は、実際の順位別回数と実戦数 `n = min(20, 作品の確定試合数)` を保持する。平均・20戦換算を途中で丸めない。
- 分布は4順位の整数重みと分母で保持する。平均から作る内訳は20戦換算の0.01回を1単位とし、合計2000単位の精度を使う。分母が異なっても同じ分布なら同値として扱い、内部の単位を小数回数の入力操作として露出しない。平均は分布の派生値であり、独立したstateにしない。
- 各人の出所を「直近実績」「平均から作成」「過去の実績例」として保持する。実績由来の指定には元artifact・参照期間・例の窓を紐づける。平均からの内訳には「平均に合わせた内訳」を添える。実績例を手で変えた後は過去実績そのものと表示しない。
- 通常の平均表示は小数2桁。保持している内訳の平均がその間にある場合は正確な値を最大4桁で併記する。実績の循環小数は「約」と参照戦数で区別し、正確な順位合計／戦数を詳細で確認できる。同率判定は表示桁に依存させない。
- 平均の図と結果は最後の有効な入力から作る。編集中の数値文字列と有効な試算値を分け、未完成の入力を0へ変換しない。ブレの例は連続操作の確定後に更新する。

### 平均を調整

主画面では2名の今後の平均を同時に表示し、人物・入力方法を切り替えるTabsを置かない。目標戦数の変更、図の読み取り、詳細・実績例の開閉では、有効値・利用者が編集中の文字を保持する。

平均は0.01刻みのsliderと数値入力で指定する。sliderでは良い成績を左、小さい数値を左に揃え、両立可能な範囲と相手の指定を示す。元の平均が2.4105など刻みの間にある場合も、表示・focus・pointerdownだけでは丸めない。矢印キーは操作方向にある次の0.01刻みへ進む。Home / Endは設定可能な端へ移動する。ドラッグは開始から確定まで、キーの押し続けはkeydownからkeyupまでを一続きの操作とし、Escape・pointer cancelでは開始時の内訳・出所へ戻す。

数値入力はEnterまたは隣の「反映」で検証・適用する。blurでは反映せず、人物のもう一方の入力、目標戦数、図、画面離脱へ移るだけでは成績を変えない。Escapeまたは隣の取消ボタンは、内訳・出所を変えず、現在の有効値の表示へ戻す。未反映の間は入力の近くに反映済みの平均を示す。文字を変更せずfocus・確定しただけならno-opとし、近似表示を新しい指定値とみなさない。入力された数値が現在平均と厳密に同じなら、刻みの検証より先にno-opとする（2.4105から2.41050への書換えなど）。必要平均・過去例の適用や直近への復帰など別の操作でその人の有効値を変更した場合は、平均欄も新しい有効値へ同期し、古い未確定文字を残さない。

未確定の平均入力は各人の文字列として保持する。他方の編集では文字を書き換えず、現在の相手との両立を確定時に検証する。他の操作の後も未反映であることが分かるようにし、元の入力へ戻るか未反映の文字だけを破棄できるようにする。平均の文字入力を理由に他方の編集や表示操作を止めない。

実績の平均は、0.01刻みで作れる範囲の外側にある場合もある。現在値を範囲の端へ自動補正せず、sliderの表示範囲に含める。操作方向に合法な値がなければ現在値を保ち、設定できる値との違いを説明する。例えば本人の直近3戦が1位2回・2位1回、相手が1位1回・2位2回なら、本人の現在平均は4/3、相手を固定して平均入力で作れる最良値は1.34となる。

実際に平均を変更したときだけ、12節の規則で回数の一例を作り、結果へ反映する。sliderでは連続して結果を確かめられる。到達条件の値は目標戦数の指定や表示だけでは入力へ入れず、「○○をX位で試す」で明示的に適用する。過去の実績例を適用したものとは区別する。

### 直近へ戻す

- 成績を1操作ずつ戻すアンドゥは設けない。誤った変更は、入力の取消、slider操作中のEscape、各人の「直近に戻す」で戻す。
- 「直近に戻す」は対象者だけを現在の参照実績へ戻す。相手の指定と両立しなければ、該当順位と理由を示して両者を変更しない。両者を暗黙に初期化する代替動作はしない。
- 入力欄内の通常のテキストUndoを奪わない。

## 12. 採用する計算方法

### 精度と成立条件

計算の入力は整数または有理数とする。2名の順位分布を `p_A[i]`、`p_B[i]` とすると、非負・各人の総和1に加え、全順位で `p_A[i] + p_B[i] <= 1` を成立条件とする。この条件は、同じ試合で同順位にならない2名の分布を組み立てられるための必要十分条件である。残る2名には残り順位を割り当てられるが、その内訳・将来順位は生成しない。

整数比較では、編集値の分母2000と参照する実戦数の最小公倍数を `L` として分布を揃え、`r_A = sum(i * p_A[i] * L)`、`r_B`を作る。3節の大小判定には `-D * L + h * (r_B - r_A)` の符号を使う。実績更新で古い実績由来の指定を引き継ぐ場合も、その分母を含める。整数の積・除算はoverflowしない表現を使い、描画時だけ浮動小数へ変換する。

### 同率・逆転・必要平均

- 遅れている側の追いつきは、改善速度が正の場合に境界を切り上げて最初の同率以上、切り捨て＋1で最初の厳密な逆転を得る。現在同率は0戦として示し、先行・相手が追う場合も符号を反転して同じ判定を使う。
- 必要平均の厳密な境界 `T = mu_B - D/h` に対し、0.01指定の最大候補は `(ceil(100*T)-1)/100`。さらに相手と両立する配分を生成できる値に限る。単に境界を小数2桁へ丸めない。
- 選べる最良値でも届かない場合、現在の指定では届かない場合、すでに条件を満たす場合を分ける。条件を満たす直近成績に対して、負の改善幅を「改善が必要」と表示しない。
- 20戦未満の有理分布などでは、連続値として可能でも平均0.01刻みで条件を満たす指定を作れない場合がある。数学的に届かない場合は「相手の成績を変えない場合、○戦後には上回れません」、入力精度だけが制約の場合（`precision-impossible`）は「入力できる細かさでは、○戦後に上回る成績を指定できません」とする。入力精度の説明は詳細に置き、未操作の実績値まで不成立と扱わない。
- 初回到達の計算結果が1000戦を超えても到達戦数は数値で示す。1〜1000の上限は利用者が指定して検討する戦数の上限であり、到達なしの判定に使わない。
- 実際の次戦の補助情報は、異なる順位12組を `-D + (rank_B - rank_A)` の符号で判定する。平均を1戦分足した結果と、実際に次戦で取れる順位を混同しない。

### 平均から回数への変換

20戦換算の0.01回を1単位とする本人の整数値を `q[i]` とする。相手の分布に対する上限は `floor(2000 * (1 - p_B[i]))`。合計2000、指定平均を満たす順位合計、各順位の上限を満たす候補のうち、`sum((q[i] - 500)^2)` が最小の配分を採用する。同点なら操作開始時の内訳に近いもの、さらに同点なら1〜4位の回数の辞書順で決める。近さは同じく回数差の二乗和とする。

4位の整数回数を有限走査し、合計・順位合計から他順位を絞る試作の純粋関数を参考にできる。相手と参照内訳が有理数の場合にも、容量・同点判定を途中丸めで変えない。不成立を別の平均へ丸めて成功扱いにしない。

### 試合ごとのブレ

初期値と同じ作品の直近 `n` 戦から、2名の同時順位表 `R` を使う。過去全期間の組合せや、シーズンの累積分布へ黙って切り替えない。両者が現在artifactの直近実績のままなら、この観測表が指定した双方の分布と一致する。

1. `R`を共通分母`L`の整数表へ変換する。表示中の双方の分布を周辺和とし、対角0・総和Lを満たす表`Q`を作る。
2. `R`からのL1距離を最小にする最小費用流を用いる。各合法セルを「Rまで費用0」「超過分費用1」に分ける。双方の総和がLなので、超過分の合計を最小にすることはL1距離の最小化と同値になる。固定した人物順・順位順・辺順で同点の経路を決める。
3. 観測されなかった合法な組合せも、変更した分布の実現に必要なら使う。これは将来の組合せを仮定する操作であり、過去の観測事実を増やすことではない。対角0、行列和、非負、総和を確認できない場合はブレだけを表示不能にする。
4. `Q`から1000戦の合法な同時順位を抽選し、201本の候補を作る。これは確率推定に必要な標本数ではなく、3例を選ぶための実装定数であり、変更時は計算方式の版と再現性を揃える。乱数は作品・canonical順の人物pair・計算方式の版から決め、配分変更時も同じ乱数列を新しい`Q`へ対応させる。目標戦数・図の範囲・入力値・artifactをseedへ含めず、表示操作や順位に無関係な実績訂正で抽選し直さない。
5. 図の範囲の終点（50・100・200戦）でのcanonical順の2名の差で候補を並べ、同値は生成順にする。20・50・80%位置に近い候補を順に選ぶが、すでに選んだ軌跡は避け、最も近い未採用の軌跡を選ぶ。同じ距離なら小さい添字を優先する。201本の場合の起点は0始まりの40・100・160番となる。目標戦数の変更で図の範囲が変わった場合は、同じ1000戦の候補から選び直す。
6. 軌跡の一致は0〜図の範囲の終点の差の列で判定し、図に見える範囲で異なる推移を優先する。その範囲で異なる軌跡が3本未満の場合だけ重複を許し、その数を説明する。選んだ3例は終点差を注目する人の方向へ揃え、有利な順に並べる。人物の役割を反転しても候補の同時順位は変えず、同じ軌跡の差の符号を反転する。画面では平均と3例を一つの差の図へ重ねる。

seed付き乱数生成と整数重みによる抽選は一つの版を持つ純粋な計算に閉じる。同じ分布を別の共通分母で表しても抽選が変わらないよう整数重みを約分し、確率の端を丸めて禁止順位を抽選しない。目標戦数・図の範囲の変更、詳細・実績例の開閉、図の読み取りでは候補の抽選結果を変えない。図の範囲が変わった場合は候補を再利用して3例の選定を変え、範囲が変わらない目標戦数の変更では選定も変えない。配分・参照する同時順位表・作品・人物pair・計算方式の版が変わると候補を更新する。非表示時の計算抑制と連続操作中の配分は14節に従う。artifactは計算結果の鮮度を守るidentityへ含め、過去の結果が新しい入力を追い越して反映されないようにする。

3例は「試している成績から作った、展開の異なる例」と説明する。終点差が互いに異なる場合は「有利な例・中間の例・不利な例」、同値がある場合は3例とも「展開例1・2・3」とする。選び方の詳細では図の範囲の終点差を使うことを示し、中央確率範囲・予測区間とは呼ばない。候補に異なる差の軌跡が足りない場合と、どの試合でも2人の順位差が一定になる場合を区別する。後者も各人の平均線まで同じとは限らないため、「2人の差が同じ推移」と説明する。少数の実績から作った例を、将来のブレを測定できた結果として扱わない。各試合は同じ分布から抽選し、連勝・連敗が次戦へ影響するモデルは追加しない。

## 13. 実績データと読取契約

### 分析バッチが作るもの

同じ確定試合snapshotから以下を作り、既存の作品artifactへ追加する。見通しのための別job、利用者の試算を保存するtable、リクエスト中の分析計算は設けない。

| 保存resource | 単位 | 内容と上限 |
| --- | --- | --- |
| 見通しsummary | 作品overall・各season、いずれも全マップ | 対象戦数と品質、4名の順位合計・現在平均。作品の全戦数、直近n戦の品質・順位別実回数・実平均・参照期間、6組の同時順位表、4名の50・100戦の自己ベストまたは同期間不足 |
| 見通しreference | 作品overall・メンバー別 | 1〜min(作品戦数, 1000)戦それぞれの自己ベスト窓、実在した20戦の順位内訳の同値型 |

過去窓・20戦例・同時順位は作品ごとに一度計算し、seasonごとに全履歴を再計算しない。各seasonで変えるのは現在の累積値とその対象期間・件数である。summary内の作品共通の小さな情報は、結果・入力・50戦と100戦の比較を一度の読取で満たすために同梱してよい。

選択scopeと作品直近n戦の品質は、それぞれの実件数からWorkerが共通契約に従って決める。作品200戦・選択シーズン1戦なら、累積値は参考扱い、直近20戦は通常の実績として区別する。Webで件数から品質を再判定せず、品質の良さを将来の確かさへ読み替えない。自己ベストも窓あり・同期間不足を区別し、比較元の作品戦数を使って不足理由を表示する。

0戦の作品にもoverall summaryを対象なし（`no_target`）として作る。この場合は平均・個人の分布・本人別referenceを持たせない。season summaryは既存scope索引にある全マップのseasonを対象とし、試合がないseasonのために空の組合せを増やさない。索引上の対象なしと、存在するはずのchunk欠落を区別する。

自己ベストは連続h戦の順位合計が最小の窓とし、同値なら既存の対戦順で終了が最も新しい窓を採る。保存するのは窓長、順位合計・平均、開始・終了試合IDと期間であり、全窓・全試合の列ではない。prefix sumまたはローリング集計を使い、計算量は最大 `O(4 * 1000 * 作品戦数)`、保存数は各人最大1000窓とする。

20戦例は4順位の回数が同じ窓を一つに集約し、代表は終了が最も新しい窓とする。型は各人最大1771個であり、平均の良い例だけへ打ち切らない。各型に順位回数、実平均、代表窓の期間・端点を持つ。直近20戦換算の内訳との回数差の絶対値合計が小さい順、同値なら終了が新しい順、さらに回数の辞書順で並べて保存する。実績が20戦未満なら型は空とし、不足理由を持たせる。20戦以上なら1〜min(1771, 作品戦数−19)型が必ずあり、不正な空集合を正常な不足に変換しない。

### APIと画面での取得

見通し用の認証済みreadを3用途に分ける。具体的なendpoint path、DTO field、schema番号は実装時のTapir・JSON Schemaを正本とし、次の入力・意味・上限を守る。

| read | 入力 | 返すもの・取得時点 |
| --- | --- | --- |
| summary | 作品、artifact、任意season | 選択scopeの見通しsummary。`outlook`選択かつ全マップのときだけ取得 |
| 同期間の過去実績 | 作品、artifact、注目する人、h | 目標戦数の有効値が50・100以外のときに保存済みreferenceから該当hの1窓を取得する。50・100はsummary内の値を使い、初期目標100戦には追加取得しない。図の読み取りは取得理由にしない |
| 20戦の実績例 | 作品、artifact、参照する人 | 保存済みの型と順序。注目する人の「目標に届く実績」を開いたときだけ、そのmember IDで取得する。同じartifact・対象者の取得済みデータを再利用し、仮定の変更では再取得しない |

APIは用途に対応する一つの有限chunkを読み、保存済みの値を射影する。1〜1000戦のために1000個のresourceを作らず、メンバー別referenceから要求された窓を選ぶ。候補は型単位の有限集合を返し、全試合の詳細を送らない。summaryを表示するために既存aggregate・review・drilldownを追加取得しない。共通のScopeBarはscope・artifactと目的に応じた品質注記を受ける形へ適合し、既存aggregate型を満たすための余分な取得を避ける。

- `h > 作品戦数` は正常な「同期間の実績なし」。存在するはずのhの欠落は成果物破損として扱い、不足へ変換しない。20戦未満による保存例なし、利用者の条件に合う例なし、未取得、取得失敗も区別する。対象なしの画面では補助readを発行しない。
- map指定を受け付けるsummaryを作らない。不正な人物、h、作品・seasonの不整合、chunkの欠落は既存のエラー契約に従い、別scopeへfallbackしない。
- artifact・scope・member・hをreadのidentityへ含め、同じ認証・権限・更新境界を使う。現在名称の変更で集計の意味値や保存順を変えない。
- 取得した20戦例に対し、Webは丸め前の有理数で適合性を判定し、保存順の先頭から最大3例を表示する。本人の目標用として、例の平均が必要平均の厳密な境界未満のものを選び、相手の現在の分布との両立を確認する。実績の再集計、実績に基づく独自の候補順位付け、行動プレイブックの再選定はしない。
- 平均条件を満たす型がない場合と、満たす型はあるがもう一方の分布と両立しない場合を区別する。適用は例の対象者だけを変更し、適用直前にも人物・artifactと最新の条件を確認する。現在の相手・目標で再検証し、10節の入力保護に従う。

### 成果物の完全性と互換性

本機能を含む新しいalgorithm・artifact・validation contractの組を導入し、producer・full validator・publisher・readerを揃える。既存の個別payloadが変わらない場合、そのpayloadの世代まで一律に変更しない。新しい要求resourceが欠けた成果物を、任意機能なしの成功として公開しない。

full validatorは、対象なしを含む必要scopeの完全性を検証する。作品に対象試合がある場合は4名・6組の表・本人別referenceを要求し、整数合計と平均の整合、直近n戦の周辺分布と表の一致、対角0、窓の長さ・期間・件数、20戦型の重複なし・順序、summaryとreferenceの一致を検証する。自己ベストは1〜min(作品戦数, 1000)の窓長を欠落・重複なく持ち、summaryの50・100戦は同じ窓または明示的な不足となる。APIは意味の検証を再実装せず、認めたpublication contractとboundedなshape・identityを確認する。

referenceの件数上限に加え、encoded / decoded bytes・深さの上限を保存schemaとreaderへ定める。最大候補数と最大入力で成立する上限を実装時に確認し、静かに型を削って上限内へ収めない。新resourceの保存、公開後の変更禁止、件数検証は共有DB側の正式な変更として扱い、その作業前にmomo-dbの開発手順を読む。

## 14. 更新と失敗

| 状態 | 表示と続けられる操作 |
| --- | --- |
| 対象scopeが0戦 | 既存の空状態。平均・必要条件・成績入力を作らない |
| 作品の実績が1〜19戦 | 実件数の初期値で計算。参照期間を示し、20戦例なしと同期間不足を項目ごとに表示。1〜2戦の参考扱いは共通契約に従う |
| 導入時に対応するartifactが未生成 | 既存の成果物未準備の表示と更新導線を使う。旧世代用の互換decoderや、view別に異なるartifactへfallbackする経路を追加しない。非対応versionと対応成果物の破損を区別する |
| 初回summary取得中／失敗 | 比較条件の位置を保つ。読込中は人物の選択、2名の入力、2つの問いの答えと図の骨格を表示完了時の配置・形に揃える。失敗時は見通しの再読込を示し、架空の初期値を置かない |
| 同期間の実績・目標に届く実績の取得失敗 | 該当部分だけで再試行。取得失敗を該当例なしへ読み替えず、入力、図、必要条件は使える状態を保つ |
| ブレを計算中／計算不能 | 成績入力、2つの答え、平均どおりの線は利用可能。差の図の注記に局所状態を示し、古い条件の例を新しい条件の結果に見せない |
| 対応する既存artifactで更新・計算中／失敗 | 集計時点と状態を示して直前の成功結果を維持する |
| artifactが失効 | 既存のbounded recoveryでstatusと対応resourceを一度取得し直す。古いartifactを最新値と混ぜない |
| 人物・scopeが変わった | 新しい比較の開始として主画面を初期化し、一時状態を破棄する |

平均、逆算、配分の検証、ブレの生成はネットワークへ送らずWebの純粋関数で行う。有効値の反映に合わせて平均の結果を更新する。ブレは見通しを表示中だけ算出する。連続操作中は開始時の2名の配分による候補と3例を保ち、確定した時点で有効な成績から再生成する。取消では開始時の成績と例を保つ。最大入力で操作を妨げないか確認し、必要な場合にWeb Worker等へ計算を分離する。分離を初版の必須構成にはしない。非同期化した場合も要求ごとの計算identityで古い結果を破棄し、画面を離れた後の処理を終了する。候補を増やし続ける継続計算や常時アニメーションは行わない。

同じartifactの再取得は一時入力を変えない。ドラッグやキーの押し続け中に新artifactが届いた場合は、操作の確定・取消まで採用を待つ。artifact ID、集計時点、品質、累積値、参照実績を同じ表示単位で切り替え、数値だけ古いまま時点を先に更新しない。

新artifactの採用時は、次の規則を一体で適用する。

- 両者とも採用中artifactの直近実績をそのまま使っている場合だけ、2名の初期値を新しい直近実績へ揃える。旧artifact由来の値は、この自動追従の対象に含めない。
- それ以外は両者の指定分布を正確なまま維持し、累積値と参照実績を新しいartifactへ切り替える。「試している成績を残して実績を更新しました」と局所表示する。旧実績由来の値は「更新前の直近n戦」「更新前の実績例を使っています」として元の出所を残す。元の試合が訂正・削除されても、新しい成果物の実績例として表示しない。両者を保つため、片側だけの自動更新による不成立を起こさない。
- 取得済みの過去実績・例・ブレは新artifactのものに揃え、別resourceの失敗でsummaryの切替を無期限に待たない。更新前の実績例を新artifactの候補として適用しない。順位分布・同時順位表が同じなら、ブレの抽選は変えず、新しい累積値に対応する線を作る。
- 主画面の未確定の平均入力は文字を保持し、切替後の相手で再検証する。人物自体が利用できなくなった場合は条件の正規化と理由を示し、別人へ以前の成績を移さない。

データの再取得は既存の初回・明示更新・失効回復に従う。スライダー、ブレ表示、hover、window focusを、データ更新や分析jobの開始理由にしない。
