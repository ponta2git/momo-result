# 見込み順位との差 要求仕様（草案）

状態: 草案（2026-11-15）。採否と範囲は未確定であり、[10節の未決事項](#10-未決事項)を決めてから実装へ渡す。確定までは本書を既存指標の変更根拠にしない。

目的: 桃鉄のルール上、物件収益が多い人と目的地に多く着いた人は総資産が増えやすく、順位が上がるのは当然である。この当然の部分を「見込み順位」として先に差し引き、残った差が誰に・どの記録と一緒に現れているかを示す。ルールからは読み取れない差を、次戦で試す行動を考える手掛かりにする。

| 関心事 | 正本 |
| --- | --- |

| 比較ページ全体のscope、順位・金額・同値の共通定義 | [戦績比較](series-comparison.md) |

| HTTP・成果物の構造 | Tapir endpoint、JSON Schema |

## 1. 成功条件

- 各プレーヤーについて「物件収益の順位と目的地の回数が同じだった場合の平均と比べ、実際の順位が上か下か」を、説明者の補助なしに答えられる。
- 場全体について「見込みとの差が、どの記録の多い・少ないと一緒に現れているか」を、値と件数を添えて答えられる。物件収益と目的地の多寡そのものを答えにしない。
- あるプレーヤーの差が、特定の記録の区分に偏っているのか、どの区分でも同じ向きなのかを見分けられる。
- 偶然の範囲に収まる差を傾向として読ませない。対象なし・少数例・観測された0を区別できる。
- 共起を因果として表現しない。見込みは保存済みの結果から作る比較の基準であり、勝敗の予測、能力の評価、試合中の行動の観測として扱わない。

## 2. 当然の部分と、残りの部分

| 分類 | 記録 | 本書での扱い |
| --- | --- | --- |
| 見込みに使う | 物件収益の試合内順位、目的地の回数 | 順位と結び付くことがルールから分かる。見込み順位の層に使い、差の説明には使わない |
| 差の説明に使う | カード売り場、プラス駅、カード駅、マイナス駅、スリの銀次 | 見込みとの差を回数の区分別に示す |
| 使わない | 総資産 | 最終順位を直接決めるため、見込みにも説明にも使わない |
| 使わない（初版） | 番手、オーナー、マップ、シーズン | 既存の条件別比較とscope切替で読む |

総資産には物件の価値と目的地の賞金が含まれる。そのため「収益が多いと上位」「目的地が多いと上位」は、戦い方の手掛かりというより採点方法の言い換えに近い。本機能はこの部分を主表示にしない。

### 既存指標との関係

- [順位を読む手掛かり](series-comparison.md#6-advanced-rank-analysis) は、物件収益と事件簿6項目を同じ重みの候補として扱う。物件収益が含まれるため、当然の項目が先頭に並びやすい。本機能の「記録別の差」は、同じ問い（何が順位と結び付くか）に当然の部分を除いて答える。同じ話題を二つのblockへ置かないための扱いは [未決事項1](#10-未決事項) とする。
- [予測より上位だった勝利](series-comparison.md#6-advanced-rank-analysis) は全signalを使うモデルの予測との差であり、本機能の見込み（物件収益の順位と目的地だけ）とは基準が異なる。初版では変更しない。
- 既存の物件収益順位との差、目的地変換効率、収益トップ未勝利率は、平均どうしの差または条件付きの率である。本機能は1試合ごとに同じ層の平均と比べる点が異なり、既存の値の定義は変えない。

## 3. 見込み順位

- 権限、scope、確定済み試合、保存順位の扱いは [戦績比較の不変条件](series-comparison.md#2-data--scope-invariants) に従う。
- 単位は、選択scope内の1試合における1プレーヤーの結果（以下「明細」）とする。各明細を次の2つの組合せによる層へ分ける。

| 軸 | 区分 |
| --- | --- |
| 収益順位 | その試合で本人より物件収益が大きい人数に1を足した値（1〜4）。同値は同じ順位とし、最大値と同値の全員が1位になる |
| 目的地 | 0回、1回、2回以上 |

- 見込み順位は、選択scope内で同じ層に入る全明細（4人分を合算）の保存順位の平均とする。本人の明細も含める。
- 明細が3件未満の層は、同じ収益順位の中で目的地の区分が隣り合う層と併合し、併合後の層で平均を求める。併合の順序は決定論的に固定する。併合しても3件に満たない収益順位は、その収益順位の全明細を一つの層とする。
- 見込みは選択scopeごとに作る。別のscope、別の作品、過去の成果物の平均で補わない。マップやシーズンを絞ると、その範囲での見込みに変わる。
- 見込みとの差は `見込み順位 − 保存順位` とし、正の値は見込みより上位だったことを表す。
- 層ごとの差の合計は0になる。したがって選択scopeの全明細の差の合計も0になり、4人の平均差を試合数で重み付けした和は0になる。

## 4. 指標

### 個人の差

| 指標 | 定義 |
| --- | --- |
| 平均差 | 本人の全明細の見込みとの差の平均。正ほど、同じ収益順位・目的地回数の平均より上位 |
| 対象件数 | 本人の選択scope内参加試合数 |
| 標章 | 5節の偶然の幅を超えた場合だけ「見込みより上位」「見込みより下位」を示す |

### 記録別の差

カード売り場、プラス駅、カード駅、マイナス駅、スリの銀次のそれぞれについて、回数を区分し、区分ごとに次を算出する。場全体（4人の明細を合算）と各プレーヤーの両方で同じ定義を使う。

| 指標 | 定義 |
| --- | --- |
| 件数・割合 | その区分に入る明細数と、分母に対する割合。分母はプレーヤーでは本人の参加試合数、場全体では全明細数 |
| 平均差 | その区分に入る明細の見込みとの差の平均 |

- 回数の区分は項目ごとに固定する。0回の明細が大半を占める項目は「0回／1回以上」、それ以外は少ない側・中間・多い側の3区分とし、具体的な境界はalgorithm versionで追跡する。選択scopeや表示のたびに境界を作り直さない。
- 場全体の値を主とし、「この記録が多い（少ない）明細は、見込みより上位（下位）だった」を読む。プレーヤー別の値は、本人の平均差がどの区分に現れているか、その区分に入る頻度が場全体とどう違うかを読むために使う。
- 項目どうしは互いに調整しない。ある項目の区分別の差には、同時に起きやすい別の項目の影響が含まれうる。係数、寄与率、項目間の重要度の順位は表示しない。
- 区分別の平均差を「1回あたりの効果」へ換算した値は初版に含めない（[未決事項4](#10-未決事項)）。

## 5. 件数・品質・偶然の差

| 対象 | 件数 | 表示 |
| --- | --- | --- |
| 選択scopeの試合数 | 0 | 共通の空状態 |
| 選択scopeの試合数 | 1〜2 | 見込みを作らず「対象なし」 |
| 選択scopeの試合数 | 3〜19 | 数値・件数と既存の「参考値」。標章は付けない |
| 区分の明細数 | 0 | 割合は観測された0%、平均差は「—」 |
| 区分の明細数 | 1〜2 | 数値・件数と「参考値」 |

- 個人の平均差の標章は、試合内でプレーヤーを無作為に入れ替えた場合にも同程度に現れる差を除いて付ける。区分別の平均差の標章は、試合内で区分を無作為に入れ替えた場合を基準にする。どちらも [既存の較正方針](../../apps/processing-worker/crates/analysis-core/src/compute/signals.rs) と同じ考え方で、弱い判定は4回に1回程度、強い判定は10回に1回程度しか偶然では出ない大きさを境界とする。
- 境界は対象の件数に応じて決める。算出方法と定数はalgorithm versionで固定し、本書へ値を複製しない（[未決事項5](#10-未決事項)）。
- 標章が付かない差は「差がない」ではなく「偶然の範囲と区別できない」と読めるようにする。標章の有無にかかわらず数値と件数は表示する。
- 併合した層があるscopeでは、見込みが粗くなっていることを品質の注意として確認できるようにする。

検討時点の確定済み戦績では、見込みに使う2項目だけで順位のばらつきの半分近くが説明され、残りの差はカード売り場とプラス駅の区分で偶然の幅を超え、成熟したscopeのいずれでも同じ向きだった。個人の平均差が偶然の幅を超えたのは一部のプレーヤーに限られた。実測値は本書へ記載しない。

## 6. 表示

- 「分析する」→「勝因候補」に置く（[未決事項2](#10-未決事項)）。ページ上部の作品・シーズン・マップ、対戦数、最終更新、「表示を更新」を共有し、block内へ複製しない。
- 読む順序は、見込みの意味を一文で示す導入、4人の平均差、場全体の記録別の差、プレーヤー別の記録別の差とする。見込み順位の層ごとの値は補助開示へ置く。
- 4人の平均差は同じ軸に並べ、0（見込みどおり）を基準線として示す。正負の向きと「上位・下位」の対応を文字でも示し、色だけで伝えない。
- 記録別の差は、行を項目と区分、列を場全体と固定4名とする。平均差を主、件数と割合を補助として対応づける。項目・区分・メンバーの順序を成績や差の大きさで並べ替えない。
- プレーヤー別の列は、場全体と同じ区分で読み比べられるようにする。初期表示を場全体と4人の平均差までにし、プレーヤー別の区分を開示にするかは読みやすさで決める。
- 文言は「〜回だった試合では見込みより上位だった」のように記録と結果の対応として書く。「売り場へ行けば順位が上がる」「プラス駅に止まるのは損」のような因果・行動の断定を使わない。読み方の説明には、回数が試合終了時の値であり順序が分からないこと、余裕のある展開だから回数が増えた可能性を消せないことを含める。
- PC・mobileで項目、区分、名前の順序、数値、分母を変えない。mobileでは1人の列に着目して全区分を読めることを優先し、必要な横スクロールは表内に閉じる。
- 対象試合一覧、試合詳細へのリンク、区分からのdrilldownは初版に含めない（[未決事項3](#10-未決事項)）。ページ共通の選択試合の表示と戻り先は維持する。

## 7. 行動プレイブックへの接続

初版は集計値の比較までとし、行動仮説への接続は初版の画面で読解を確かめた後に検討する（[未決事項6](#10-未決事項)）。接続する場合の方針は次のとおりとする。

- 場全体で共通する記録別の差は、個人cardではなく [共通論点](series-review-playbook.md#2-output--presentation) の候補とする。
- 個人cardは、本人の平均差が5節の強い判定を満たし、かつ区分への頻度または区分内の差に場全体との違いがある場合に限る。
- 発動条件は本人の自己観察とし、試合中の収益順位や回数を記録したかのように書かない。候補の採否・縮小・品質境界・文面の規則は [プレイブック正本](series-review-playbook.md#4-deterministic-selection) に従う。

## 8. 実装に渡す境界

- 既存の分析入力だけで計算する。入力、DB schema、記録項目、OCRを本機能のために変更しない。
- 各scopeの集計と同じ入力から事前計算し、aggregateへ保存する。追加payloadは、層の表（最大12層）と、「場全体＋固定4名」×「5項目の区分」の固定サイズに収める。明細ごとの差、試合ID、drilldown用の明細は追加しない。
- 見込み、差、区分、件数、品質、標章はWorkerが確定する。APIとWebは保存済み成果物を検証して表示し、層の併合・平均・偶然の差の判定を再計算しない。
- 意味検証は、層の件数の合計と全明細数、層ごとの差の合計が0であること、各項目の区分の件数の合計と分母、プレーヤー別の区分の件数の合計と場全体の件数を照合する。不正な成果物は公開しない。
- 既存の「順位を読む手掛かり」を置き換える場合は成果物の非互換変更となる。API・Web・Workerと既存作品の再計算を [切替契約](series-analysis-batch.md#8-compatibility--release--rollback) に従って揃え、手掛かりを参照するプレイブックの候補と詳細リンクを対応させる。
- 更新中・失敗時の直前成功成果物の扱い、同一成果物への固定、取得失敗は [分析バッチ](series-analysis-batch.md#6-api--web--admin) の共通契約に従う。

## 9. 受入条件

| ID | 利用者が得る結果 | 主な確認境界 |
| --- | --- | --- |
| AC1 | 各明細がちょうど一つの層に入り、見込み順位が同じ層の平均順位になる。層ごとの差の合計が0になる | 収益の同値、全員の収益0、目的地0回と複数回、3件未満の層の併合を含む純粋計算 |
| AC2 | 個人の平均差と、記録別・区分別の平均差・件数・割合が4節の定義と分母で算出される | 区分の境界、件数0の区分、プレーヤー別と場全体の照合 |
| AC3 | 試合数と区分の件数に応じて、対象なし・参考値・通常値を区別できる。割合の観測された0%と平均差の対象なしを取り違えない | 件数境界の分岐、選択scope全体が0戦の空状態 |
| AC4 | 偶然の範囲の差に標章が付かず、標章のない差を「差がない」と読ませない | 入れ替えた戦績での標章の出現頻度、境界値 |
| AC5 | 見込みの意味、4人の平均差、場全体の記録別の差の順に読める。PC・mobileで項目・区分・値・件数・参考値を読める | component、Playwright MCPによる表示確認と下記の読解課題 |
| AC6 | マップ・シーズンを切り替えると、その範囲の見込みで計算した値に変わり、別scopeの値が混ざらない | scope切替、同一成果物への固定 |
| AC7 | 計算中・失敗・未取得を、最新の値や対象なしと混同しない | API・Webの成果物と状態の接続 |
| AC8 | 既存scopeの集計・振り返り・通知などのconsumerが新契約で壊れない | 変更したconsumerの契約証拠 |

証拠は [テスト・品質規約](../test-rule.md) に従って選び、[Change Gates](../dev-rule.md#change-gates) に割り当てる。

読解課題は「自分は見込みより上位か下位か、その差に標章は付いているか」「場全体では、どの記録のどの区分が見込みより上位・下位だったか」「自分の差は特定の区分に偏っているか」に、値と件数を添えて答えられることとする。あわせて「見込みより上位」を「強い」「うまい」と言い換えずに説明できるかを確認する。明確な差がない結果も失敗扱いにせず、差の捏造へ誘導しない。

### 手計算できる具体例

以下は説明用の架空データであり、実際の戦績ではない。層「収益順位2位・目的地0回」に入る明細が次の4件だけだったとし、層の併合は考えない。

| 試合 | プレーヤー | 順位 | カード売り場 |
| --- | --- | --- | --- |
| 1 | B | 2位 | 1回 |
| 2 | C | 3位 | 0回 |
| 3 | A | 1位 | 2回 |
| 4 | B | 2位 | 0回 |

- この層の見込み順位は `(2 + 3 + 1 + 2) / 4 = 2.0` となる。
- 見込みとの差は、試合1のBが0、試合2のCが−1.0、試合3のAが＋1.0、試合4のBが0で、合計は0になる。
- この層だけで見ると、カード売り場の区分別の平均差は、0回が `(−1.0 + 0) / 2 = −0.5`、1回が0、2回以上が＋1.0となる。いずれも1〜2件のため参考値とする。
- プレーヤーBのこの層での平均差は0であり、「収益2位で目的地0回なら2位」という見込みどおりの結果を表す。Bの順位が2位と高くても、見込みより上位とは読まない。
- 実際の集計では、全層の明細をまとめて区分別・プレーヤー別の平均差を求める。

## 10. 未決事項

採否の前に決める事項と、草案時点の推奨を示す。

| # | 事項 | 推奨 | 理由 |
| --- | --- | --- | --- |
| 1 | 既存の「順位を読む手掛かり」（プレーヤー別の最大3件）を本機能へ置き換えるか、併存させるか | 置き換える。モデルを共有する「予測より上位だった勝利」「王座の確からしさ」は残す | 同じ問いに二つのblockが別の単位で答えることになる。検討時点の手掛かりは4人ともほぼ同じ項目が並び、先頭は物件収益だった |
| 2 | 置き場所 | 勝因候補 | 「何が順位と結び付くか」を読む場所であり、置き換える場合は手掛かりの位置を引き継げる |
| 3 | 見込みより大きく上位・下位だった試合へ移動できるようにするか | 初版の後に検討 | 試合メモには数値に残らない手筋が書かれており、根拠試合として価値が高い。ただし差が同値の試合が多く、一覧の選び方を決める必要がある |
| 4 | 区分別の差を「1回あたり何位ぶん」へ換算して示すか | 初版は見送る | 換算には回帰が必要で、手計算で確かめられなくなる。区分別の平均差で同じ向きと大きさを読める |
| 5 | 偶然の差の境界を、固定した定数表にするか、成果物の計算時に入れ替えで求めるか | 実装時に決める | 件数に依存し、既存の試合数帯だけの定数では足りない。決定性と計算量の上限を満たす方法を選ぶ |
| 6 | 行動プレイブックへ候補を加えるか | 初版の後に検討 | 場全体の差が主であり、共通論点としての文面と発動条件を画面での読解後に決めたい |
| 7 | 見込みの層に、収益の差の大きさ（シェアなど）を加えるか | 加えない | 検討時点では、加えても見込みの当てはまりと個人の平均差がほとんど変わらなかった。層が増えると少数例の併合が増える |

範囲外: 物件収益・目的地の多寡そのものを勝ち筋として示す表示、番手・オーナー別の見込みとの差、新しい記録項目、統計モデルによる項目の自動選択、勝者予測、AIによる解説。
