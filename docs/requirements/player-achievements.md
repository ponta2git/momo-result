# 実績達成管理 要求仕様

状態: 初版を実装し、ローカルレビューの対象とする。星からポイントへの配点は5節の暫定値で試作しており、画面で確認してから確定する。

試合結果とともに実績の達成を記録し、誰がいつ初達成したかを振り返れるようにする。作品ごとの実績リストを運用担当以上が管理し、難易度に応じた達成度を既存の戦績レーダーチャートにも表示する。

本書は実績リスト、初達成、配点、実績軸、初期移行の要求を定める。試合・プレーヤー・認証と共通権限は[基本要求](base.md)と[ドメインルール](../domain-rule.md)、既存6軸の採点は[プレーヤーレーダー比較](series-player-radar.md)、分析の再計算・公開は[分析バッチ](series-analysis-batch.md)を正本とする。DB構造、API、画面配置は本書では固定しない。

## 1. 対象と管理単位

- 実績リストは作品ごとに持つ。初期データは、提供された「桃鉄2これが出来たら凄いリスト（案）」TSVの31項目とする。
- 項目は達成内容・条件、対象マップ、難易度、備考を持つ。難易度は星1〜5で表示する。
- 対象マップを指定でき、「共通」は後から追加するマップも含め、その作品内の全マップで達成可能な項目を意味する。他作品へは共有しない。新マップでも同じ項目・達成状況を使い、項目を複製しない。
- 達成者は既存の固定4人のプレーヤーとし、入力するログインアカウントとは区別する。
- プレーヤーと項目の組み合わせごとに初達成を1件として表示・加点する。同じ項目の再達成で回数やポイントを増やさない。共通項目もマップごとに再取得する実績にはしない。訂正に必要な独立した根拠の扱いは3節に従う。
- 達成状況は作品通算とし、シーズンの切替でリセットしない。

### 項目の追加と表示順

- 運用担当以上が項目を追加できる。自動判定は3節の4種類から種類と閾値を設定し、それ以外は手入力の条件として管理する。
- 初期移行・導入後の追加にかかわらず、その作品の過去の全確定試合を対象にする。項目の追加日や試合の登録日による開始制限は設けない。後から追加した項目も保存済みの試合から判定する。
- 対戦日時は[基本要求の結果記録](base.md#71-確定時の必須項目)に従い、開催日時とは区別する。初達成は対戦日時から求め、項目を登録した日時で置き換えない。
- 誤字修正、条件の意味を変えない説明補足、星の変更は同じ項目の更新とする。達成条件、判定方法、対象作品・マップを実質的に変える場合は別項目を追加し、旧項目を廃止する。新しい条件も過去の全確定試合に適用し、旧項目の手入力による達成を移し替えない。
- 管理時に作品内の表示順を変更・保存できる。モバイルとキーボードでも並べ替えられ、保存した順を閲覧・試合入力・訂正候補へ共通して使う。表示側の独自ソートは設けず、マップなどで絞った後も保存順を保つ。新項目は末尾に追加する。
- 並べ替えは全項目を一括保存し、編集中の項目追加・廃止・別の並べ替えを検出して黙って上書きしない。表示順だけの変更では達成条件・入力の版・得点を変えず、再計算しない。

### 廃止と達成履歴

- 廃止は物理削除にせず、旧項目の内容・達成条件・対象マップと各人の初達成記録を保持する。
- 廃止項目は通常の入力候補から外し、現在の獲得ポイントと対象総ポイントの両方から除く。新しい試合から達成を追加しない。
- 通常の実績リスト・試合入力・訂正候補には現役項目を表示する。廃止した項目は管理画面の折りたたみから確認し、各プレーヤー名のリンクで達成状態・日時・根拠の個別記録を開ける。全編集操作の版履歴は初版の要件に含めない。
- 廃止済みの自動判定項目は、廃止時点の達成状態・初達成日時・根拠を履歴として固定する。その後の試合訂正・削除・追加によって再判定せず、確認・取消・日時や根拠の訂正も行わない。過去に移行実績を含めて固定した履歴も、その内容を保持し、現在の判定方法で作り直さない。「廃止時点の記録」であることを表示する。
- 固定する履歴には、廃止直前までの保存済み入力を反映した一貫した結果を使う。未反映の入力や計算失敗が残る旧結果を、最新の履歴として固定しない。
- 自動項目の廃止は、現行の保存済み入力と互換な最新成功結果が揃うときだけ成立させる。同じ整合性境界で鮮度と項目の版を確認し、固定履歴の保存・廃止・得点の再計算予約をまとめて確定する。未計算・失敗・競合時は未廃止を維持し、利用者が集計完了後に改めて廃止する。自動実行の予約は設けない。
- 旧項目の定義と固定した達成履歴は、通常の分析成果物の整理・削除で失われない永続記録として保持する。古い成果物や元試合への参照だけで代用しない。
- 手入力実績の訂正・根拠喪失は廃止後も3節に従う。根拠の試合が削除された場合は、自動・手入力のいずれも無効なリンクを出さず、固定した履歴では参照先が削除済みと分かるようにする。
- 項目・達成履歴が参照する作品やマップを、マスタ削除によって連鎖消去しない。参照中のマスタは既存の参照保護に従って削除を拒否する。

## 2. 権限

| 操作 | 権限 |
| --- | --- |
| リストと達成状況の閲覧 | 既存の試合結果を閲覧できる有効なアカウント |
| 項目・達成条件・対象マップ・難易度・備考の管理 | 運用担当、管理者 |
| 手入力実績の入力・修正 | 既存の試合登録・修正と同じ権限。一般も全員分を入力・修正できる |

管理権限と達成入力権限を画面とAPIで一致させる。新しいロールや、達成入力に対する追加承認は設けない。移行実績の確認・訂正も手入力項目に限り、達成入力と同じ権限で行える。自動項目への直接入力・移行実績の訂正は画面とAPIの両方で認めず、廃止済み自動項目の固定履歴も変更しない。管理権限を失っても、一般に許される達成入力とその未保存内容を破棄しない。

## 3. 入力と達成判定

### 試合結果との記録

- 手入力による試合作成とOCR確認からの確定の両方で、試合結果とともに手入力項目の達成を入力できる。入力は任意とし、試合結果だけでも保存できる。確定済み試合の編集でも達成を追加できる。保存済みの達成は参照表示とし、取消・日時訂正・根拠の付け替えは専用ページで行う。
- 試合の作品・マップに適用できる項目を扱い、プレーヤーごとの達成を記録する。
- 自動判定できる項目は確定試合の保存値だけから判定し、特殊なカード操作や出来事など、保存値だけでは判定できない項目は手入力する。
- 今回の試合へ入力する達成と、すでに保存された達成を区別する。保存前の入力は取り消せるが、今回入力しなかったことや送信項目の欠落を理由に既存の達成を解除しない。
- 手入力に記録がない状態は「まだ記録なし」とし、実際に未達成だったと確認した意味にはしない。毎試合の「達成なし」の確認は要求しない。
- 達成入力も既存の試合入力の一時保存・復元・離脱保護に含める。別アカウント、別試合、更新された元データへ古い入力を復元しない。
- 未確定下書きの入力を、確定済みの達成や得点として扱わない。

### 自動判定と段階条件

自動判定の種類と閾値の意味は以下とする。管理画面ではこの種類と数値を設定し、項目名の文面から判定方法を推測しない。

| 条件 | 判定に使う記録 |
| --- | --- |
| 総資産が閾値以上 | 試合終了時の保存総資産。途中で到達しても終了時に下回った場合は対象外 |
| 1試合の目的地到着回数が閾値以上 | 確定試合の目的地回数 |
| 1試合のスリの銀次の回数が閾値以上 | 確定試合の銀次回数 |
| 1開催の平均順位が閾値以下 | 下記の開催条件を満たす4試合の保存順位の算術平均 |

有効な自動判定項目は保存済みの確定試合だけを根拠とし、移行実績や直接入力、上位項目の達成からの補完を使わない。各項目の適用範囲と閾値を対象試合から独立に評価し、満たした各項目のポイントを合計する。例えば総資産40億円なら、20億円以上・30億円以上・40億円以上をすべて達成とする。目的地回数なども「以上」、平均順位は各項目の「以下」で判定する。廃止済み上位項目の固定履歴を、有効な下位項目の自動判定の根拠にはしない。

手入力の包含関係は、初期リストの次の2組だけを固定で扱う。項目の識別子で対応づけ、星の数や名称の類似から推測しない。管理画面で関係を追加・変更せず、新しい関係は実装変更として追加する。後から追加した項目は、明示的に対応するまで他項目を補完しない。

- 福袋は1回の使用で得た枚数で判定する。「パトカード＋ダビングカードを4枚」は合計4枚で片方が0枚でもよく、「パトカードを4枚」を達成したら両方を達成とする。
- 同じ「1が出るまでカード」で半年以上1が出なければ、3か月以上の条件も達成とする。
- 下位項目の対象マップも満たす場合に限って補完する。上位を未確認としているだけでは下位を達成にしない。

現行の確定試合では、資産・目的地・銀次の保存値から未確認と0を区別できない。自動判定は保存値に基づき、記録されていない出来事を補って達成とみなさない。

### 開催平均と訂正への追従

- 「1開催（4試合）の平均順位」は、開催全体が同じ作品の確定4試合で構成される場合だけ判定する。東日本・西日本などのマップ混在は許可する。
- 4試合未満、5試合以上、または作品が混在する開催を対象にしない。任意の4試合を選び出す判定にはしない。
- 4試合すべてが項目の対象マップの条件を満たすことを必要とする。初期リストの開催平均は共通項目なので、作品内の全マップを対象にする。
- 有効な項目では、試合の訂正・削除や開催構成の変更が自動判定へ影響する場合に再判定し、達成状況と得点へ反映する。5試合目の追加などで条件を外れた開催を、達成の根拠として使い続けない。廃止済みの自動判定項目は1節の固定履歴として扱う。

### 初達成日時と根拠

- 自動判定の初達成は、項目の適用範囲内で条件を満たす最古の記録とする。順序は[戦績比較の対戦順](series-comparison.md#2-data--scope-invariants)を使い、登録順では判定しない。
- 試合単位の達成日時は対象試合の対戦日時とする。開催平均の達成日時は、対象4試合の対戦順で最後の試合の日時とし、根拠はその開催へ紐づける。
- 手入力の初達成は利用者が確認した対象試合を根拠にする。新規試合作成では同じ操作で確定する試合を使い、別試合を指定する場合は項目の作品・マップに合う確定試合から選ぶ。より古い初達成が分かった場合は明示的に訂正できる。
- 手入力項目では、直接の入力、移行元の申告、上位項目からの補完を、訂正時に区別できる根拠として扱う。補完によって直接の手入力や移行元の根拠を上書きしない。毎回の再達成を蓄積する要求ではなく、現に成立している独立した根拠を保持するための区別とする。
- 手入力項目に複数の根拠がある場合は、判明している達成日時のうち最古のものを使い、同時刻の試合間は既存の対戦順に従う。最古の根拠が取り消されたら、残る根拠から求め直す。日時不明の根拠が残る場合は実際の初達成日時を断定せず、日時が分かる最古の記録を示す。「記録上」を日付に付けず、詳細で日付の分からない達成もあることを補足する。
- 入力・移行した時刻を達成日時の代わりにしない。日時不明の移行実績の扱いは6節に従う。

### 自動判定と手入力の訂正

- 有効な自動判定項目の達成状態・根拠を直す場合は元の試合結果を訂正する。達成だけの手動上書きや、手動指定を優先する切替は設けない。訂正後は適用範囲内の記録から最古の有効な根拠を求め直す。廃止済みの自動判定項目は再判定しない。
- 有効な自動判定項目は、条件を満たす試合・開催がなくなれば達成を解除し、得点から除く。既存の移行実績があっても達成を維持する根拠にはしない。6節の手入力項目の移行実績は、該当試合が見つからないだけで解除しない。
- 手入力実績は、根拠試合の削除、作品・マップ変更など、根拠が対象外になっても達成済みを維持する。紐づけを外して「根拠不明」とし、それまでに記録した達成日時は保持する。別の試合を自動で補わない。
- 手入力の誤達成を取り消す操作と、根拠の紐づけを外す操作を区別する。専用ページで取消・適用範囲内の別試合への付け替えができる。有効な根拠試合がある間は、その対戦日時へ達成日時を追従させる。専用ページで独立した日時を補完・訂正できるのは、日時・根拠不明の記録に限る。
- 手入力項目の包含関係と移行時の補完は、根拠となる上位達成に追従する。取消対象の根拠を区別し、上位達成の取消だけで、直接の入力など独立した根拠がある下位項目まで消さない。下位への補完自体を直す場合は上位の根拠を訂正する。取消後も別の根拠によって達成が残る場合は、その理由を表示する。
- 上位項目を廃止して得点から除いたことだけを理由に、すでに成立していた下位達成を消さない。自動判定の下位項目は独立に再判定するため、例えば40億円項目の廃止後に元試合を10億円へ訂正したら、固定した40億円履歴は残るが、その試合による20億円の達成は解除する。
- 手入力項目の直接入力・移行実績の訂正には最終変更者・変更日時を保持し、達成者・達成日時と区別する。

## 4. 達成状況の閲覧

専用ページで、作品全体の実績リストと4人の達成状況を確認できるようにする。マップによる表示の絞り込みは設けない。確定試合が0件の作品でも、リストと手入力項目の移行実績を閲覧できる。

- ページの要約は4人の獲得・対象ポイントに絞り、レーダー用の換算点数は戦績比較側で扱う。
- 項目の達成内容・条件、対象マップ、星、備考を確認できる。
- 一覧の4人分のセルは達成状態の表示に専念し、操作ボタンを置かない。項目ごとの「記録」列に「記録を見る」を1つ置き、実績単位のモーダルを開く。
- モーダルでは共通の条件・メモを一度だけ示し、その下でプレーヤーを切り替えて、各人の達成と獲得ポイント、日付、振り返れる試合または開催を確認する。根拠の内部分類を前面に出さず、どの記録から達成になったかを具体的に伝える。廃止項目に現在の獲得ポイントを表示しない。プレーヤーを指定した既存リンクは、その人の記録を開く。
- 達成、まだ記録なし、確認待ちの実績を区別する。日時不明と根拠不明は、達成の有無とは別に示す。有効な項目の確認待ちは手入力項目の初期移行の保留状態であり、毎試合の確認作業を増やさない。
- 達成日時・根拠が不明な記録に、移行日時や無関係な試合を補わない。
- 試合詳細にはその試合が根拠の達成を表示し、専用ページと相互に辿れる。試合結果の訂正は既存の試合編集へ、手入力項目の直接入力・移行実績自体の訂正は専用ページへ案内する。
- 手入力項目の日時不明の移行実績は、専用ページで達成の確認・取消・日時や根拠の補完を行える。自動項目は廃止前後を問わず、達成の確認・訂正操作を表示しない。通常の新規手入力は試合に紐づけ、日時不明の新規登録を独立した入口として増やさない。
- 手入力項目の訂正は実績モーダルで選択したプレーヤーの記録から行い、保存・キャンセル後も同じ実績・プレーヤーへ戻る。移行実績は「以前の記録」として目的を説明し、未確認・取消済みの記録もここから確認・復元できる。集計前の項目も保存済みの記録に到達できるようにし、集計済みの達成状態やポイントを推測して表示しない。保存後の集計待ちや取得失敗はモーダル内でも分かるようにする。

## 5. ポイントとレーダー

### 暫定配点

高難度を重く評価し、試作用の配点を次のとおりとする。実際の画面で確認してから初版の正式な数値を決める。配点はシステム側の固定値とし、運用担当が変更するのは項目ごとの星とする。星別の配点編集画面は作らない。

| 難易度 | ★ | ★★ | ★★★ | ★★★★ | ★★★★★ |
| --- | --- | --- | --- | --- | --- |
| ポイント | 1 | 4 | 9 | 16 | 25 |

達成済み項目のポイントを合計する。未確認は得点に含めない。星を変更した場合は、達成当時の配点を固定せず、全員の既存達成分も現在の星・配点で計算し直す。

### 実績軸

- 既存の6軸へ「実績達成」を7軸目として追加する。既存の成績軸の計算は維持する。
- 実績軸は作品通算の達成度を表す。シーズンで絞っても通算値を表示し、その対象期間を読み取れるようにする。
- マップ指定時は、そのマップに適用される項目を分子・分母の対象にする。共通項目の達成は、初達成したマップにかかわらず共有する。全マップでは項目を重複なく数える。
- 廃止項目を除いた対象項目の現在の総ポイントに対する獲得ポイントの達成率を使い、保存した採点曲線で1〜10点へ換算する。既存6軸の成績分布から作る閾値とは別の計算とする。
- 実績軸は、既存6軸の試合数・開催数や採点基準の有無にかかわらず、対象項目と記録された達成状況から算出する。

達成率は `100 × 獲得ポイント ÷ 対象項目の総ポイント`。1・3・5・7・10点に対応する5つの達成率を保存し、隣接する点の間を直線で補間する。最初の達成率以下は1点、最後の達成率以上は10点とする。初期値は次のとおり。

| 点数 | 1 | 3 | 5 | 7 | 10 |
| --- | --- | --- | --- | --- | --- |
| 達成率 | 0% | 10% | 25% | 50% | 80% |

初期値では未達成は1点、配点の半分で7点、80%以上で10点となる。対象項目がない場合は採点対象外とし、未達成の1点とは区別する。

曲線は作品共通とし、既存の採点基準設定に「実績達成」を加えて編集する。入力は0〜100%の有限数5つを厳密な昇順とし、重複・逆転・範囲外・空欄を拒否する。現在の基準または有効な候補から編集し、同じ入力保持、仮プレビュー、正式比較、適用、改訂履歴、復帰の手順を使う。6軸の自動提案は現在の曲線を引き継ぐ。既存基準に曲線が保存されていない場合と基準未作成の場合は初期値で採点し、旧基準の識別内容を書き換えない。基準未作成の作品で実績曲線だけを単独で保存・適用する機能は含めない。

正式比較は実績の対象項目・達成記録・獲得ポイントを同じ時点で固定し、変更前後で曲線だけを変える。項目・星・達成状況など採点に影響する変更があれば比較を失効させ、入力を保持して再計算・再確認する。実績だけの変更で6軸の自動提案値を再生成しない。

実績軸の数値は既存の数値整形に合わせて最大小数2桁で表示し、計算・描画には丸め前の値を使う。獲得ポイントと対象総ポイントも確認できる。比較条件が0試合や少数の場合も、既存6軸の対象なし・未採点と、採点可能な実績軸を区別し、実績軸の数値と専用ページへの導線を残す。未採点の成績軸を0点や1点で補わない。

項目の追加・廃止や星・配点の変更で総ポイントが変われば、既存の達成状況が同じでも実績軸の点数は変わる。実績ポイントの合計はこの軸の入力であり、7軸の合計・平均や総合順位は作らない。

## 6. 初期移行

- 提供TSVの項目・難易度・備考を移し、カテゴリの東日本・西日本・共通を作品内の対象マップへ対応づける。
- プレーヤー列は既存の固定4人に対応づける。達成記号の形式は、自動・手入力のいずれの項目でも検証する。
- 自動判定項目の「達成！」「達成？」は達成記録として取り込まない。保存済みの全確定試合から判定し、条件を満たす最古の試合・開催を初達成の根拠にする。該当記録がなければ、TSVの記号にかかわらず達成・加点しない。
- すでに保存されている自動項目の移行実績や直接入力は削除・書き換えをせずに残すが、有効な自動項目の達成状態・初達成日時・根拠・得点の計算には使わない。廃止済み自動項目は1節の固定履歴を保持する。
- 手入力項目の「達成！」は日時・対象試合不明の既存達成として保持し、通算ポイントに含める。「達成？」は未確認として保持し、得点に含めない。該当試合が見つからないだけで確認済み達成を解除しない。
- 移行時の下位補完は3節の手入力2組だけに適用し、未確認からは補完しない。目的地回数などの自動項目は、上位の移行実績から補完しない。
- 手入力項目の未確認実績は、確認できた結果に従って達成または達成記録なしへ訂正できる。直接入力などの独立した根拠がある場合は、移行実績の訂正だけでその達成を取り消さない。
- 移行の再実行で項目や達成を重複作成したり、確認済みの訂正を戻したりしない。実際のDB変更は[DB利用規約](../db-rule.md)とmomo-dbの開発手順に従う。
- 導入後の項目追加でも過去の全確定試合へ遡って判定する。有効な自動項目について、試合の訂正・削除に伴い適用範囲内の根拠を再判定することは通常運用として継続する。

## 7. 保存と再計算

- 試合結果と送信された手入力達成は一つの成功単位で保存する。達成入力が不正なら試合だけを部分確定せず、入力を保持して修正できるようにする。既存のOCR下書きを閉じる契約も維持する。
- 実績だけを追加・訂正する保存では、画面に残った古い試合結果を書き戻さない。結果も同時に変える場合は、試合自体の元の版を含めて競合を確認する。
- 再送で重複達成・重複加点を作らない。編集中に参照する試合・項目・達成が更新された場合は、古い状態で他者の訂正を黙って上書きせず、未保存入力を保って最新状態を確認し直せるようにする。
- 達成の入力・訂正・取消、判定に使う試合情報、項目追加・廃止、星の変更は、保存と同じ整合性境界で影響作品の再計算を予約する。表示名・備考・表示順だけの修正では再計算しない。
- 開催平均については、変更試合の作品だけでなく、変更前後の開催に属する全作品を影響対象に含める。例えば作品Aの4試合開催へ作品Bの試合を追加・削除すると、Aの実績も変わる。作品内の試合だけに絞ってから開催の4試合条件を判定しない。
- 対象項目・星・達成集合・分子・分母・実績軸は同じ計算時点に揃え、作品の全表示範囲へ一括で反映する。実績や星だけの変更で既存6軸の採点基準を作り直さない。
- 実績の計算・表示対象は、試合行だけからではなく、固定4人と作品の項目・対象マップからも求める。0試合の作品や追加直後のマップでも実績を扱い、空の試合や比較用の架空scopeを作らない。マップ追加で共通項目の表示範囲が増えた場合も反映する。
- 記録の保存成功と、集計結果の更新完了を区別する。管理・編集では保存された最新状態を確認できるようにし、閲覧・採点では旧集計へ新しい星や達成状況を混ぜない。
- 更新中・失敗時は直前に成功した集計を状態付きで維持する。初回未計算・取得失敗を達成記録なしや0点へ置き換えない。再計算の失敗を理由に保存済み入力の再送を求めない。公開・再試行の境界は[分析バッチ](series-analysis-batch.md)に従う。

## 8. 受入条件

| 観点 | 満たす結果 |
| --- | --- |
| 権限 | 運用担当以上だけがリストを管理でき、一般も既存の試合権限で全員分の手入力実績を入力・修正できる |
| 項目の改訂 | 条件変更は別項目にする。自動項目は最新集計が揃う場合だけ廃止でき、廃止時点の履歴を固定して、その後の試合訂正や成果物整理で変えない。過去に固定した移行分も再計算しない。廃止項目は獲得点・対象総点から除く |
| 記録 | 手入力・OCR確認の両経路で任意入力でき、再送・再達成・移行との重複で加点を増やさない。入力なしで既存達成を消さない |
| 対象期間 | 初期項目・追加項目とも過去の全確定試合を対象にし、追加日・登録日・端末のタイムゾーンによる制限を設けない |
| 表示順 | 管理画面で保存した順を閲覧と入力候補に使い、絞り込み後も順序を保つ。モバイル・キーボードで変更でき、競合・失敗時は編集を保持する |
| 判定 | 自動4種類を閾値付きで管理でき、終了時資産・回数・開催平均を確定試合の保存値だけから判定する。移行実績・直接入力・上位達成から自動項目を補完しない。手入力の包含関係は初期2組に固定し、名称変更で関係を失わない |
| 訂正 | 有効な自動項目は元の試合結果へ追従し、根拠を失えば移行実績があっても解除する。達成自体の確認・訂正は手入力項目に限る。手入力は根拠試合の削除等でも達成を維持する。上位の取消で直接の下位根拠を消さず、残る最古の根拠へ戻る |
| 開催の影響 | 有効な項目では同一作品の確定4試合だけを対象にし、別作品の試合追加・削除で条件が変わった作品も再判定する |
| 閲覧・移行 | 専用ページで達成者・日時・根拠を辿れ、日時不明・根拠不明・未確認を区別する。自動項目のTSV記号は検証のみで取り込まず、既存の移行実績も計算に使わない。手入力項目の移行元の達成は該当試合なしだけで取り消さない |
| 採点 | 作品通算・対象マップ・現行配点・1〜10点換算と分子分母が一致する。0試合や新マップでも共通項目を扱い、未採点の成績軸とは独立して実績軸を読める |
| 保存・公開 | 実績だけの保存で試合結果を戻さず、同時編集の競合時は未保存入力を保つ。部分保存を防ぎ、保存完了と集計更新を区別し、失敗時に新旧の項目・得点を混ぜない |

## 9. 初版の範囲と配点の確認

- 初版はリスト管理、試合登録・詳細、実績専用ページ、レーダーへの反映を対象とする。達成通知、実績専用エクスポート、既存CSV/TSVの列追加、汎用インポート画面、任意の条件式を記述する仕組みは含めない。
- 実績・星だけの変更で、内容の変わらない既存の試合結果通知を送らない。試合結果も変更した場合は既存の通知契約に従う。
- DB・API・分析成果物の保存形、ページの具体的な配置は実装時に既存の正本へ定める。初回データ移行の実施・本番適用は、要求整理とは別の実装・運用作業とする。

未確定なのは星別配点の正式な数値とする。5節の値で試作し、下位条件を含む獲得点と実績軸の見え方を確認してから決定する。配点の管理UIを追加する判断とは分けて扱う。
