## 1. 提供価値と利用場面

総合成績に蓄積した相手との差を、必要な成績改善と、それを続ける試合数へ置き換える。相手より良い平均が必要だと示すだけでなく、少し改善すれば届くのか、その改善を続けても長くかかるのかを判断できるようにする。

現在の平均順位の差が同じでも、累積戦数が多いほど追いつくために積み重ねる成績差は大きい。次戦で順位が動かない局面も主な利用場面とし、改善幅と継続戦数の組合せを比べられることを重視する。既存の総合成績の意味を保ちながら競争の見方を広げ、接戦時だけ次戦の緊張感を補う。

| 利用場面 | 答える問い |
| --- | --- |
| 相手を追う | 直近の勝ち方・負け方が続くと、何戦で同率・逆転になるか。届かないならどれくらい変える必要があるか |
| 期間を決めて考える | 50戦後・100戦後、または指定した試合数で上回るには、どの程度の平均が必要か |
| 先行を守る | 指定した時点でも相手より上でいるには、どの程度の成績を続ける必要があるか |
| 相手の変化も考える | 自分だけが改善する場合と、相手も改善・悪化する場合で、到達時期や必要な成績がどう変わるか |
| 次の対戦へつなぐ | 必要な改善は過去の実績からどれほど離れているか。どの戦績や行動仮説を見直すと手掛かりになるか |

対戦後に距離の変化を確かめたくなること、競争への関心とゲーム・アプリへの継続的な参加につながることを価値仮説とする。試作の機能受入を、再訪や行動変化の効果検証済みとは扱わない。この機能のために独自のスコアや計測基盤を必須化しない。

## 2. 対象とデータの意味

- 作品総合と、これから試合を重ねるシーズン総合を扱う。初版の対象は全マップの成績とする。終了したシーズンを過去時点からやり直す機能は含めない。
- 固定4名から「注目する人」と「比較する相手」の異なる2名を選ぶ。ログインアカウントを注目するプレーヤーと決めつけない。
- 保存済みの確定順位から求めた算術平均順位を比較する。小さいほど良い成績であり、資産からの順位再計算、新得点・レーティングへの置換をしない。
- 2名は同じ確定試合集合に参加している前提で比較する。将来の1戦にも固定4名が参加し、1〜4位を重複なく取る。残る2名の個別成績や、4名全体での将来順位はこの比較から決めない。
- 現在の累積成績は選択した作品・シーズンの全対象試合を使う。今後の成績の初期値は、作品全体の直近20戦の順位分布を使う。この2つの母集団を混同しない。
- シーズン総合でも初期値が前シーズンを含む場合がある。対象範囲、累積成績の戦数、初期値の参照期間・戦数を確認できるようにする。マップ条件のある既存画面から入る場合、元の共有scopeを保持した別条件の試算にするか、利用者が明示的にscopeを切り替える。view選択だけでマップ条件を変更せず、総合の試算を元と同じ範囲の値に見せない。
- 直近20戦や連続した過去の実績は、戦績比較の対戦順に従う。作品の日時・件数・メンバー名を試作の値へ固定しない。
- 対象なし・件数不足・集計失敗・古い成果物は、既存の戦績比較の品質・状態契約に従う。20戦未満では実件数を示し、20戦の実績があるように補わない。換算や表示の丸めで実績平均を変更せず、算出できない項目は理由とともに区別する。
- 将来分は、選択した総合成績へ同じ試合数を追加する条件計算である。暦日、次回開催日、シーズン終了までの残り戦数は推定しない。

## 3. 見通しと必要条件

### 順算と逆算

- 操作前から、直近の成績が続く場合の見通し、50戦後・100戦後に上回るための平均、直近からの改善幅を確認できる。先行中は指定時点でも上でいるための条件を示す。
- 「この成績が続くと」と「この試合数で上回るには」は、同じ条件の見通しと必要な変更を行き来する一連の検討である。同じ2名・同じ集計時点・同じ相手の仮定を使い、別々の試算状態へ分断しない。
- 10戦後・20戦後など複数時点の結果と、利用者が指定した正の整数戦数の結果を数値で確認できる。100戦を超える時点も数値で検討できる。入力上限は本実装の計算・応答境界として定め、UIに明示する。
- 指定した試合数を変更しても、本人・相手の平均や順位別回数を自動変更しない。成績まで同時に変わると条件の効果を比較できなくなるため、必要条件の表示と、その条件を試す操作を分ける。
- 相手の仮定を変えると必要条件も変わる。本人だけを編集する間は相手の指定を保ち、相手も変える場合は別の仮定として明示的に編集する。本人の改善に対する相手の反応を自動予測しない。同じ人物の過去の累積平均と、これからの平均を取り違えないようにする。

### 計算の契約

同じ対象試合数を `N`、保存済み順位合計を `S_A`・`S_B`、これからの平均順位を `mu_A`・`mu_B`、追加戦数を `h` とする。総合の平均は次の条件計算で求める。

```text
A(h) = (S_A + h * mu_A) / (N + h)
B(h) = (S_B + h * mu_B) / (N + h)
D = S_A - S_B
G(h) = B(h) - A(h) = (-D + h * (mu_B - mu_A)) / (N + h)
```

- `G(h) > 0` はAが上、`G(h) = 0` は同率、`G(h) < 0` はBが上。「上回る」は厳密な大小関係とする。
- 指定時点でAが上となる条件は `mu_A < mu_B - D / h`。平均を0.01刻みで指定する場合は、この境界を厳密に下回る設定可能値を示す。同率になる値を「上回るための値」に含めない。
- 初めて同率以上になる整数戦数と、初めて厳密に上回る戦数を区別する。すでに先行、現在同率、相手が追いつく場合も扱う。
- 表示用の丸めを大小・同率・到達戦数の判定に使わない。小数の回数から生じる精度も保ち、丸め後の表示が同じでも判定が違う場合は説明する。
- 成立可能な順位分布の制約も含めて判定する。「この成績では追いつかない」「100戦以内には届かない」「指定時点にはどの成立する成績でも届かない」を区別する。
- 回数の詳細指定では届くが、平均0.01刻みでは指定できない狭い範囲も区別する。入力できない平均を通常の達成条件として案内しない。

人工例: 2名とも200戦、Aの順位合計510、Bは500、Bの今後の平均2.55とする。Aが平均2.35なら50戦後に同率、51戦後に上回る。2.45なら100戦後に同率、101戦後に上回るため、改善幅と続ける長さの違いを比較できる。50戦後に上回るための0.01刻みの条件は2.34以下となる。この例は保存データや到達予測ではない。

### 推移と次戦

- グラフは現在からこの先100戦までを表示する。同率以上になる時点は、平均どおりに進む線上へ常時表示し、hoverだけに隠さない。
- 100戦より後の到達は数値で示し、未到達と混同しない。指定戦数の変更でグラフの横軸を際限なく伸ばさない。
- 条件を変更したときは、現在試している条件と直近実績のままの条件を比較できる。試算を実績の更新として表示しない。
- 実際の次戦1回で同率・逆転が可能な接戦は、成立する順位の組合せを補助的に強調する。次戦で動かないときにも中長期の見通しが利用価値を持つ構成にする。

## 4. 成績を調整する操作

平均の調整は「どれほど改善し、何戦続けるか」を比較する入口、回数の調整は「どの順位を増減させるか」を具体化する入口とする。スライダーでは変更量と到達時期の変化を連続して確かめ、直接入力では試したい値を正確に指定する。操作の価値は、その結果から改善の負担と継続の長さを判断できることに置く。

- 本人・相手の双方について、平均順位の指定と1〜4位の回数の指定を行き来できる。切替だけでは値、内訳、ブレ、変更履歴を変えない。
- 平均順位は0.01刻みで、連続操作と数値の直接入力に対応する。小さいほど良いこと、変更対象の人、直近との差、結果への反映が分かるようにする。
- 回数は長期の順位分布を20戦あたりに換算した目安であり、合計20回とする。0.01回刻みの直接入力と、合計を保ちながら順位間で回数を移す操作に対応する。端数を実際の1試合や確定した20戦の結果として扱わない。
- 回数から平均を算出する。平均0.01刻みより細かな値になる場合も、平均操作へ切り替えただけでは丸めない。例えば `[5.54, 5.18, 4.81, 4.47]` 回の平均は2.4105である。
- 平均を実際に変更した場合は、合計・指定平均・2名の両立条件を守り、各順位へできるだけ均した回数の一例を作る。同じ平均を再入力しただけでは、手で作った内訳を置き換えない。
- 自動生成した内訳は、観測実績・本人の意図・改善の推奨手段とは区別する。同じ平均でも内訳によってブレは変わり得る。
- 各順位について2名の回数の合計が20を超える指定を受け付けない。相手を同じ試合で同順位にせず、相手の設定を黙って変更して整合させない。
- 範囲外・合計不一致・不成立の入力では、理由と直し方を示して直前の有効な試算を維持する。入力を黙って別の値へ丸めない。
- 通常のアンドゥと、対象者だけを直近の成績へ戻す操作を用意する。アンドゥは平均だけでなく内訳も戻し、スライダーのひと続きの操作を1回として扱う。表示切替や目標戦数の変更を成績変更として混ぜない。
- 一方を直近に戻すと他方の指定と両立しない場合は、その理由を示す。他方を無断で変更しない。

## 5. 試合ごとのブレ

- ブレを重ねる表示は任意に入切でき、初期値は非表示とする。操作はグラフと対応が分かる場所に置く。
- 保存済みの試合ごとの順位・2名の同時順位の組合せを参照し、表示中の順位分布に対応するブレを扱う。本人と相手の両方を含め、同一試合の順位の整合を守る。
- 平均の線とは別に、展開が多少異なる3パターンを表示する。幅を意識して代表例を選ぶが、上限・下限、信頼区間、逆転確率として表示しない。
- 3パターンの選び方と意味が分かり、同じ条件なら再現できる。開閉や目標戦数の変更だけで100戦までの例を抽選し直さない。
- 表示の入切では平均の線、必要条件、入力値を変えない。条件の変更では対応する内訳とブレを揃える。
- 一度追い越して再び下回る展開もあり得る。平均線の到達点や指定時点で上となる条件を、途中も含めて必ず上にいる保証として扱わない。
- ブレが生じない条件では3本が重なることを説明し、違いを捏造しない。ブレの例だけを作れない場合は、説明とともに利用可能な平均の試算を残す。
- 連勝・連敗の持続、将来の実力変化、因果的な戦略効果を再現したとは扱わない。初版は双方の実績と試している内訳に対応した3例でブレを読めることに絞る。独立したブレ幅の調整UIは必須にせず、平均・順位内訳・同時順位との整合を優先する。

## 6. 実績との照合と検討の続き

- 必要な平均を、本人の過去の同じ長さの実績と照らせる。50戦なら連続50戦、100戦なら連続100戦を優先し、作品内の自己ベストと対象期間・件数を確認できる。
- 同じ長さの記録がない場合は不足を示す。短期間の好成績を、長期間続けられる根拠へ読み替えない。過去の実績は当時の相手・展開を含み、表示中の相手の仮定と同条件だったとは扱わない。
- 必要な平均を満たす順位内訳の例は、実際にあった連続20戦の成績から、直近の内訳に近く、相手の指定と両立する例を優先して示す。目的に届くだけの極端な配分を実績に代えて勧めない。
- 実績例に0回の順位があっても、それだけで除外・補正しない。本人の実績と直近からの違いを判断材料にし、全順位を含めるための固定下限は設けない。実績例の選定と、平均入力を回数へ変換するために均す規則は目的を分ける。
- 例がない、平均は満たすが相手の内訳と両立しない、指定時点には成立する条件自体がない場合を区別する。例がなくても成立可能な手入力は妨げない。
- 過去の例は、利用者が明示的に選んだときだけ反映し、アンドゥできる。20戦の実績を指定した全戦数まで続ける仮定であることを示す。
- 必要な改善や試している内訳から、「勝ち切れない試合」「下位だった試合」「好調期との違い」など、何を見直したいかという観点を示して、既存の行動仮説・戦績へつなぐ。リンクを置くだけで完結させない。
- この導線は「注目する人」を対象とする。相手の成績を編集しただけで、相手の改善策を考える導線へ切り替えない。
- 平均から自動生成した回数を、本人が選んだ戦略や実績由来の行動仮説として扱わない。既存プレイブックの候補・採否・文章・品質は再生成しない。
- 移動先が保持できる作品・シーズン等を引き継ぎ、対応していない人物・期間・順位の絞り込みまで適用したと表示しない。

## 7. 本実装へ引き継ぐ境界

### IA・UX・UI

試作で確定したのは、上記の問いに答える機能と意味である。実アプリでの配置、表・グラフ、操作、状態の仕様は9節以降に定める。細部の寸法・折り返しは既存UI規約に合わせ、本番画面の確認で調整する。

その際も、操作前に見通しを読めること、順算・逆算の条件が揃うこと、誰の何を変えると結果がどう変わったか分かることを維持する。調整と結果は近接させ、PC・mobileで同じ意味と機能を提供する。色・hover・ドラッグだけに依存させず、数値とkeyboardで操作・結果を確認できるようにする。

試作では作品の実戦績の固定スナップショットを使い、機能と操作を検討した。この確認は、最新実績との一致、本番のIA・UX・UIや性能、再訪・行動変化の確認を兼ねない。参考資材はgit管理外の `docs/tmp/series-rank-outlook/README.md` を入口とし、本書と参照正本だけでも必要な意味・計算・受入条件を理解できるようにする。

### 実績集計と仮定の試算

- 保存済みの実績指標、累積値、過去窓の実績、順位の組合せ等の参照データは、既存の分析成果物の責務・一貫性に従って提供する。
- 利用者が変更する仮定からの見通し・必要条件・展開例は、実績とは別の一時的な試算である。確定戦績を書き換えず、実績の集計失敗を同期再計算で補わない。
- 試算の実行場所、配分変換、ブレの生成、成果物の分割、計算上限は9節以降に定める。wireの厳密な型・path・versionは実装時のTapir・JSON Schemaを正本とする。試作の全履歴埋め込み・ブラウザでの実績再集計を本番へ持ち込まない。
- 実績を読む範囲は用途ごとの有限なデータとし、初期表示のために全試合の詳細を取得しない。比較の基になるデータを同じ成果物・集計時点へ揃え、試合追加・訂正・削除後に新旧の値を混ぜない。
- データ更新時も、適用中の入力と参照実績の関係を明示する。更新が利用者の編集を黙って上書きしたり、過去の試算を最新実績に基づく結果として残したりしない。

### 範囲外

行動方針・目標・コミットメントの記録、試算の永続保存・公開共有、通知、新しいランキングやレーティング、4名全体の将来順位・勝者予測、目標からの配分の自動変更、新しい行動仮説生成・AI解説、未保存の行動情報の推定は追加しない。

## 8. 受入条件

| 観点 | 確認する利用者の結果 |
| --- | --- |
| 初期読解 | 未操作で現状の見通し、50・100戦の必要平均、改善幅、参照実績を読め、相手に置いた仮定を説明できる。次戦で順位が動かない差でも、改善幅と継続戦数を判断できる |
| 範囲 | 作品・シーズンの累積値と作品直近20戦を区別でき、対象なし・少数例・失敗を通常の見通しに見せない |
| 計算 | 同率と厳密な逆転、現在同率、先行維持、相手の逆転、未到達、100戦外の到達を正しく区別する |
| 精度 | 平均0.01刻みの操作が計算へ反映され、回数からの細かな平均を表示切替で失わず、0.01指定では不可能な条件を案内し分ける |
| 操作 | 本人・相手、平均・回数の編集、直接入力、例の適用、アンドゥ、対象者だけの実績復帰が一貫し、不正入力で有効な結果を壊さない |
| 条件連動 | 相手の編集が必要条件に反映され、目標戦数や表示切替では配分を変更せず、条件変更後は実績のままの場合と比較できる |
| ブレ | 双方のブレと合法な同時順位を扱い、3例を確率や範囲保証に見せず、入切で平均の計算を変えない |
| 実績例 | 同期間の実績と短期参考例を区別し、例なし・不成立を説明し、採用操作なしに入力を書き換えない |
| 次の検討 | 注目する人について見直す観点があり、既存の戦績・行動仮説へ、実際に対応する条件で移動し、戻って試算を続けられる |
| 本番統合 | 既存の認証、成果物の整合・更新・失敗境界、共通UIを維持し、PC・mobile・keyboardで主要操作が成立する |

品質証拠は [テスト・品質規約](../test-rule.md) から選ぶ。数学的な境界と入力の保持は直接検証し、情報の読み取りや調整と結果の対応は本番画面で確認する。試作での確認を、本実装や競争・再訪への効果の確認に代用しない。

## 9. momo-resultへの組み込み

### 入口と対象

戦績比較 `/analytics/series` の上位目的に「見通しを試す」（`view=outlook`）を追加する。「次戦に備える」「分析する」と同格とし、既存の初期viewは変えない。分析の4切り口は実績を読む場所として維持する。仮定を編集する本機能は、現在の順位や行動仮説とは異なる操作のまとまりとして置く。

- 共通の比較条件、作品・シーズン選択、状態更新、認証、`PageFrame` / `PageContentSurface` を使う。独立route、専用の画面全体テーマ、重複したpage titleを追加しない。
- 「今の差」の順位比較の近くに「総合成績の見通しを試す」を置く。`view`だけを切り替え、作品・シーズン・マップを保持する。
- マップ指定中は試算を開始せず、「見通しは全マップの総合成績で試します」と「全マップで試す」を表示する。実行時にマップだけを解除し、作品・シーズンを保持する。このためだけに個別マップのaggregateを取得しない。
- シーズン未指定は作品総合、指定ありはそのシーズン総合。シーズンには現在、開始・終了・開催中を表す正式な状態がないため、名称、表示順、最新試合から終了を判定しない。「選んだシーズンに、この先の試合を加えた場合」と説明する。過去の途中時点へ巻き戻す指定は設けない。
- 選択試合は共有URLに保持しても、見通しの計算・マーカーに使わない。このviewではmatch-contextを取得せず、「分析する」に戻ったときに既存の整合確認を通す。明示的なscope変更では既存どおり選択試合を解除する。

### 人物とURL

| 状態 | 所有と初期値 |
| --- | --- |
| 作品・シーズン・マップ・view | 既存の共通URL状態 |
| 注目する人・比較する相手 | outlook用のURL状態 `focusMemberId` / `rivalMemberId`。固定メンバーIDのみ許可する |
| 平均・回数、確認する戦数、ブレの入切、編集対象、入力方法、アンドゥ | 同じ比較を検討している間の一時状態。URL・DB・永続storageへ保存しない |

人物を未指定の場合はcanonical順の先頭2名とする。成績順やログインアカウントから本人を推定しない。入力欄は「注目する人」「比較する相手」の役割順に固定し、人物変更で位置を入れ替えない。候補と同格の結果比較は既存のcanonical順を使い、候補では現在の他方を選択不可にする。一方だけが有効なら保持し、他方はcanonical順で異なる先頭の人へ補う。同一人物のURLは注目する人を保って相手を補い、不正な指定の変更理由を示す。

人物の入替・変更は別の比較を始める操作とし、2名とも直近実績へ戻してアンドゥを空にする。変更先の初期状態になることを選択欄の補足で示す。編集対象の人を切り替えるだけなら、比較する2名・入力値・履歴・次の検討の主語は変わらない。

同じ比較の検討を続ける間は、直近1件の試算を同じ認証・ブラウザタブ内のメモリに保持する。目的の切替と、戦績を確認して `returnTo` / ブラウザの戻る操作で帰る場合を同じ扱いにする。状態の所有者は再マウントするview・route本文の外へ置き、画面外では計算や取得を継続しない。

作品・シーズン・マップ・比較する人物の変更、認証の終了・切替、ページ再読込で破棄する。別の比較を始めても以前の試算を複数保存しない。戻った時点でartifactが変わっていれば、14節の更新規則を通して復元する。試算を保存・共有する機能や離脱確認dialogは追加しない。

## 10. 画面の読み順と操作の対応

仲間との対戦後に「この差をどれほどの成績で、何戦続ければ動かせるか」を読み、次戦前には見直す戦績・行動仮説へ進む。そのため、試合・確定・順位・総合成績・直近・次戦の語彙を使い、蓄積した差、改善幅、継続戦数、過去実績を一つの流れで照合する。

| 順序 | 表示・操作 | 初期状態と意味 |
| --- | --- | --- |
| 1 | 2名の選択と現在の総合平均 | 誰と誰の、どの総合成績かを確定する。累積戦数は共通条件の表示を使う |
| 2 | 見通しの結論 | 「直近n戦の成績なら、○戦で同率／○戦で上回る」等。nには実件数を入れ、到達しない・先行中も結果を出す |
| 3 | 必要な成績の比較 | 50・100戦後の必要平均、直近との差、本人の過去の同じ長さの自己ベストを同じ表で読む |
| 4 | グラフと成績の調整 | 平均の線、到達点、双方の指定値と編集、ブレの入切を一つの操作範囲にする |
| 5 | 実績の例と次の検討 | 過去20戦の例を確認・適用し、必要な改善から戦績・行動仮説へ進む |

主焦点は2の結論とし、同じ強さの数値cardを並べない。3は操作前から読める短い比較表、4は試して確かめる領域とする。条件変更後は「試している成績が続くと」と、現在の直近実績のままの場合を区別する。どちらも2名の今後の平均を確認できるようにする。入力値は「これからの平均順位」、累積値は「総合の平均順位」とし、同じ「平均」だけで両方を表さない。

### 確認する戦数

「この先何戦で比べるか」の初期値は50戦。50・100戦の比較行にある選択操作か、整数の直接入力で1〜1000戦を指定する。行全体をbuttonにせず、操作名に戦数を含める。10・20戦も直接指定できる。1〜1000は入力・参照データを有限にする初版の上限であり、効果検証から決めた最適値ではない。

指定値は図上の確認位置、必要条件、実績照合の対象だけを変える。成績・線の形を変える操作にはしない。50・100以外を指定した場合は同じ表に指定戦数の行を追加し、その行に詳細を対応させる。範囲外・未完成の入力では直前の有効な戦数を保ち、理由を欄に示す。100戦より後の確認結果は図外の数値として示す。

### グラフと調整欄

連続操作中に、誰の成績をどれだけ変えると差や到達時期がどう変わるかを追える配置にする。狭幅でも結果を見るたびに離れた表示を探し直す構成を避け、操作・変更量・結果の対応を優先する。

- 横軸は「この先の試合数」、0は現在、上限は100。縦軸は「総合の平均順位の差」とし、上側を注目する人が上、下側を相手が上、0を同率に固定する。縦軸は平均順位そのものではない。
- 「試している成績」は実線、「直近n戦のまま」は破線。後者は現在の成果物の参照実績から作り、更新前の実績や最後の編集値を基準にしない。平均の線が一致する場合は1本にまとめ、その旨を凡例へ示す。ブレは試している内訳から作るため、平均線が同じでも変わり得る。線名と数値を併記し、2人の系列であるかのようにmember色を割り当てない。
- 現在の指定の線に、最初の同率以上となる整数戦数を常時表示する。同率と厳密な逆転が別戦なら「50戦で同率、51戦で上回る」のように区別する。先行中に相手が追いつく場合はその時点を表示し、100戦外は図の近くに数値で示す。ブレの各交差点には到達保証の印を付けない。
- 0線と0〜100戦に表示する線を切らない縦軸範囲を使う。100戦を超える確認値は図の目盛りに含めない。同一ドラッグ中の目盛りは固定し、表示線が範囲外へ出る場合だけ拡張する。
- 0・10・20・50・100戦と、指定戦数の2名の総合平均・差を数値表でも確認できる。図の操作だけでしか得られない結果を作らない。
- PCは図と1人分の編集欄を横並びにする。狭幅では図、2名の指定値、編集対象、入力欄の順へ積み替える。図と入力の間へ実績例や長い説明を挟まない。図全体を横スクロールさせず、0〜100戦が利用可能幅へ収まる専用の描画にする。
- 編集対象は2名の名前を持つ選択肢で切り替え、同じ位置に1人分の編集欄を出す。双方の現在値は選択肢の近くに残す。本文が切り替わる操作なので、共通Tabsと対応panelを使う。
- 「試合ごとのブレを重ねる」は図の直下に置く。入切、3例の説明、計算中・失敗の表示を図に隣接させる。初版では独立したブレ幅sliderを追加しない。

既存の白い面、neutralの階層、member sequenceの青・赤・黄・緑、順位専用の意味表現を役割どおり使う。`MemberSequenceLabel`、共通の文字recipe・数値整列・入力・Tabs・Disclosure・Buttonを使い、試作の見出し装飾・配色・カード構成を移植しない。凡例、線種、ラベル、keyboard操作、44px以上のtouch対象を持たせ、色やドラッグのみで操作させない。

### 次の検討への接続

必要な平均だけでは何を振り返るか決まらないため、改善幅と実際に指定した内容から、注目する人の記録を見直す観点を短く言葉にしてから移動先を置く。成績を試し、戦績や行動仮説を確認して戻るまでを一つの作業として扱う。初版は次の決定規則で十分とし、試算から戦略の因果を生成しない。

| 状態 | 見直す観点と導線 |
| --- | --- |
| 必要な平均が直近より良い | 「直近より平均順位を○位良くし、○戦続けると上回ります」。差と必要な平均を併記し、本人の行動仮説を確認する |
| 本人が回数を直接指定・過去例を適用し、1位を増やしている | 「勝ち切れなかった試合で、見直せる点を探す」 |
| 同じく3・4位の合計を減らしている | 「下位だった試合で、共通する展開を確かめる」 |
| 平均だけを変更し、回数が自動生成されている | 平均の改善幅だけを述べる。自動生成した回数を本人の方針として説明しない |
| 先行条件を直近成績が満たす | 「直近の成績なら、○戦後も上回る条件を満たします」。維持できた試合の振り返りへつなぐ |

複数が当てはまる場合は下位の減少、1位の増加の順に最大2観点を示す。変更対象が相手でも、本人の観点を置き換えない。行動仮説への移動は同じ作品・シーズンの `review` と本人のsection anchorへ接続し、戻ると試算を保持する。既存の本人別sectionへ安定したIDとfocus可能な見出しを加える。仮説がない場合はその状態を残し、推奨文を捏造しない。

戦績一覧には作品・シーズン・確定状態と安全な `returnTo` を渡す。現行一覧が扱わない人物・順位・任意期間の絞り込みを適用したとは表示しない。作品総合なら「この作品の確定戦績を見る」、シーズン総合なら「このシーズンの確定戦績を見る」とする。戻る際の一時保持は9節に従う。

## 11. 入力と一時状態

### 値の保持と表示

- 未編集の直近実績は、実際の順位別回数と実戦数 `n = min(20, 作品の確定試合数)` を保持する。平均・20戦換算を途中で丸めない。
- 編集済みの回数は0.01回を1単位とする整数4個、合計2000単位で保持する。平均はその派生値であり、平均と回数を独立したstateにしない。
- 各人の出所を「直近実績」「平均から作成」「回数を指定」「過去の実績例」として保持する。実績由来の指定には元artifact・参照期間・例の窓を紐づける。平均からの内訳には「平均に合わせた回数の一例」を添える。実績例を手で変えた後は過去実績そのものと表示しない。
- 通常の平均表示は小数2桁。回数由来の平均がその間にある場合は正確な値を最大4桁で併記する。実績の循環小数は「約」と参照戦数で区別し、正確な順位合計／戦数を詳細で確認できる。同率判定は表示桁に依存させない。
- 図と結果は最後の有効な入力から作る。編集中の数値文字列と有効な試算値を分け、未完成の入力を0へ変換しない。

### 平均を調整

「平均順位で調整」「順位の回数で調整」は同じ人の入力方法を切り替える下位Tabsとする。初期は平均。方法を変えても有効値・利用者が編集中の文字・履歴は保持する。

平均は0.01刻みのsliderと数値入力で指定する。sliderでは良い成績を左、小さい数値を左に揃え、両立可能な範囲と相手の指定を示す。元の平均が2.4105など刻みの間にある場合も、表示・focus・pointerdownだけでは丸めない。矢印キーは操作方向にある次の0.01刻みへ進む。Home / Endは設定可能な端へ移動する。

数値入力はEnterまたはblurで検証する。ただし入力方法・編集対象・目的の切替や画面離脱によるblurは入力確定を兼ねず、表示切替だけでは成績を変えない。Escapeは現在の有効値の表示へ戻す。文字を変更せずfocus・確定しただけならno-opとし、近似表示を新しい指定値とみなさない。入力された数値が現在平均と厳密に同じなら、刻みの検証より先にno-opとする（2.4105から2.41050への書換えなど）。回数反映など別の操作でその人の有効値を変更した場合は、平均欄も新しい有効値へ同期し、古い未確定文字を残さない。

実績の平均は、0.01刻みで作れる範囲の外側にある場合もある。現在値を範囲の端へ自動補正せず、sliderの表示範囲に含める。操作方向に合法な値がなければ現在値を保ち、設定できる値との違いを説明する。例えば本人の直近3戦が1位2回・2位1回、相手が1位1回・2位2回なら、本人の現在平均は4/3、相手を固定して平均入力で作れる最良値は1.34となる。

実際に平均を変更したときだけ、12節の規則で回数の一例を作り、結果へ即時反映する。到達条件の値を自動で入力へ入れず、参考例の適用とは異なる操作として扱う。

### 回数を調整

1〜4位の4つの数値欄と合計を同じ表で示し、「回数を反映」で4値を一括適用する。各値0〜20、0.01刻み、合計20、相手との両立を確認する。合計が違う間は不足・超過回数を示し、有効な図は維持する。手入力で一つを増減したときに、別順位を勝手に変えない。

加えて、変更する2順位を選び、その2順位の合計を保つ配分sliderを用意する。初期の組合せは1位と4位。片側の回数を0.01刻みで動かし、他方から同量を移す。残る2順位と相手は変えない。選ぶ順位の変更自体では回数を変えず、可能な端点は双方の非負・容量から決める。

20戦未満で20戦換算を0.01回に正確に表せない場合は、近い合法な4値を未反映の入力案として示す。「入力しやすい回数に丸めています。反映すると平均も変わる場合があります」と、反映前後の平均を示す。「回数を反映」までは実績の分布を維持し、配分sliderはその後に使えるようにする。平均で新しい値を指定する操作は、その操作自体を編集値への移行とする。

自動表示しただけの入力案と、利用者が変更した未反映の入力（draft）を区別する。入力案を見ただけでは他の操作を止めず、有効値や相手が変われば案を作り直せる。

利用者のdraftは各人ごとに保持する。その人の平均の確定、slider、実績例の適用、実績へ戻す操作と、2名を一体で戻すアンドゥだけを止める。他方の編集、戦数・ブレの表示操作、入力欄内のテキストUndoは続けられる。他方の成績が変わってもdraftの文字を書き換えず、両立条件を再検証する。「回数を反映」の直前にも現在の相手で検証する。

編集対象・入力方法を変えても、図に近い2名の指定値の欄に「○○の回数は入力中・まだ反映されていません」と残し、その入力へ戻る操作と「入力を破棄」を置く。draftを隠したまま操作を止めない。未確定の平均入力も、反映されていないことと入力へ戻る操作を示す。破棄は未反映の文字だけを捨て、適用済みの成績や履歴を変えない。

### アンドゥと実績へ戻す

- 共通Buttonの規約に合わせた「元に戻す」を置く。iconのみの場合も同じaccessible nameを持たせる。平均変更、配分移動、回数の反映、過去例の適用、実績への復帰を1操作ずつ戻し、両者の正確な分布と出所を復元する。
- ドラッグは開始から確定まで、キーの押し続けはkeydownからkeyupまでを1操作とする。操作開始時の内訳を参照にし、取消または開始値へ戻って終了した場合は内訳・出所も戻して履歴を増やさない。
- 表示切替、戦数、ブレの入切、未反映draftは履歴に入れない。入力欄内の通常のテキストUndoを奪わない。戻せる操作がない場合は理由が分かる無効状態にする。履歴の保持上限は一時状態のメモリ予算として実装時に定める。
- 「○○を直近の成績に戻す」は対象者だけを現在の参照実績へ戻す。相手の指定と両立しなければ、該当順位と理由を示して両者を変更しない。両者を暗黙に初期化する代替動作はしない。

## 12. 採用する計算方法

### 精度と成立条件

計算の入力は整数または有理数とする。2名の順位分布を `p_A[i]`、`p_B[i]` とすると、非負・各人の総和1に加え、全順位で `p_A[i] + p_B[i] <= 1` を成立条件とする。この条件は、同じ試合で同順位にならない2名の分布を組み立てられるための必要十分条件である。残る2名には残り順位を割り当てられるが、その内訳・将来順位は生成しない。

整数比較では、編集値の分母2000と参照する実戦数の最小公倍数を `L` として分布を揃え、`r_A = sum(i * p_A[i] * L)`、`r_B`を作る。3節の大小判定には `-D * L + h * (r_B - r_A)` の符号を使う。実績更新で古い実績由来の指定を引き継ぐ場合も、その分母を含める。整数の積・除算はoverflowしない表現を使い、描画時だけ浮動小数へ変換する。

### 同率・逆転・必要平均

- 遅れている側の追いつきは、改善速度が正の場合に境界を切り上げて最初の同率以上、切り捨て＋1で最初の厳密な逆転を得る。現在同率は0戦として示し、先行・相手が追う場合も符号を反転して同じ判定を使う。
- 必要平均の厳密な境界 `T = mu_B - D/h` に対し、0.01指定の最大候補は `(ceil(100*T)-1)/100`。さらに相手と両立する配分を生成できる値に限る。単に境界を小数2桁へ丸めない。
- 選べる最良値でも届かない場合、現在の指定では届かない場合、すでに条件を満たす場合を分ける。条件を満たす直近成績に対して、負の改善幅を「改善が必要」と表示しない。
- 20戦未満の有理分布では、連続値として可能でも0.01回の入力で作れない場合がある。数学的に届かない場合は「相手の成績を変えない場合、○戦後には上回れません」、入力精度だけが制約の場合は「入力できる細かさでは、○戦後に上回る成績を指定できません」とする。平均0.01では作れず回数入力なら作れる場合は「回数で調整すると、この条件を試せます」と入力方法へ接続する。20戦換算と入力精度の説明は詳細に置き、未操作の実績値まで不成立と扱わない。
- 初回到達の計算結果が1000戦を超えても到達戦数は数値で示す。1〜1000の上限は利用者が指定して検討する戦数の上限であり、到達なしの判定に使わない。
- 実際の次戦の補助情報は、異なる順位12組を `-D + (rank_B - rank_A)` の符号で判定する。平均を1戦分足した結果と、実際に次戦で取れる順位を混同しない。

### 平均から回数への変換

本人の整数回数を `q[i]` とする。相手の分布に対する上限は `floor(2000 * (1 - p_B[i]))`。合計2000、指定平均を満たす順位合計、各順位の上限を満たす候補のうち、`sum((q[i] - 500)^2)` が最小の配分を採用する。同点なら操作開始時の内訳に近いもの、さらに同点なら1〜4位の回数の辞書順で決める。近さは同じく回数差の二乗和とする。

4位の整数回数を有限走査し、合計・順位合計から他順位を絞る試作の純粋関数を参考にできる。相手と参照内訳が有理数の場合にも、容量・同点判定を途中丸めで変えない。不成立を別の平均へ丸めて成功扱いにしない。

実績から0.01回の未反映draftを作る場合は、20戦換算の各値を容量内で切り下げ、残りを二乗誤差の増分が小さい合法な順位へ1単位ずつ足す。同点は順位順とする。この近似は入力案の作成に限り、実績や未操作の試算へ適用しない。

### 試合ごとのブレ

初期値と同じ作品の直近 `n` 戦から、2名の同時順位表 `R` を使う。過去全期間の組合せや、シーズンの累積分布へ黙って切り替えない。両者が現在artifactの直近実績のままなら、この観測表が指定した双方の分布と一致する。

1. `R`を共通分母`L`の整数表へ変換する。表示中の双方の分布を周辺和とし、対角0・総和Lを満たす表`Q`を作る。
2. `R`からのL1距離を最小にする最小費用流を用いる。各合法セルを「Rまで費用0」「超過分費用1」に分ける。双方の総和がLなので、超過分の合計を最小にすることはL1距離の最小化と同値になる。固定した人物順・順位順・辺順で同点の経路を決める。
3. 観測されなかった合法な組合せも、変更した分布の実現に必要なら使う。これは将来の組合せを仮定する操作であり、過去の観測事実を増やすことではない。対角0、行列和、非負、総和を確認できない場合はブレだけを表示不能にする。
4. `Q`から100戦の合法な同時順位を抽選し、有限数の候補を作る。初版の計算予算は201本とする。これは確率推定に必要な標本数ではなく、3例を選ぶための実装定数であり、変更時は計算方式の版と再現性を揃える。乱数は作品・canonical順の人物pair・計算方式の版から決め、配分変更時も同じ乱数列を新しい`Q`へ対応させる。入力値やartifactをseedへ含めず、順位に無関係な実績訂正で抽選し直さない。
5. 100戦後のcanonical順の2名の差で候補を並べ、同値は生成順にする。25・50・75%位置に近い候補を順に選ぶが、すでに選んだ軌跡は避け、最も近い未採用の軌跡を選ぶ。同じ距離なら小さい添字を優先する。201本の場合の起点は0始まりの50・100・150番となる。
6. 軌跡の一致は0〜100戦の差の列で判定する。異なる軌跡が3本未満の場合だけ重複を許し、その数を説明する。表示は注目する人の方向へ揃え、人物の役割を反転しても同じ軌跡の符号が反転するようにする。

seed付き乱数生成と整数重みによる抽選は一つの版を持つ純粋な計算に閉じる。同じ分布を別の共通分母で表しても抽選が変わらないよう整数重みを約分し、確率の端を丸めて禁止順位を抽選しない。目標戦数、開閉、編集対象、入力方法の切替では作り直さない。配分・参照する同時順位表・作品・人物pair・計算方式の版が変わると更新する。artifactは計算結果の鮮度を守るidentityへ含め、過去の結果が新しい入力を追い越して反映されないようにする。

3例は「展開例1・2・3」とし、「試している成績から作った、展開の異なる例」と説明する。選び方の詳細では100戦後の差を使うことを示し、中央確率範囲・予測区間とは呼ばない。候補に異なる軌跡が足りない場合と、どの試合でも差が一定になる場合を区別し、前者を「ブレがない」と表示しない。少数の実績から作った例を、将来のブレを測定できた結果として扱わない。各試合は同じ分布から抽選し、連勝・連敗が次戦へ影響するモデルは追加しない。

## 13. 実績データと読取契約

### 分析バッチが作るもの

同じ確定試合snapshotから以下を作り、既存の作品artifactへ追加する。見通しのための別job、利用者の試算を保存するtable、リクエスト中の分析計算は設けない。

| 保存resource | 単位 | 内容と上限 |
| --- | --- | --- |
| 見通しsummary | 作品overall・各season、いずれも全マップ | 対象戦数と品質、4名の順位合計・現在平均。作品の全戦数、直近n戦の品質・順位別実回数・実平均・参照期間、6組の同時順位表、4名の50・100戦の自己ベストまたは同期間不足 |
| 見通しreference | 作品overall・本人別 | 1〜min(作品戦数, 1000)戦それぞれの自己ベスト窓、実在した20戦の順位内訳の同値型 |

過去窓・20戦例・同時順位は作品ごとに一度計算し、seasonごとに全履歴を再計算しない。各seasonで変えるのは現在の累積値とその対象期間・件数である。summary内の作品共通の小さな情報は初回表示を一度の読取で満たすために同梱してよい。

選択scopeと作品直近n戦の品質は、それぞれの実件数からWorkerが共通契約に従って決める。作品200戦・選択シーズン1戦なら、累積値は参考扱い、直近20戦は通常の実績として区別する。Webで件数から品質を再判定せず、品質の良さを将来の確かさへ読み替えない。自己ベストも窓あり・同期間不足を区別し、比較元の作品戦数を使って不足理由を表示する。

0戦の作品にもoverall summaryを対象なし（`no_target`）として作る。この場合は平均・個人の分布・本人別referenceを持たせない。season summaryは既存scope索引にある全マップのseasonを対象とし、試合がないseasonのために空の組合せを増やさない。索引上の対象なしと、存在するはずのchunk欠落を区別する。

自己ベストは連続h戦の順位合計が最小の窓とし、同値なら既存の対戦順で終了が最も新しい窓を採る。保存するのは窓長、順位合計・平均、開始・終了試合IDと期間であり、全窓・全試合の列ではない。prefix sumまたはローリング集計を使い、計算量は最大 `O(4 * 1000 * 作品戦数)`、保存数は各人最大1000窓とする。

20戦例は4順位の回数が同じ窓を一つに集約し、代表は終了が最も新しい窓とする。型は各人最大1771個であり、平均の良い例だけへ打ち切らない。各型に順位回数、実平均、代表窓の期間・端点を持つ。直近20戦換算の内訳との回数差の絶対値合計が小さい順、同値なら終了が新しい順、さらに回数の辞書順で並べて保存する。実績が20戦未満なら型は空とし、不足理由を持たせる。20戦以上なら1〜min(1771, 作品戦数−19)型が必ずあり、不正な空集合を正常な不足に変換しない。

### APIと画面での取得

見通し用の認証済みreadを3用途に分ける。具体的なendpoint path、DTO field、schema番号は実装時のTapir・JSON Schemaを正本とし、次の入力・意味・上限を守る。

| read | 入力 | 返すもの・取得時点 |
| --- | --- | --- |
| summary | 作品、artifact、任意season | 選択scopeの見通しsummary。`outlook`選択かつ全マップのときだけ取得 |
| 同期間の過去実績 | 作品、artifact、注目する人、h | 保存済みreferenceから該当hの1窓。50・100戦以外を確定入力したときに取得 |
| 20戦の実績例 | 作品、artifact、注目する人 | 保存済みの型と順序。利用者が「過去の成績例」を開いたときだけ取得し、以後の仮定変更では再取得しない |

APIは用途に対応する一つの有限chunkを読み、保存済みの値を射影する。1〜1000戦のために1000個のresourceを作らず、本人別referenceから要求された窓を選ぶ。候補は型単位の有限集合を返し、全試合の詳細を送らない。summaryを表示するために既存aggregate・review・drilldownを追加取得しない。共通のScopeBarはscope・artifactと目的に応じた品質注記を受ける形へ適合し、既存aggregate型を満たすための余分な取得を避ける。

- `h > 作品戦数` は正常な「同期間の実績なし」。存在するはずのhの欠落は成果物破損として扱い、不足へ変換しない。20戦未満による保存例なし、利用者の条件に合う例なし、未取得、取得失敗も区別する。対象なしの画面では補助readを発行しない。
- map指定を受け付けるsummaryを作らない。不正な人物、h、作品・seasonの不整合、chunkの欠落は既存のエラー契約に従い、別scopeへfallbackしない。
- artifact・scope・member・hをreadのidentityへ含め、同じ認証・権限・更新境界を使う。現在名称の変更で集計の意味値や保存順を変えない。
- 取得した20戦例に対し、Webは利用者が置いた厳密な必要平均と相手の分布で適合性を判定し、保存順の先頭から最大3例を表示する。実績の再集計、実績に基づく独自の候補順位付け、行動プレイブックの再選定はしない。
- 必要平均を満たす型がない場合と、満たす型はあるが相手と両立しない場合を区別する。例の適用は注目する人だけを変更し、適用直前にも現在の相手・目標との両立を検証する。

### 成果物の完全性と互換性

本機能を含む新しいalgorithm・artifact・validation contractの組を導入し、producer・full validator・publisher・readerを揃える。既存の個別payloadが変わらない場合、そのpayloadの世代まで一律に変更しない。新しい要求resourceが欠けた成果物を、任意機能なしの成功として公開しない。

full validatorは、対象なしを含む必要scopeの完全性を検証する。作品に対象試合がある場合は4名・6組の表・本人別referenceを要求し、整数合計と平均の整合、直近n戦の周辺分布と表の一致、対角0、窓の長さ・期間・件数、20戦型の重複なし・順序、summaryとreferenceの一致を検証する。自己ベストは1〜min(作品戦数, 1000)の窓長を欠落・重複なく持ち、summaryの50・100戦は同じ窓または明示的な不足となる。APIは意味の検証を再実装せず、認めたpublication contractとboundedなshape・identityを確認する。

referenceの件数上限に加え、encoded / decoded bytes・深さの上限を保存schemaとreaderへ定める。最大候補数と最大入力で成立する上限を実装時に確認し、静かに型を削って上限内へ収めない。新resourceの保存、公開後の変更禁止、件数検証は共有DB側の正式な変更として扱い、その作業前にmomo-dbの開発手順を読む。今回の仕様定義ではschema・migration・DBを変更しない。

## 14. 更新と失敗

| 状態 | 表示と続けられる操作 |
| --- | --- |
| 対象scopeが0戦 | 既存の空状態。平均・必要条件・成績入力を作らない |
| 作品の実績が1〜19戦 | 実件数の初期値で計算。参照期間を示し、20戦例なしと同期間不足を項目ごとに表示。1〜2戦の参考扱いは共通契約に従う |
| 導入時に対応するartifactが未生成 | 既存の成果物未準備の表示と更新導線を使う。旧世代用の互換decoderや、view別に異なるartifactへfallbackする経路を追加しない。非対応versionと対応成果物の破損を区別する |
| 初回summary取得中／失敗 | 比較条件・目的の位置を保つ。失敗時は見通しの再読込を示し、架空の初期値を置かない |
| 同期間の実績・例の取得失敗 | 該当部分だけで再試行。入力、図、必要条件は使える状態を保つ |
| ブレを計算中／計算不能 | 平均線と入力は利用可能。古い条件のブレを新しい線に重ねず、局所状態を表示する |
| 対応する既存artifactで更新・計算中／失敗 | 集計時点と状態を示して直前の成功結果を維持する |
| artifactが失効 | 既存のbounded recoveryでstatusと対応resourceを一度取得し直す。古いartifactを最新値と混ぜない |

平均、逆算、配分の検証、ブレの生成はネットワークへ送らずWebの純粋関数で行う。入力と平均の結果は即時に更新し、ブレは一連の操作を確定したときに更新する。最大入力で操作を妨げないか確認し、必要な場合にWeb Worker等へ計算を分離する。分離を初版の必須構成にはしない。非同期化した場合も要求ごとの計算identityで古い結果を破棄し、画面を離れた後の処理を終了する。候補を増やし続ける継続計算や常時アニメーションは行わない。

同じartifactの再取得は一時入力を変えない。ドラッグやキーの押し続け中に新artifactが届いた場合は、操作の確定・取消まで採用を待つ。artifact ID、集計時点、品質、累積値、参照実績を同じ表示単位で切り替え、数値だけ古いまま時点を先に更新しない。確定前の操作を新しいアンドゥ履歴へ混ぜない。

新artifactの採用時は、次の規則を一体で適用する。

- 両者とも採用中artifactの直近実績をそのまま使っている場合だけ、2名の初期値を新しい直近実績へ揃える。旧artifact由来の値は、この自動追従の対象に含めない。
- それ以外は両者の指定分布を正確なまま維持し、累積値と参照実績を新しいartifactへ切り替える。「試している成績を残して実績を更新しました」と局所表示する。旧実績由来の値は「更新前の直近n戦」「更新前の実績例を使っています」として元の出所を残す。元の試合が訂正・削除されても、新しい成果物の実績例として表示しない。両者を保つため、片側だけの自動更新による不成立を起こさない。
- 取得済みの過去実績・例・ブレは新artifactのものに揃え、別resourceの失敗でsummaryの切替を無期限に待たない。更新前の実績例を新artifactの候補として適用しない。順位分布・同時順位表が同じなら、ブレの抽選は変えず、新しい累積値に対応する線を作る。
- 採用時にアンドゥを空にする。利用者の未反映draftは文字を保持し、切替後の相手で再検証する。自動表示しただけの入力案は作り直せる。人物自体が利用できなくなった場合は条件の正規化と理由を示し、別人へ以前の成績を移さない。

データの再取得は既存の初回・明示更新・失効回復に従う。スライダー、ブレ表示、hover、window focusを、データ更新や分析jobの開始理由にしない。
