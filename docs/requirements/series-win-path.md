# 勝ち筋マップ 要求仕様（草案）

状態: 草案（2026-11-15）。採否と範囲は未確定であり、[10節の未決事項](#10-未決事項)を決めてから実装へ渡す。確定までは本書を既存指標の変更根拠にしない。

目的: 確定済み戦績を「物件収益でトップだったか」「カード売り場・目的地の記録があるか」で分け、各分岐への到達の頻度と1位率を場全体と固定4名で見比べる。次戦でどの展開を目指し、収益で先行できない展開で何を優先するかを考える手掛かりにする。

| --- | --- |
| 勝ち筋マップの目的、分岐、指標、表示、成果物固有の契約 | 本書 |

| HTTP・成果物の構造 | Tapir endpoint、JSON Schema |

## 1. 成功条件

- 場全体の分岐別1位率から、選択した作品・シーズン・マップでの勝ち方の構造を読める。収益トップの1位率、収益非トップからの1位がどの分岐に多いかを、説明者の補助なしに答えられる。
- 各プレーヤーについて、分岐への到達率と分岐内の1位率を場全体と見比べられる。成績の差が「その分岐へ行く頻度」と「行った後の1位率」のどちらに表れているかを区別して読める。
- マップ・シーズンを切り替え、構造の違いを同じ分岐・同じ読み方で比べられる。
- 偶然の範囲に収まる個人差を、傾向として読ませない。対象なし・少数例・観測された0を区別できる。
- 共起を因果として表現しない。分岐は試合終了時の保存値による分類であり、試合中の行動順や判断を観測したものとして扱わない。

## 2. 既存指標との関係

本機能は新しい入力を必要とせず、既存の2指標を組み合わせて一つの読み方へまとめるものである。

| 既存 | 現在の意味 | 本機能との関係 |
| --- | --- | --- |
| 収益トップ時の成績、[物件収益トップ未勝利率](series-comparison.md#core--drivers) | 収益トップだった試合の結果 | 第1分岐の収益トップ側と同じ集合。値の定義を変えない |
| [カード売り場×目的地](series-comparison.md#flow--context) の4象限 | 全試合を両者の有無で分けた成績 | 4象限を収益トップ・非トップで分けたものが本機能の第2分岐。両側の合計は現在の4象限に一致する |
| 目的地なし売り場率 | 売り場ありの試合のうち目的地0回の率 | 変更しない |

現在の4象限は、収益トップの試合とそれ以外を混ぜて集計している。収益トップは単独で1位率が高いため、4象限だけでは「売り場・目的地の有無による差」と「収益トップが多く含まれることによる差」を分けて読めない。本機能はこの混在を解く。

同じ値を二つのblockへ置かないため、採用時は現在の「カード売り場×目的地」blockを本機能へ置き換えることを推奨する（[未決事項1](#10-未決事項)）。

## 3. 対象データと分岐

- 権限、scope、確定済み試合、対戦順、保存順位・金額の扱いは [戦績比較の不変条件](series-comparison.md#2-data--scope-invariants) に従う。
- 分類の単位は、選択scope内の1試合における1プレーヤーの結果（以下「明細」）とする。各明細は次の2段の分岐でちょうど一つの区分に入る。

| 段 | 区分 | 条件 |
| --- | --- | --- |
| 1 | 収益トップ | 本人の物件収益が、その試合の4人の最大値と同値。同値の全員を含む |
| 1 | 収益非トップ | 上記以外 |
| 2 | 売り場・目的地あり | カード売り場1回以上、かつ目的地1回以上 |
| 2 | 目的地のみ | 目的地1回以上、カード売り場0回 |
| 2 | 売り場のみ | カード売り場1回以上、目的地0回 |
| 2 | どちらもなし | 両方0回 |

- 「収益トップ」は既存の「トップ」定義と同じ集合とし、既存の収益トップ時の成績と件数が一致する。同値があると、1試合に収益トップの明細が複数ある。4人全員の物件収益が0の試合も、全員を同値のトップとして扱う。
- 第2段の区分は既存の4象限と同じ条件を使う。回数の多寡では分けず、1回以上の有無だけを使う。
- 回数は試合終了時の保存値である。売り場・目的地の記録が、収益の差がつく前か後か、どの順序かは分からない。

## 4. 指標

場全体と各プレーヤーについて、8区分（2×4）と小計を同じ定義で算出する。

| 指標 | 定義 |
| --- | --- |
| 件数 | その区分に入る明細数 |
| 到達率 | 件数 / 分母。分母はプレーヤーでは本人の選択scope内参加試合数、場全体では全明細数 |
| 1位数・1位率 | 区分内で保存順位が1位の明細数と、それを件数で割った率 |
| 平均順位 | 区分内の保存順位の平均 |

- 場全体は4人の明細を合算した値とする。プレーヤーの値と見比べる基準であり、5人目の主体として順位づけしない。
- 小計は「収益トップ計」「収益非トップ計」と、第2段だけで集計した4区分（現在の4象限と同じ値）とする。
- 各プレーヤーの8区分の件数の合計は参加試合数に、到達率の合計は1に一致する。場全体の1位数の合計は、順位に同値がなければscopeの試合数に一致する。
- 到達率と1位率は別の量として扱う。到達率は「その展開になった頻度」、1位率は「その展開になった試合での結果」を表し、掛け合わせた値や合成指標は表示しない。
- 「成績差のうち何ポイントが頻度、何ポイントが1位率によるか」を数値へ分解した値は初版に含めない（[未決事項3](#10-未決事項)）。

## 5. 件数・品質・偶然の差

| 区分の件数 | 表示 |
| --- | --- |
| 0 | 「対象なし」。到達率は観測された0%として表示し、1位率・平均順位は「—」とする |
| 1〜2 | 数値・件数と既存の「参考値」 |
| 3以上 | 数値と件数。件数境界を統計的な確実性の証明として扱わない |

- 品質は区分ごとの件数で判定し、親scopeの試合数で代用しない。選択scope全体が0戦の場合は共通の空状態に従う。
- 個人差の標章（場全体より高い・低い）は、試合内でプレーヤーを無作為に入れ替えた場合にも同程度に現れる差を除いたうえで付ける。境界は [既存の較正方針](../../apps/processing-worker/crates/analysis-core/src/compute/signals.rs) と同じ考え方で、弱い判定は4回に1回程度、強い判定は10回に1回程度しか偶然では出ない大きさとする。
- 区分の件数は区分ごとに大きく異なるため、境界は親scopeの試合数だけでなく区分の件数に応じて決める。算出方法と定数はalgorithm versionで固定し、本書へ値を複製しない（[未決事項6](#10-未決事項)）。
- 標章が付かない差は「差が小さい」ではなく「偶然の範囲と区別できない」と読めるようにする。標章の有無にかかわらず数値と件数は表示する。
- 場全体の区分間の差（例: 収益非トップの「売り場・目的地あり」と「どちらもなし」）にも件数を併記し、少数例では参考値とする。

検討時点の確定済み戦績では、場全体の構造は開催単位の再標本化でも安定していた一方、個人差の多くは偶然の幅の近くにあった。主表示を場全体に置き、個人差を補助にする5節の構成はこの観察に基づく。実測値は本書へ記載しない。

## 6. 表示

- 「分析する」→「勝因候補」に置き、収益トップ時の成績に続けて読めるようにする（[未決事項2](#10-未決事項)）。ページ上部の作品・シーズン・マップ、対戦数、最終更新、「表示を更新」を共有し、block内へ複製しない。
- 主表示は場全体の分岐とする。第1段（収益トップ・非トップ）の1位率、第2段の4区分の1位率を、到達率と件数を添えて上から読めるようにする。
- 4人の値は同じ区分の行に並べ、場全体と同じ軸で比べる。行を区分、列を場全体と固定4名とし、固定メンバー順を使う。成績や件数で行・列を並べ替えない。
- 1位率を主、到達率と件数を補助として対応づける。到達率は各列で合計が100%になる構成であり、[UI規約](../ui-rule.md) の構成表現に従う。数値をhoverや色だけで伝えない。
- 収益トップ側は件数が少なくなりやすい。第2段を常時開くか、収益トップ計だけを常時表示して4区分を補助開示にするかは、件数と読みやすさで決める。どちらの場合も区分の定義と順序は両側で揃える。
- 文言は「記録がある」「〜だった試合」とし、「寄った結果勝った」「売り場へ行けば勝てる」のような因果・行動の断定を使わない。読み方の説明には、分岐が試合終了時の値による分類であること、順序が分からないことを含める。
- PC・mobileで区分、名前の順序、数値、分母を変えない。mobileでは1人の列に着目して全区分を読めることを優先し、必要な横スクロールは表内に閉じる。
- 対象試合一覧、試合詳細へのリンク、区分からのdrilldownは初版に含めない（[未決事項5](#10-未決事項)）。ページ共通の選択試合の表示と戻り先は維持する。

## 7. 行動プレイブックへの接続（段階2）

初版は集計値の比較までとし、行動仮説への接続は画面での読解を確かめた後の段階2とする（[未決事項4](#10-未決事項)）。接続する場合の方針は次のとおりとする。

- 既存の「物件収益」categoryは収益トップ側、「目的地」categoryは目的地なしの悪化を扱う。本機能から追加するのは、収益非トップ側の区分間の差を扱う1categoryに限る。
- 場全体で共通する差は、個人cardではなく [共通論点](series-review-playbook.md#2-output--presentation) の候補とする。個人cardは、本人の到達率または1位率が5節の強い判定を満たす場合に限る。
- 発動条件は「収益で先行できていないと感じる展開」のような本人の自己観察とし、試合中の収益順位を記録したかのように書かない。候補の採否・縮小・品質境界・文面の規則は [プレイブック正本](series-review-playbook.md#4-deterministic-selection) に従う。

## 8. 実装に渡す境界

- 既存の分析入力だけで計算する。入力、DB schema、記録項目、OCRを本機能のために変更しない。
- 各scopeの集計と同じ走査で事前計算し、aggregateへ保存する。追加payloadは「場全体＋固定4名」×「8区分＋小計」の固定サイズに収める。区分ごとの試合ID、drilldown用の明細は追加しない。
- 値・件数・品質・標章はWorkerが確定する。APIとWebは保存済み成果物を検証して表示し、分類・集計・偶然の差の判定を再計算しない。
- 意味検証は、区分の件数の合計と参加試合数、第2段の小計と既存4象限、収益トップ計と既存の収益トップ件数、1位数の合計とscopeの試合数（順位の同値がない場合）を照合する。不正な成果物は公開しない。
- 現在の4象限を置き換える場合は成果物の非互換変更となる。API・Web・Workerと既存作品の再計算を [切替契約](series-analysis-batch.md#8-compatibility--release--rollback) に従って揃え、既存blockを参照するプレイブックの詳細リンクと目次を新しい位置へ対応させる。
- 更新中・失敗時の直前成功成果物の扱い、同一成果物への固定、取得失敗は [分析バッチ](series-analysis-batch.md#6-api--web--admin) の共通契約に従う。

## 9. 受入条件

| ID | 利用者が得る結果 | 主な確認境界 |
| --- | --- | --- |
| AC1 | 選択scopeの各明細が8区分のちょうど一つに入り、件数・到達率の合計が3〜4節の恒等式を満たす | 収益の同値、全員の収益0、売り場・目的地の0回と複数回を含む純粋計算 |
| AC2 | 収益トップ計と第2段の小計が、既存の収益トップ時の成績・4象限と同じ値になる | 同じ入力に対する既存指標との照合 |
| AC3 | 区分の件数0・1〜2・3以上を、対象なし・参考値・通常値として区別できる。到達率の観測された0%と1位率の対象なしを取り違えない | 件数境界の分岐、選択scope全体が0戦の空状態 |
| AC4 | 偶然の範囲の個人差に標章が付かず、標章のない差を「差がない」と読ませない | 入れ替えた戦績での標章の出現頻度、境界値 |
| AC5 | 場全体の構造を先に読み、同じ行で4人を比べられる。PC・mobileで区分・値・件数・参考値を読める | component、Playwright MCPによる表示確認と下記の読解課題 |
| AC6 | マップ・シーズンを切り替えても区分と読み方が変わらず、別scopeの値が混ざらない | scope切替、同一成果物への固定 |
| AC7 | 計算中・失敗・未取得を、最新の値や対象なしと混同しない | API・Webの成果物と状態の接続 |
| AC8 | 既存scopeの集計・振り返り・通知などのconsumerが新契約で壊れない | 変更したconsumerの契約証拠 |

証拠は [テスト・品質規約](../development/test-policy.md) に従って選び、[Change Gates](../development/workflow.md#change-gates) に割り当てる。

読解課題は「収益トップでなかった試合では、どの区分の1位率が高いか」「自分は場全体と比べて、どの区分へ行く頻度が高いか・低いか」「その差に標章は付いているか」に、値と件数を添えて答えられることとする。明確な差がない結果も失敗扱いにせず、差の捏造へ誘導しない。

### 手計算できる具体例

以下は説明用の架空データであり、実際の戦績ではない。作品・シーズン・マップはすべて同じとする。各セルは「物件収益（万円）／目的地回数／売り場回数／順位」を表す。

| 試合 | A | B | C | D |
| --- | --- | --- | --- | --- |
| 1 | 300／1／0／1位 | 100／1／1／2位 | 50／0／1／3位 | 0／0／0／4位 |
| 2 | 200／0／0／2位 | 150／1／1／1位 | 100／0／0／4位 | 50／1／0／3位 |
| 3 | 100／0／1／3位 | 100／1／0／1位 | 20／1／1／2位 | 0／0／0／4位 |

- 収益トップの明細は試合1のA、試合2のA、試合3のAとBの4件である。試合3は同値のため2件になる。1位は試合1のAと試合3のBの2件なので、場全体の収益トップの1位率は50%となる。
- 収益非トップの明細は8件で、1位は試合2のBだけなので、場全体の1位率は12.5%となる。1位数の合計は2＋1＝3で、試合数に一致する。
- 収益非トップの第2段は、売り場・目的地ありが3件（試合1のB、試合2のB、試合3のC）で1位率33.3%、目的地のみが1件、売り場のみが1件、どちらもなしが3件でいずれも1位率0%となる。
- 収益トップの第2段は、目的地のみが2件で1位率100%（参考値）、売り場のみとどちらもなしが各1件で0%（参考値）、売り場・目的地ありは0件で対象なしとなる。
- プレーヤーAは3戦すべてが収益トップで、到達率100%、1位率33.3%となる。収益非トップは0件のため到達率0%、1位率は「—」とする。
- プレーヤーBは収益トップが1件（到達率33.3%、1位率100%、参考値）、収益非トップが2件でどちらも売り場・目的地あり（1位率50%、参考値）となる。

## 10. 未決事項

採否の前に決める事項と、草案時点の推奨を示す。

| # | 事項 | 推奨 | 理由 |
| --- | --- | --- | --- |
| 1 | 現在の「カード売り場×目的地」blockを置き換えるか、併存させるか | 置き換える | 第2段の小計が同じ値を持つ。併存すると同じ量が二箇所に出て、収益トップの混在を解いた値と解いていない値の読み分けが必要になる |
| 2 | 置き場所を「勝因候補」と「条件別」のどちらにするか | 勝因候補 | 第1分岐が物件収益であり、収益トップ時の成績の続きとして読める |
| 3 | 成績差を「頻度の差」と「1位率の差」へ数値で分解して示すか | 初版は見送る | 到達率と1位率を同じ行に並べれば目視で同じ問いに答えられる。検討時点では分解値の多くが偶然の幅の近くにあった |
| 4 | 行動プレイブックへ新categoryを加えるか | 段階2 | 場全体の差が主であり、共通論点としての文面と発動条件を画面での読解後に決めたい |
| 5 | 区分から根拠試合へ移動できるようにするか | 段階2 | 収益非トップで1位だった試合の試合メモは戦術の手掛かりになるが、初版は集計値の読解を先に確かめる |
| 6 | 偶然の差の境界を、固定した定数表にするか、成果物の計算時に入れ替えで求めるか | 実装時に決める | 区分の件数に依存するため、既存の試合数帯だけの定数では足りない。決定性と計算量の上限を満たす方法を選ぶ |
| 7 | 物件収益のシェア帯（試合内の4人合計に占める割合）別の1位率を加えるか | 段階2 | 収益トップでも差が小さい試合を読み分けられるが、試合終了時のシェアを試合中の目安と誤読させない表現を先に確かめたい |

範囲外: マップ別の並置表示（既存のscope切替で読む）、新しい記録項目、回数の多寡による細分、統計モデルによる分岐の自動探索、勝者予測、AIによる解説。
