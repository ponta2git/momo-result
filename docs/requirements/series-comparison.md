# 戦績比較ページ 要求仕様

目的: 確定済み戦績から固定4名の現在差、勝因候補、推移、条件差を比較し、根拠試合までたどれるようにする。

責務の境界:

| 関心事 | 正本 |
| --- | --- |
| 本ページのscope、指標の意味、表示上の判断 | 本書 |
| 「次戦に備える」の行動プレイブック | `docs/requirements/series-review-playbook.md` |
| 非同期計算、artifact、状態、管理、公開・復旧 | `docs/requirements/series-analysis-batch.md` |
| HTTP / artifact shape | Tapir endpoint、JSON Schema、共有fixture。OpenAPI / Web型は派生物 |
| UI共通規約、test、command | `docs/ui-rule.md`、`docs/test-rule.md`、`docs/dev-rule.md` |

endpoint path、DTO field、component構成、query cache key、閾値の配置場所は実装・schemaを正本とし、本書へ複製しない。

## 1. Product Scope

- 「シリーズ」は既存の作品1件と同義であり、初期版は作品内の4プレーヤー比較に集中する。作品間の同時比較はしない。
- 集計対象は確定済み試合だけとし、OCR下書きや未確定下書きを含めない。
- 初回は確定済み試合が最も新しい作品の総合scopeを選ぶ。過去作品への切替は残す。
- 利用者は次戦前の作戦確認と対戦後の振り返りに使い、結論から詳細指標、根拠試合へ段階的に移動できる。
- 認証済みの有効accountだけが閲覧できる。URLは状態復元に使うが、公開共有手段にはしない。
- 試合作成・編集、master管理、export、共有画像、自由文AI、勝者予測、未保存の行動・カード・距離の推定は本ページの責務外とする。

成功条件:

- 初期表示で4人の最優先の行動仮説を把握できる。
- 同じ指標を4人で比較し、説明だけで意味、良い方向、注意点を理解できる。
- 行動仮説や指標から根拠試合へ移動し、browser back後も元のscopeと選択状態へ戻れる。
- 件数不足、対象なし、同値、計算中、失敗を断定的な分析値と混同しない。
- PCでは4人比較、mobileでは1人ずつの読解を維持し、意味・scope・分母をdevice間で変えない。

## 2. Data / Scope Invariants

- 作品を必須scope、seasonとmapを独立した任意filterとする。両方未指定は総合、両方指定は実在する組合せだけを有効とする。
- scope候補は現在の確定試合から作る。古いartifactだけに存在する候補を残さず、新規候補がartifactに未収録なら別scopeへfallbackしない。
- 対戦順は `played_at`、開催、開催内試合番号、試合IDの安定順とする。
- 順位は保存済み値を正とし、総資産から再計算しない。金額はDB保存値から途中丸めなしで計算する。
- 指標の分母は各プレーヤーの選択scope内参加試合数とする。平均は算術平均、中央値は偶数件なら中央2値の平均、順位ブレは母標準偏差とする。
- 値順位の同値は平均順位方式を使い、同値をmetadataで伝える。「トップ」は最大値と同値の全員を含む。
- 分母0は `no_target`、1〜2件は `reference` とする。より厳しい指標固有条件は後節に明記する。
- 事件簿は保存済み各項目を独立して使う。合算を総行動数、総駅数、総マス数、移動量として扱わない。
- 行動順、因果、能力、次戦結果を保存済み集計から推定しない。

## 3. Information Architecture / State

ページは比較条件の後、目的で切り替える。

| View | 役割 |
| --- | --- |
| 次戦に備える (`review`) | 行動仮説。詳細はplaybook正本に従う |
| 今の差 (`overview`) | 平均順位、順位分布、直接対決、順位ブレ、王座の確からしさ |
| 勝因候補 (`drivers`) | 資産、物件収益、目的地、順位を読む追加の手掛かり |
| 推移 (`flow`) | 直近成績、切り替え力、荒れ試合、開催内の流れ、予測より上位だった勝利 |
| 条件別 (`context`) | 番手、カード売り場と目的地、スリの銀次 |

- URLは作品、season、map、view、選択試合を復元する。無効値は別scopeへ推測変換せず、安全な既定値へ正規化して理由を示す。
- view切替だけで集計scopeを変えない。作品・season・map変更時は選択試合を解除する。
- 根拠試合の選択中は4人の結果と分析上の位置を一貫して示す。試合粒度で一意に対応できない指標へ目印を捏造しない。
- 対象試合のrevisionまたは作品所属がartifactと異なる場合、一次データは維持し、古い派生分析だけを隠す。
- artifact切替は主表示、drilldown、試合文脈を混在させずlatest-winsで行う。

## 4. Presentation Requirements

- 画面は縦に読み、各指標block内で4人を同じ軸に並べる。多数の小型KPI cardを敷き詰めない。
- 同じ値は主役となるblockへ集約する。対戦数は比較条件、順位差は「今の差」、資産と収益は「勝因候補」、銀次は「条件別」で扱う。
- 指標は結論、比較、対象件数、注意、必要なときだけ算出方法の順に読めるようにする。構造で分かる内容を説明文で復唱しない。
- tableは名前、行見出し、列見出し、分母を持つ。graphは数値表現を併記し、色だけで系列、強み、注意、選択状態を伝えない。
- 順位軸は1位を上、histogramは全員共通binとする。負値を保持し、収益0は独立binとしてよい。
- 詳細履歴は初期payloadへ全件を含めず、指標blockから同一artifactのdrilldownとして取得する。
- highlightは短く遊びを入れてよいが、対象件数、根拠、同値を示し、個人攻撃や能力断定をしない。
- 空状態、help、dialog、graph、table、responsiveの共通要件は `docs/ui-rule.md` に従う。

### 4.1 UI構造契約

- 「次戦に備える」「分析する」の目的を分け、共通topicの開示、4人のprimary hypothesis、player内の補助開示をこの順で扱う。根拠やreliability helpは比較の高さを変えないdialogへ置く。
- pale surfaceは `docs/ui-rule.md` の強調文法に従い、選択中または現在のscope、状態・通知、操作のinset、compactな標章に限定する。primary result、page-local navigation、label付きheader、primary hypothesisは、重要という理由だけで淡色面へ置かず、読み順、文字、余白、dividerを優先する。同格比較でfillを反復する場合は比較群を一つのanchorとして扱い、その外側へ同じ強さの面を重ねず、意味を持つfillには非色labelまたはmarkerを併用する。
- chart / table 内だけに必要な横スクロールを閉じ込め、legendはplot外でwrapし、axis名とtick labelをplot境界内に収める。mobileのdialogは本文に1つの縦scroll領域を持つ。
- parts-of-a-wholeは1本の100% compositionと値一覧で示し、単一候補は確率100%ではなく「候補はこの1件」と表現する。
- 選択試合のresult ledgerを分析目的より前に共有し、根拠試合と比較をURL stateで往復できるようにする。markerは試合粒度で一意に対応できる場合だけ表示し、tab切替後もfocusを保持する。

## 5. Metric Semantics

単純なcount、sum、max、min、average、medianと表示用projectionは実装・schemaを正本とする。以下は誤解や実装差が起きやすいため、要求として意味を固定する。

提供する指標群:

| 切り口 | 必須出力 |
| --- | --- |
| 今の差 | 対戦数、平均順位、順位分布、入賞・下位率、順位ブレ、直接対決 |
| 資産・収益 | 総資産と物件収益の代表値・共通bin分布、収益順位との差、収益トップ未勝利、観測上の戦い方傾向 |
| 推移 | 累積平均順位・順位ブレ、直近20戦、前戦からの順位遷移、開催内第n試合、荒れ試合 |
| 条件別 | 番手別成績、目的地、カード売り場×目的地、銀次の件数・発生率・被害時成績 |
| 補助 | 根拠付きhighlight、高度な順位分析、試合とプレーヤー粒度のdrilldown |

### Core / Drivers

| 指標 | 定義 |
| --- | --- |
| 平均順位 / 順位分布 / 順位ブレ | 保存順位の平均、各順位の件数・率、母標準偏差 |
| 直接対決優勢率 | 相手より上位だった共通試合数 / 両者の共通試合数 |
| 直接対決平均順位差 | `相手順位 - 本人順位` の平均。正ほど本人が上位 |
| 物件収益順位との差 | `平均物件収益順位 - 平均最終順位`。正ほど収益順位以上の最終順位 |
| 物件収益トップ未勝利率 | 収益最大値と同値だった非1位試合数 / 収益トップ試合数 |
| 目的地変換効率 | `平均目的地順位 - 平均最終順位`。正ほど目的地順位以上の最終順位 |
| 目的地依存度 | `目的地上位時の平均順位score - 目的地下位時の平均順位score` |

順位scoreは `5 - rank`。目的地順位は到着回数の降順を同値平均順位とし、2.5未満を上位、2.5超を下位、2.5を中立として依存度から除く。

資産・収益は全員共通binの分布と、勝敗時の差、収益比率、目的地を組み合わせて「観測上の傾向」として示す。分類の固定ID、根拠値、閾値はartifact schemaとalgorithm versionで追跡し、行動ログを観測したように表現しない。

- 資産帯の下限・上限はscope全員の総資産P10 / P90とし、各人の該当件数・率、P10 / 中央 / P90、P90−P10を保持する。
- 大勝は1位と2位の資産差のscope内P75、惜しい2位は1位との差のP25、大敗は下位と1位との差のP75を基準にする。対象順位がない場合は閾値と件数を対象なしにする。
- 資産タイプは各人値と4人中央値の差を固定優先順位で分類し、分布形状を別軸、収益比率・目的地・下振れなどを複数tagとして保持する。primary分類とtagを相互に上書きしない。

### Flow / Context

| 指標 | 定義 |
| --- | --- |
| 直近成績 | 選択scopeの安定順で末尾20戦。3戦未満は参考 |
| 下位後入賞率 | 前戦3・4位の次戦で1・2位になった率 |
| 4位後入賞率 | 前戦4位の次戦で1・2位になった率 |
| 入賞後下位率 | 前戦1・2位の次戦で3・4位になった率 |
| 順位遷移 | 前戦順位を行、次戦順位を列にした件数・行内率 |
| 番手差 | 苦手番手の平均順位から得意番手の平均順位を引いた値 |
| カード売り場×目的地 | 両者の有無による4象限。共起を因果として表現しない |
| 目的地なし売り場率 | 目的地0回かつカード売り場ありの試合数 / カード売り場ありの試合数 |

- 切り替え力は選択scope内の前戦だけを使い、scope外の直前試合を混ぜない。条件対象0件は対象なし、1〜7件は参考とする。
- 荒れ試合は、収益トップ未勝利、銀次複数回、相対的な僅差、相対的な大差を決定論的flagとして示す。相対flagは3試合未満のscopeで出さない。
- 「直近n戦と荒れ方」の横ストリップは最新試合を左端に置き、新しい順に読む。集計、累積推移、順位遷移に使う安定対戦順は反転させない。
- 番手、銀次被害、目的地、カード売り場の条件別指標は対象件数を必ず併記し、偶発イベントを判断ミスとして扱わない。
- 累積推移、分布、drilldown用明細は同じ対戦順・分母・同値規則を使う。
- 平均順位履歴は前開催平均との差、開催内の初戦から最終戦の順位差、開催前後の通算平均差を別の値として保持する。番手drilldownの基準は同scope全員の同番手平均とし、本人平均との差、件数、最良・最悪番手と差幅を示す。

### Highlights

highlightは既存指標から決定論的に選び、銀次被害後の成績、収益トップ未勝利、目的地依存・変換、資産・収益peak、順位安定性を候補とする。根拠不足では表示せず、playbookと同じ話題を重複card化しない。

## 6. Advanced Rank Analysis

高度分析は次戦予測や因果推定ではなく、保存済みの総資産以外の記録と期間内順位の関連を別開催で検証する補助分析とする。

| 指標 | 意味 |
| --- | --- |
| 順位を読む手掛かり | 期間内順位と安定して結び付いた保存signalを各人最大3件示す |
| 予測より上位だった勝利 | 外部評価で下位寄りでも実際は1位だった根拠試合を示す |
| 王座の確からしさ | 開催条件と番手を調整しても期間内首位を支持する再標本化比率 |

共通要件:

- 1試合4人の6組比較を正則化Bradley–Terryモデルで扱う。物件収益と固定6事件の試合内相対値をsignal、番手とプレーヤーを調整変数とし、最終順位を直接決める総資産は説明変数から除く。
- 同じ開催を学習と評価へ分割しない。開催単位の決定論的5foldで、各試合を当該開催を学習に含めないout-of-fold推定にする。
- full modelをプレーヤーと番手だけのbaselineとpairwise log loss / Brier scoreで比較する。solver、正則化、seed、反復、foldはmodel versionで固定する。
- 順位signalは開催単位permutation importanceと係数方向を使い、5fold中4fold以上で方向一致、3fold以上で正のimportance、平均importanceが `+0.0001` 以上の採用境界をすべて満たす候補だけを返す。
- 予測順位は `1 + sum(P(相手が本人より上位))`。実際1位かつ予測順位2.5以上の試合を対象とする。
- 予測より上位だった勝利は本人の勝利0件で `no_target`、1〜9件で `reference`、10件以上で共通model品質を継承する。
- 根拠試合では物件収益、目的地、プラス駅、マイナス駅、カード駅、カード売り場、スリの銀次の保存値を欠落なく示す。
- 王座の確からしさは開催単位block bootstrapでプレーヤー効果の首位割合を返し、同値を等分する。丸め前の4人合計は1とする。
- 開催8未満または試合32未満、数値不正、solver非収束は `no_target`。開催8〜19または方向不安定は `reference`。開催20以上かつfull modelが5fold中4fold以上baselineを上回り方向安定した場合だけ `ok` とする。
- 高度分析の定義済み非採用は作品成果物の正常成功とする。予期しない計算失敗は部分公開せず、直前成功artifactを維持する。
- UIは対象件数、品質、平易な読み方を先に示し、係数やfold詳細を補助開示へ置く。確率、隠れた実力、運、勝因として表現しない。

## 7. Read / Failure Behavior

- Web / APIは保存済みartifactを読むだけとし、指標、閾値、意味順、fallbackを再計算しない。詳細はbatch正本に従う。
- options、status、aggregate、review、drilldown、試合文脈は用途別resourceとし、同一画面ではstatusが解決した同じartifactへ固定する。
- 通常表示はactive viewのbounded chunkだけを読み、試合詳細N+1や作品全体decodeを行わない。
- 計算中・失敗時は直前成功artifactがあれば鮮度と状態を示して閲覧を維持し、一度も成功していなければ分析値を表示しない。
- 定義済みの対象なし・件数不足はtypedな正常結果とし、予期しないscope計算失敗で部分artifactを公開しない。
- ancillary resourceの取得失敗で取得済み主表示を消さない。expired artifactはstatusを更新して一度だけ最新へretryし、同期計算や別scopeへfallbackしない。

## 8. Acceptance Evidence

| 領域 | 必要な証拠 |
| --- | --- |
| scope / URL | 無効・削除・追加scope、旧URL正規化、browser back、選択試合解除 |
| 指標 | 分母、同値、負値、境界、安定順、手計算可能なgolden / property |
| 高度分析 | solver、fold漏洩なし、決定性、品質境界、局所非採用と予期しない失敗の区別 |
| artifact連携 | 同一artifact pinning、bounded chunk、revision不一致、latest-wins、fallback禁止 |
| UI | 4人比較、mobile、table semantics、graph非色依存、空・参考・失敗状態、根拠試合往復 |
